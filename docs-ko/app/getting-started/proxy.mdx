## 프록시

> **알아두면 좋은 정보**: Next.js 16부터 미들웨어는 이제 그 목적을 더 잘 반영하기 위해 프록시라고 부릅니다. 기능은 동일하게 유지됩니다.

프록시를 사용하면 요청이 완료되기 전에 코드를 실행할 수 있습니다. 그런 다음 들어오는 요청에 따라 요청 또는 응답 헤더를 다시 작성, 리디렉션, 수정하거나 직접 응답하여 응답을 수정할 수 있습니다.

### 사용 사례

프록시가 효과적인 몇 가지 일반적인 시나리오는 다음과 같습니다.

- 모든 페이지 또는 페이지 하위 집합의 헤더 수정
- A/B 테스트 또는 실험을 기반으로 다른 페이지에 재작성
- 들어오는 요청 속성을 기반으로 하는 프로그래밍 방식 리디렉션

간단한 리디렉션의 경우 먼저 [`redirects`](../api-reference/config/next-config-js/redirects.mdx) 구성을 사용하는 것이 좋습니다. 요청 데이터나 더 복잡한 로직에 액세스해야 하는 경우 프록시를 사용해야 합니다.`next.config.ts` first. Proxy should be used when you need access to request data or more complex logic.

프록시는 느린 데이터 가져오기를 위한 것이 *아닙니다*. 프록시는 권한 기반 리디렉션과 같은 [낙관적 검사](../guides/authentication.mdx#optimistic-checks-with-proxy-optional)에 도움이 될 수 있지만 전체 세션 관리 또는 권한 부여 솔루션으로 사용해서는 안 됩니다.

Using fetch with `options.cache`, `options.next.revalidate` 또는 `options.next.tags`과 함께 가져오기를 사용하면 프록시에서는 효과가 없습니다.

### 컨벤션

Create a `proxy.ts`(또는 `.js`) 파일을 프로젝트 루트에 생성하거나 해당하는 경우 `src` 내부에 생성하여 `pages` 또는 `app`과 동일한 레벨에 위치하도록 합니다.

> **참고**: 프로젝트당 하나의 `proxy.ts` 파일만 지원되지만 여전히 프록시 로직을 모듈로 구성할 수 있습니다. 프록시 기능을 별도의 `.ts` 또는 `.js` 파일로 나누고 기본 `proxy.ts` 파일로 가져옵니다. 이를 통해 중앙 집중식 제어를 위해 `proxy.ts`에 집계된 경로별 프록시를 더욱 깔끔하게 관리할 수 있습니다. 단일 프록시 파일을 적용함으로써 구성을 단순화하고 잠재적인 충돌을 방지하며 여러 프록시 계층을 방지하여 성능을 최적화합니다.

### 예

프록시 기능을 기본 내보내기 또는 명명된 `proxy` 내보내기로 내보낼 수 있습니다.

```ts filename="proxy.ts" switcher
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

// This function can be marked `async` if using `await` inside
export function proxy(request: NextRequest) {
  return NextResponse.redirect(new URL('/home', request.url))
}

// Alternatively, you can use a default export:
// export default function proxy(request: NextRequest) { ... }

export const config = {
  matcher: '/about/:path*',
}
```

```js filename="proxy.js" switcher
import { NextResponse } from 'next/server'

// This function can be marked `async` if using `await` inside
export function proxy(request) {
  return NextResponse.redirect(new URL('/home', request.url))
}

// Alternatively, you can use a default export:
// export default function proxy(request) { ... }

export const config = {
  matcher: '/about/:path*',
}
```

The `matcher` 구성을 사용하면 특정 경로에서 실행되도록 프록시를 필터링할 수 있습니다. 경로 일치에 대한 자세한 내용은 [Matcher](../api-reference/file-conventions/proxy.mdx#matcher) 문서를 참조하세요.

Read more about [using `proxy`](../guides/backend-for-frontend.mdx#proxy)에 대해 자세히 알아보거나 `proxy` [API 참조](../api-reference/file-conventions/proxy.mdx)를 참조하세요.
