## 폴더 및 파일 규칙

경로를 노출하려면 `page`를 추가하고, 헤더나 탐색, 푸터 같은 공유 UI에는 `layout`, 스켈레톤에는 `loading`, 오류 경계에는 `error`, API에는 `route`를 추가합니다.

### 중첩 경로

폴더는 URL 세그먼트를 정의합니다. 폴더를 중첩하면 세그먼트도 중첩됩니다. 어떤 수준의 레이아웃이든 하위 세그먼트를 감쌉니다. `page` 또는 `route` 파일이 존재하면 해당 경로는 공개 경로가 됩니다.

| Path                        | URL pattern     | Notes                         |
| --------------------------- | --------------- | ----------------------------- |
| `app/layout.tsx`            | —               | 모든 경로를 감싸는 루트 레이아웃 |
| `app/blog/layout.tsx`       | —               | `/blog` 및 그 하위 경로를 감쌈 |
| `app/page.tsx`              | `/`             | 공개 경로                     |
| `app/blog/page.tsx`         | `/blog`         | 공개 경로                     |
| `app/blog/authors/page.tsx` | `/blog/authors` | 공개 경로                     |

### 동적 경로

대괄호로 세그먼트를 매개변수화합니다. 단일 매개변수에는 `[segment]`, catch-all에는 `[...segment]`, 선택적 catch-all에는 `[[...segment]]`를 사용합니다. 값은 [`params`](../api-reference/file-conventions/page.mdx#params-optional) prop을 통해 접근합니다.

| Path                            | URL pattern                                                          |
| ------------------------------- | -------------------------------------------------------------------- |
| `app/blog/[slug]/page.tsx`      | `/blog/my-first-post`                                                |
| `app/shop/[...slug]/page.tsx`   | `/shop/clothing`, `/shop/clothing/shirts`                            |
| `app/docs/[[...slug]]/page.tsx` | `/docs`, `/docs/layouts-and-pages`, `/docs/api-reference/use-router` |

### 경로 그룹과 프라이빗 폴더

경로 그룹 [`(group)`](../api-reference/file-conventions/route-groups.mdx#convention)을 사용하면 URL을 변경하지 않고 코드를 구성할 수 있고, 프라이빗 폴더 [`_folder`](#private-folders)를 사용하면 라우팅되지 않는 파일을 함께 배치할 수 있습니다.

| Path                            | URL pattern | Notes                                     |
| ------------------------------- | ----------- | ----------------------------------------- |
| `app/(marketing)/page.tsx`      | `/`         | 그룹은 URL에서 생략됨                     |
| `app/(shop)/cart/page.tsx`      | `/cart`     | `(shop)` 안에서 레이아웃 공유             |
| `app/blog/_components/Post.tsx` | —           | 라우팅되지 않음, UI 유틸리티를 두기 안전한 위치 |
| `app/blog/_lib/data.ts`         | —           | 라우팅되지 않음, 유틸리티를 두기 안전한 위치 |

### 병렬 경로와 인터셉트 경로

이 기능들은 슬롯 기반 레이아웃이나 모달 라우팅 같은 특정 UI 패턴에 적합합니다.

상위 레이아웃이 렌더링하는 이름 있는 슬롯에는 `@slot`을 사용합니다. 예를 들어 목록 위에 상세 보기를 모달로 표시하려면, URL을 바꾸지 않고 현재 레이아웃 안에서 다른 경로를 렌더링하도록 인터셉트 패턴을 사용하세요.

| Pattern (docs)                                                                 | Meaning              | Typical use case                         |
| ------------------------------------------------------------------------------ | -------------------- | ---------------------------------------- |
| [`@folder`](../api-reference/file-conventions/parallel-routes.mdx#slots)       | 이름 있는 슬롯       | 사이드바 + 메인 콘텐츠                   |
| [`(.)folder`](../api-reference/file-conventions/intercepting-routes.mdx#convention) | 같은 레벨 인터셉트 | 형제 경로를 모달에서 미리 보기           |
| [`(..)folder`](../api-reference/file-conventions/intercepting-routes.mdx#convention) | 부모 인터셉트      | 부모의 하위 경로를 오버레이로 열기       |
| [`(..)(..)folder`](../api-reference/file-conventions/intercepting-routes.mdx#convention) | 두 레벨 인터셉트 | 깊게 중첩된 오버레이                     |
| [`(...)folder`](../api-reference/file-conventions/intercepting-routes.mdx#convention) | 루트에서 인터셉트 | 현재 뷰 안에서 임의의 경로 표시          |

## 프로젝트 구성

Next.js는 프로젝트 파일을 어떻게 구성하고 함께 배치할지에 대해 **특정 방식을 강제하지 않습니다**. 하지만 프로젝트를 구성하는 데 도움이 되는 여러 기능을 제공합니다.

### 구성 요소 계층 구조

특수 파일에 정의된 구성 요소는 다음과 같은 특정 계층 구조로 렌더링됩니다.

- `layout.js`
- `template.js`
- `error.js` (React 오류 경계)
- `loading.js` (React suspense 경계)
- `not-found.js` ("찾을 수 없음" UI를 위한 React 오류 경계)
- `page.js` 또는 중첩된 `layout.js`

<Image alt="파일 규칙을 위한 구성 요소 계층 구조" srcLight="/docs/light/file-conventions-component-hierarchy.png" srcDark="/docs/dark/file-conventions-component-hierarchy.png" width="1600" height="643" />

구성 요소는 중첩 경로에서 재귀적으로 렌더링되므로, 어떤 경로 세그먼트의 구성 요소는 상위 세그먼트의 구성 요소 **안쪽에** 중첩됩니다.

<Image alt="중첩된 파일 규칙의 구성 요소 계층 구조" srcLight="/docs/light/nested-file-conventions-component-hierarchy.png" srcDark="/docs/dark/nested-file-conventions-component-hierarchy.png" width="1600" height="863" />

### 코로케이션

`app` 디렉터리에서는 중첩된 폴더가 경로 구조를 정의합니다. 각 폴더는 URL 경로의 해당 세그먼트에 매핑되는 경로 세그먼트를 나타냅니다.

하지만 폴더를 통해 경로 구조를 정의하더라도, 경로 세그먼트에 `page.js` 또는 `route.js` 파일이 추가되기 전까지는 해당 경로에 **공개적으로 접근할 수 없습니다**.

<Image alt="경로 세그먼트에 page.js 또는 route.js 파일이 추가되기 전까지는 경로에 공개적으로 접근할 수 없음을 보여주는 다이어그램" srcLight="/docs/light/project-organization-not-routable.png" srcDark="/docs/dark/project-organization-not-routable.png" width="1600" height="444" />

그리고 경로가 공개적으로 접근 가능해지더라도, `page.js` 또는 `route.js`가 반환하는 **콘텐츠만** 클라이언트로 전송됩니다.

<Image alt="page.js와 route.js 파일이 경로를 공개적으로 접근 가능하게 만드는 방식을 보여주는 다이어그램" srcLight="/docs/light/project-organization-routable.png" srcDark="/docs/dark/project-organization-routable.png" width="1600" height="687" />

즉, **프로젝트 파일**은 `app` 디렉터리의 경로 세그먼트 안에 실수로 라우팅되지 않으면서도 **안전하게 함께 배치**될 수 있습니다.

<Image alt="세그먼트에 page.js 또는 route.js 파일이 있어도 함께 배치된 프로젝트 파일은 라우팅되지 않음을 보여주는 다이어그램" srcLight="/docs/light/project-organization-colocation.png" srcDark="/docs/dark/project-organization-colocation.png" width="1600" height="1011" />

> **알아두면 좋은 점**: 프로젝트 파일을 `app` 안에 함께 배치할 **수는 있지만**, 반드시 그래야 하는 것은 아닙니다. 원한다면 [프로젝트 파일을 `app` 디렉터리 밖에 둘 수도 있습니다](#store-project-files-outside-of-app).

### 프라이빗 폴더

프라이빗 폴더는 폴더 이름 앞에 밑줄을 붙여 만들 수 있습니다: `_folderName`

이것은 해당 폴더가 비공개 구현 세부사항이며 라우팅 시스템에서 고려되지 않아야 함을 나타냅니다. 따라서 **그 폴더와 모든 하위 폴더**가 라우팅에서 제외됩니다.

<Image alt="프라이빗 폴더를 사용하는 폴더 구조 예시" srcLight="/docs/light/project-organization-private-folders.png" srcDark="/docs/dark/project-organization-private-folders.png" width="1600" height="849" />

`app` 디렉터리 안의 파일은 기본적으로 [안전하게 함께 배치할 수 있으므로](#colocation), 코로케이션을 위해 프라이빗 폴더가 필수는 아닙니다. 하지만 다음과 같은 경우에는 유용할 수 있습니다.

- UI 로직과 라우팅 로직을 분리할 때
- 프로젝트와 Next.js 생태계 전반에서 내부 파일을 일관되게 구성할 때
- 코드 편집기에서 파일을 정렬하고 그룹화할 때
- 향후 Next.js 파일 규칙과의 잠재적인 이름 충돌을 피할 때

> **알아두면 좋은 점**:
>
> - 프레임워크 규칙은 아니지만, 같은 밑줄 패턴을 사용해 프라이빗 폴더 밖의 파일도 "private"으로 표시하는 방식을 고려할 수 있습니다.
> - 밑줄로 시작하는 URL 세그먼트를 만들려면 폴더 이름 앞에 `%5F`(밑줄의 URL 인코딩 형태)를 붙일 수 있습니다: `%5FfolderName`.
> - 프라이빗 폴더를 사용하지 않는다면, 예상치 못한 이름 충돌을 방지하기 위해 Next.js의 [특수 파일 규칙](#routing-files)을 알아두는 것이 좋습니다.

### 경로 그룹

경로 그룹은 폴더 이름을 괄호로 감싸서 만들 수 있습니다: `(folderName)`

이것은 해당 폴더가 구성을 위한 용도이며, 경로의 URL 경로에는 **포함되지 않아야 함**을 나타냅니다.

<Image alt="경로 그룹을 사용하는 폴더 구조 예시" srcLight="/docs/light/project-organization-route-groups.png" srcDark="/docs/dark/project-organization-route-groups.png" width="1600" height="849" />

경로 그룹은 다음과 같은 경우에 유용합니다.

- 사이트 섹션, 의도, 팀별로 경로를 구성할 때. 예: 마케팅 페이지, 관리자 페이지 등
- 같은 경로 세그먼트 수준에서 중첩 레이아웃을 활성화할 때:
  - [여러 루트 레이아웃을 포함해 같은 세그먼트에 여러 중첩 레이아웃 만들기](#creating-multiple-root-layouts)
  - [공통 세그먼트의 일부 경로에만 레이아웃 적용하기](#opting-specific-segments-into-a-layout)

### `src` folder

Next.js는 애플리케이션 코드(`app` 포함)를 선택적 [`src` folder](../api-reference/file-conventions/src-folder.mdx) 안에 저장하는 것을 지원합니다. 이렇게 하면 주로 프로젝트 루트에 위치하는 프로젝트 구성 파일과 애플리케이션 코드를 분리할 수 있습니다.

<Image alt="`src` folder를 사용하는 폴더 구조 예시" srcLight="/docs/light/project-organization-src-directory.png" srcDark="/docs/dark/project-organization-src-directory.png" width="1600" height="687" />

## 예시

다음 섹션은 일반적인 전략을 매우 높은 수준에서 개괄합니다. 가장 단순한 핵심은, 자신과 팀에 잘 맞는 전략을 선택하고 프로젝트 전반에서 일관되게 유지하는 것입니다.

> **알아두면 좋은 점**: 아래 예시에서는 `components`와 `lib` 폴더를 일반적인 자리표시자로 사용합니다. 이 이름 자체에 특별한 프레임워크 의미는 없으며, 프로젝트에서는 `ui`, `utils`, `hooks`, `styles` 등 다른 폴더 이름을 사용할 수도 있습니다.

### 프로젝트 파일을 `app` 밖에 저장하기

이 전략은 모든 애플리케이션 코드를 프로젝트 **루트의** 공유 폴더에 저장하고, `app` 디렉터리는 오직 라우팅 목적에만 사용합니다.

<Image alt="프로젝트 파일을 app 밖에 둔 폴더 구조 예시" srcLight="/docs/light/project-organization-project-root.png" srcDark="/docs/dark/project-organization-project-root.png" width="1600" height="849" />

### `app` 내부 최상위 폴더에 프로젝트 파일 저장하기

이 전략은 모든 애플리케이션 코드를 **`app` 디렉터리 루트의** 공유 폴더에 저장합니다.

<Image alt="프로젝트 파일을 app 내부에 둔 폴더 구조 예시" srcLight="/docs/light/project-organization-app-root.png" srcDark="/docs/dark/project-organization-app-root.png" width="1600" height="849" />

### 기능 또는 경로별로 프로젝트 파일 분리하기

이 전략은 전역적으로 공유되는 애플리케이션 코드를 루트 `app` 디렉터리에 저장하고, 더 구체적인 애플리케이션 코드는 이를 사용하는 경로 세그먼트로 **분리**합니다.

<Image alt="프로젝트 파일을 기능 또는 경로별로 분리한 폴더 구조 예시" srcLight="/docs/light/project-organization-app-root-split.png" srcDark="/docs/dark/project-organization-app-root-split.png" width="1600" height="1011" />

### URL 경로에 영향을 주지 않고 경로 구성하기

URL에 영향을 주지 않고 경로를 구성하려면, 관련 경로를 함께 유지하는 그룹을 만드세요. 괄호 안의 폴더는 URL에서 생략됩니다. 예: `(marketing)`, `(shop)`.

<Image alt="경로 그룹으로 경로 구성하기" srcLight="/docs/light/route-group-organisation.png" srcDark="/docs/dark/route-group-organisation.png" width="1600" height="930" />

`(marketing)`과 `(shop)` 안의 경로는 동일한 URL 계층 구조를 공유하지만, 각 폴더 안에 `layout.js` 파일을 추가하면 그룹마다 다른 레이아웃을 만들 수 있습니다.

<Image alt="여러 레이아웃을 가진 경로 그룹" srcLight="/docs/light/route-group-multiple-layouts.png" srcDark="/docs/dark/route-group-multiple-layouts.png" width="1600" height="768" />

### 특정 세그먼트에만 레이아웃 적용하기

특정 경로에만 레이아웃을 적용하려면 새 경로 그룹(예: `(shop)`)을 만들고, 같은 레이아웃을 공유하는 경로(예: `account`, `cart`)를 그 그룹으로 이동하세요. 그룹 밖의 경로(예: `checkout`)는 그 레이아웃을 공유하지 않습니다.

<Image alt="선택적으로 레이아웃을 적용한 경로 그룹" srcLight="/docs/light/route-group-opt-in-layouts.png" srcDark="/docs/dark/route-group-opt-in-layouts.png" width="1600" height="930" />

### 특정 경로에만 로딩 스켈레톤 적용하기

특정 경로에 `loading.js` 파일을 통한 [로딩 스켈레톤](../api-reference/file-conventions/loading.mdx)을 적용하려면, 새 경로 그룹(예: `/(overview)`)을 만든 다음 `loading.tsx`를 그 경로 그룹 안으로 이동하세요.

<Image alt="경로 그룹 안에 loading.tsx와 page.tsx가 있는 폴더 구조" srcLight="/docs/light/route-group-loading.png" srcDark="/docs/dark/route-group-loading.png" width="1600" height="444" />

이제 `loading.tsx` 파일은 URL 경로 구조에 영향을 주지 않으면서, 대시보드의 모든 페이지가 아니라 dashboard → overview 페이지에만 적용됩니다.

### 여러 루트 레이아웃 만들기

여러 [루트 레이아웃](../api-reference/file-conventions/layout.mdx#root-layout)를 만들려면, 최상위 `layout.js` 파일을 제거하고 각 경로 그룹 안에 `layout.js` 파일을 추가하세요. 이 방법은 UI나 경험이 완전히 다른 섹션으로 애플리케이션을 분할할 때 유용합니다. `<html>`과 `<body>` 태그는 각 루트 레이아웃에 추가해야 합니다.

<Image alt="여러 루트 레이아웃을 가진 경로 그룹" srcLight="/docs/light/route-group-multiple-root-layouts.png" srcDark="/docs/dark/route-group-multiple-root-layouts.png" width="1600" height="687" />

위 예시에서는 `(marketing)`과 `(shop)`이 각각 자체 루트 레이아웃을 가집니다.
