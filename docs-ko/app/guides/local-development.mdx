Next.js는 훌륭한 개발자 경험을 제공하도록 설계되었습니다. 애플리케이션이 성장함에 따라 로컬 개발 중에 컴파일 시간이 느려질 수 있습니다. 이 가이드는 일반적인 컴파일 시간 성능 문제를 식별하고 해결하는 데 도움이 됩니다.

## 로컬 개발 vs. 프로덕션

The development process with `next dev`을 사용한 개발 프로세스는 `next build` 및 `next start`과 다릅니다.

`next dev`은 사용자가 경로를 열거나 탐색할 때 애플리케이션에서 경로를 컴파일합니다. 이를 통해 애플리케이션의 모든 경로가 컴파일될 때까지 기다리지 않고 개발 서버를 시작할 수 있으며, 이는 더 빠르고 더 적은 메모리를 사용합니다. 프로덕션 빌드를 실행하면 로컬 개발에 필요하지 않은 파일 축소 및 콘텐츠 해시 생성과 같은 다른 최적화가 적용됩니다.

## 로컬 개발 성능 개선

### 1. 컴퓨터의 바이러스 백신을 확인하세요.

바이러스 백신 소프트웨어는 파일 액세스 속도를 저하시킬 수 있습니다. 이는 Windows 컴퓨터에서 더 일반적이지만 바이러스 백신 도구가 설치된 모든 시스템에서 문제가 될 수 있습니다.

Windows에서는 [Microsoft Defender 바이러스 백신 제외 목록](https://support.microsoft.com/en-us/windows/virus-and-threat-protection-in-the-windows-security-app-1362f4cd-d71a-b52a-0b66-c2820032b65e#bkmk_threat-protection-settings)에 프로젝트를 추가할 수 있습니다.

1. Open the **"Windows 보안"** 애플리케이션을 연 다음 **"바이러스 및 위협 방지"** → **"설정 관리"** → \*\*"제외 항목 추가 또는 제거"\*\*를 선택합니다.**"Add or remove exclusions"**.
1. Add a **"폴더"** 제외를 추가합니다. 프로젝트 폴더를 선택하세요.

macOS에서는 터미널 내부에서 [Gatekeeper](https://support.apple.com/guide/security/gatekeeper-and-runtime-protection-sec5599b66df/web)를 비활성화할 수 있습니다.

1. 터미널에서 `sudo spctl developer-mode enable-terminal`을 실행하세요.
1. Open the **"시스템 설정"** 앱을 연 다음 **"개인정보 및 보안"** → \*\*"개발자 도구"\*\*를 선택합니다.**"Developer Tools"**.
1. 터미널이 목록에 있고 활성화되어 있는지 확인하세요. iTerm 또는 Ghostty와 같은 타사 터미널을 사용하는 경우 해당 터미널을 목록에 추가하세요.
1. 터미널을 다시 시작하세요.

귀하 또는 귀하의 고용주가 시스템에 다른 바이러스 백신 솔루션을 구성한 경우 해당 제품에 대한 관련 설정을 검사해야 합니다.

### 2. Next.js를 업데이트하고 Turbopack를 사용합니다.

Next.js의 최신 버전을 사용하고 있는지 확인하세요. 각각의 새 버전에는 성능 향상이 포함되는 경우가 많습니다.

Turbopack는 이제 Next.js 개발을 위한 기본 번들러이며 webpack에 비해 상당한 성능 향상을 제공합니다.

```bash
npm install next@latest
npm run dev  # Turbopack is used by default
```

Turbopack 대신 Webpack를 사용해야 하는 경우 다음을 선택할 수 있습니다.

```bash
npm run dev --webpack
```

[Turbopack에 대해 자세히 알아보세요](https://nextjs.org/blog/turbopack-for-development-stable). 자세한 내용은 [업그레이드 가이드](upgrading/index.mdx) 및 codemods를 참조하세요.

### 3. 수입품을 확인하세요

코드를 가져오는 방법은 컴파일 및 번들링 시간에 큰 영향을 미칠 수 있습니다. [패키지 번들링 최적화](package-bundling.mdx)에 대해 자세히 알아보고 [Dependency Cruiser](https://github.com/sverweij/dependency-cruiser) 또는 [Madge](https://github.com/pahen/madge)와 같은 도구를 살펴보세요.

#### 아이콘 라이브러리

Libraries like `@material-ui/icons`, `@phosphor-icons/react` 또는 `react-icons`과 같은 라이브러리는 몇 개만 사용하더라도 수천 개의 아이콘을 가져올 수 있습니다. 필요한 아이콘만 가져오십시오.

```jsx
// Instead of this:
import { TriangleIcon } from '@phosphor-icons/react'

// Do this:
import { TriangleIcon } from '@phosphor-icons/react/dist/csr/Triangle'
```

사용 중인 아이콘 라이브러리에 대한 문서에서 사용할 가져오기 패턴을 찾을 수 있는 경우가 많습니다. 이 예는 [`@phosphor-icons/react`](https://www.npmjs.com/package/@phosphor-icons/react#import-performance-optimization) 권장 사항을 따릅니다.

Libraries like `react-icons`와 같은 라이브러리에는 다양한 아이콘 세트가 포함되어 있습니다. 한 세트를 선택하고 해당 세트를 고수하세요.

예를 들어, 애플리케이션이 `react-icons`을 사용하고 다음을 모두 가져오는 경우:

- `pi` (형광체 아이콘)
- `md`(머티리얼 디자인 아이콘)
- `tb` (테이블 아이콘)
- `cg`(cssgg)

결합하면 각각에서 단일 가져오기만 사용하더라도 컴파일러가 처리해야 하는 수만 개의 모듈이 됩니다.

#### 배럴 파일

"배럴 파일"은 다른 파일에서 많은 항목을 내보내는 파일입니다. 컴파일러는 가져오기를 사용하여 모듈 범위에 부작용이 있는지 찾기 위해 구문 분석해야 하기 때문에 빌드 속도가 느려질 수 있습니다.

가능하면 특정 파일에서 직접 가져오십시오. [배럴 파일에 대해 자세히 알아보세요](https://vercel.com/blog/how-we-optimized-package-imports-in-next-js) 및 Next.js에 내장된 최적화 기능.

#### 패키지 가져오기 최적화

Next.js는 특정 패키지에 대한 가져오기를 자동으로 최적화할 수 있습니다. 배럴 파일을 활용하는 패키지를 사용하는 경우 해당 패키지를 `next.config.js`에 추가하세요.

```jsx
module.exports = {
  experimental: {
    optimizePackageImports: ['package-name'],
  },
}
```

Turbopack는 가져오기를 자동으로 분석하고 최적화합니다. 이 구성은 필요하지 않습니다.

### 4. Tailwind CSS 설정을 확인하세요.

Tailwind CSS를 사용하는 경우 올바르게 설정되었는지 확인하세요.

일반적인 실수는 `content` 또는 스캔해서는 안되는 기타 대규모 파일 디렉터리를 포함하는 방식으로 `node_modules` 배열을 구성하는 것입니다.

Tailwind CSS 버전 3.4.8 이상에서는 빌드 속도를 저하시킬 수 있는 설정에 대해 경고합니다.

1. In your `tailwind.config.js`에서 스캔할 파일을 구체적으로 지정하십시오.

   ```jsx
   module.exports = {
     content: [
       './src/**/*.{js,ts,jsx,tsx}', // Good
       // This might be too broad
       // It will match `packages/**/node_modules` too
       // '../../packages/**/*.{js,ts,jsx,tsx}',
     ],
   }
   ```

1. Avoid scanning unnecessary files:

   ```jsx
   module.exports = {
     content: [
       // Better - only scans the 'src' folder
       '../../packages/ui/src/**/*.{js,ts,jsx,tsx}',
     ],
   }
   ```

### 5. 사용자 정의 웹팩 설정 확인

사용자 정의 웹팩 설정을 추가한 경우 컴파일 속도가 느려질 수 있습니다.

지역 발전을 위해 정말로 필요한지 생각해 보세요. 선택적으로 프로덕션 빌드를 위한 특정 도구만 포함하거나 대신 기본 Turbopack 번들러를 사용하고 [로더](../api-reference/config/next-config-js/turbopack.mdx#configuring-webpack-loaders)를 구성하여 탐색할 수 있습니다.

### 6. 메모리 사용량 최적화

앱의 크기가 매우 크면 더 많은 메모리가 필요할 수 있습니다.

[메모리 사용량 최적화에 대해 자세히 알아보세요](memory-usage.mdx).

### 7. 서버 구성 요소 및 데이터 가져오기

서버 구성 요소를 변경하면 구성 요소에 대한 새 데이터 가져오기를 포함하여 새 변경 사항을 표시하기 위해 전체 페이지가 로컬로 다시 렌더링됩니다.

실험적인 `serverComponentsHmrCache` 옵션을 사용하면 로컬 개발 시 HMR(핫 모듈 교체) 새로 고침 전반에 걸쳐 서버 구성 요소의 `fetch` 응답을 캐시할 수 있습니다. 그 결과, 청구된 API 통화에 대한 응답 속도가 빨라지고 비용이 절감됩니다.

[실험적 옵션에 대해 자세히 알아보세요](../api-reference/config/next-config-js/serverComponentsHmrCache.mdx).### 8. Docker를 통한 로컬 개발 고려

### 자세한 가져오기 로깅

If you're using Docker for development on Mac or Windows, you may experience significantly slower performance compared to running Next.js locally. 파일에서  옵션을 사용하여 개발 중에 일어나는 일에 대한 자세한 정보를 확인하세요.

Docker's filesystem access on Mac and Windows can cause Hot Module Replacement (HMR) to take seconds or even minutes, while the same application runs with fast HMR when developed locally..

Turbopack 추적은 로컬 개발 중에 애플리케이션의 성능을 이해하는 데 도움이 되는 도구입니다.
각 모듈을 컴파일하는 데 걸리는 시간과 모듈 간의 관계에 대한 자세한 정보를 제공합니다.

- Use local development (`npm run dev` or `pnpm dev`) instead of Docker during development
- Reserve Docker for production deployments and testing production builds
- If you must use Docker for development, consider using Docker on a Linux machine or VM

[Learn more about Docker deployment](../getting-started/deploying.mdx#docker) for production use.을 사용할 수 없는 버전에서는 명령 이름이 로 지정되었습니다.

## Tools for finding problems

### 아직도 문제가 있나요?

Use the `logging.fetches` option in your `next.config.js` file, to see more detailed information about what's happening during development: 섹션에서 생성된 추적 파일을 공유하고  또는 에서 공유합니다.

```js
module.exports = {
  logging: {
    fetches: {
      fullUrl: true,
    },
  },
}
```

[Learn more about fetch logging](../api-reference/config/next-config-js/logging.mdx).

### Turbopack tracing

Turbopack tracing is a tool that helps you understand the performance of your application during local development.
It provides detailed information about the time taken for each module to compile and how they are related.

1. Make sure you have the latest version of Next.js installed.

1. Generate a Turbopack trace file:

   ```bash
   NEXT_TURBOPACK_TRACING=1 npm run dev
   ```

1. Navigate around your application or make edits to files to reproduce the problem.

1. Stop the Next.js development server.

1. A file called `trace-turbopack` will be available in the `.next/dev` folder.

1. You can interpret the file using `npx next internal trace [path-to-file]`:

   ```bash
   npx next internal trace .next/dev/trace-turbopack
   ```

   On versions where `trace` is not available, the command was named `turbo-trace-server`:

   ```bash
   npx next internal turbo-trace-server .next/dev/trace-turbopack
   ```

1. Once the trace server is running you can view the trace at https://trace.nextjs.org/.

1. By default the trace viewer will aggregate timings, in order to see each individual time you can switch from "Aggregated in order" to "Spans in order" at the top right of the viewer.

> **Good to know**: The trace file is place under the development server directory, which defaults to `.next/dev`. This is controllable using the [`isolatedDevBuild`](../api-reference/config/next-config-js/isolatedDevBuild.mdx) flag in your Next config file.

### Still having problems?

Share the trace file generated in the [Turbopack Tracing](#turbopack-tracing) section and share it on [GitHub Discussions](https://github.com/vercel/next.js/discussions) or [Discord](https://nextjs.org/discord).
