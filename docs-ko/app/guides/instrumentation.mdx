계측은 코드를 사용하여 모니터링 및 로깅 도구를 애플리케이션에 통합하는 프로세스입니다. 이를 통해 애플리케이션의 성능과 동작을 추적하고 프로덕션에서 문제를 디버깅할 수 있습니다.

## 컨벤션

계측을 설정하려면 프로젝트의 `instrumentation.ts|js` 파일을 만듭니다.**root directory** of your project (or inside the [`src`](../api-reference/file-conventions/src-folder.mdx) folder if using one).

그런 다음 파일에서 `register` 함수를 내보냅니다. 이 함수는 새로운 Next.js 서버 인스턴스가 시작될 때 **한 번** 호출됩니다.

예를 들어, [OpenTelemetry](https://opentelemetry.io/) 및 [@vercel/otel](https://vercel.com/docs/observability/otel-overview)과 함께 Next.js를 사용하려면 다음을 수행하세요.

```ts filename="instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

```js filename="instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

전체 구현을 보려면 [Next.js with OpenTelemetry 예시](https://github.com/vercel/next.js/tree/canary/examples/with-opentelemetry)를 참조하세요.

> **알면 좋은 점**:
>
> - The `instrumentation` 파일은 `app` 또는 `pages` 디렉터리가 아닌 프로젝트 루트에 있어야 합니다. `src` 폴더를 사용하는 경우 파일을 `src` 및 `pages`과 함께 `app` 안에 배치하세요.
> - If you use the [`pageExtensions` 구성 옵션](../api-reference/config/next-config-js/pageExtensions.mdx)을 사용하여 접미사를 추가하는 경우 일치하도록 `instrumentation` 파일 이름도 업데이트해야 합니다.

## 예

### 부작용이 있는 파일 가져오기

때로는 발생할 수 있는 부작용 때문에 코드에서 파일을 가져오는 것이 유용할 수 있습니다. 예를 들어, 전역 변수 세트를 정의하는 파일을 가져올 수 있지만 가져온 파일을 코드에서 명시적으로 사용하지 않을 수 있습니다. 패키지가 선언한 전역 변수에는 계속 액세스할 수 있습니다.

We recommend importing files using JavaScript `import` 함수 내에서 JavaScript `register` 구문을 사용하여 파일을 가져오는 것이 좋습니다. 다음 예에서는 `import` 함수에서 `register`의 기본 사용법을 보여줍니다.

```ts filename="instrumentation.ts" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

> **알아두면 좋은 점:**
>
> 파일 상단이 아닌 `register` 함수 내에서 파일을 가져오는 것이 좋습니다. 이렇게 하면 모든 부작용을 코드의 한 위치에 배치할 수 있으며 파일 상단에서 전체적으로 가져오는 데 따른 의도하지 않은 결과를 방지할 수 있습니다.

### 런타임별 코드 가져오기

Next.js는 모든 환경에서 `register`을 호출하므로 특정 런타임을 지원하지 않는 코드(예: [Edge 또는 Node.js](../api-reference/edge.mdx))를 조건부로 가져오는 것이 중요합니다. `NEXT_RUNTIME` 환경 변수를 사용하여 현재 환경을 가져올 수 있습니다.

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```
