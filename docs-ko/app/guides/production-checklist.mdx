Next.js 애플리케이션을 프로덕션으로 전환하기 전에 최상의 사용자 경험, 성능 및 보안을 위해 구현을 고려해야 하는 몇 가지 최적화 및 패턴이 있습니다.

이 페이지에서는 [애플리케이션 구축](#during-development) 및 [프로덕션 시작 전](#before-going-to-production)에서 참조로 사용할 수 있는 모범 사례와 알아야 할 [자동 Next.js 최적화](#automatic-optimizations)를 제공합니다.

## 자동 최적화

이러한 Next.js 최적화는 기본적으로 활성화되어 있으며 구성이 필요하지 않습니다.

- **[서버 구성 요소](../getting-started/server-and-client-components.mdx):** Next.js는 기본적으로 서버 구성 요소를 사용합니다. 서버 구성 요소는 서버에서 실행되며 클라이언트에서 렌더링하는 데 JavaScript가 필요하지 않습니다. 따라서 클라이언트 측 JavaScript 번들의 크기에는 영향을 미치지 않습니다. 그런 다음 상호작용을 위해 필요에 따라 [클라이언트 구성요소](../getting-started/server-and-client-components.mdx)를 사용할 수 있습니다.
- **[코드 분할](../getting-started/linking-and-navigating.mdx#how-navigation-works):** 서버 구성 요소는 경로 세그먼트별로 자동 코드 분할을 활성화합니다. 적절한 경우 [지연 로딩](lazy-loading.mdx) 클라이언트 구성 요소 및 타사 라이브러리를 고려할 수도 있습니다.
- **[프리페치](../getting-started/linking-and-navigating.mdx#prefetching):** 새 경로에 대한 링크가 사용자의 뷰포트에 들어가면 Next.js는 백그라운드에서 경로를 프리페치합니다. 이를 통해 새로운 경로를 거의 즉시 탐색할 수 있습니다. 적절한 경우 프리패치를 선택 해제할 수 있습니다.
- **[정적 렌더링](caching.mdx#static-rendering):** Next.js는 빌드 시 서버에 서버 및 클라이언트 구성 요소를 정적으로 렌더링하고 렌더링된 결과를 캐시하여 애플리케이션 성능을 향상시킵니다. 적절한 경우 특정 경로에 대해 [동적 렌더링](caching.mdx#dynamic-rendering)을 선택할 수 있습니다. {/* TODO: Update when PPR is stable */}
- **[캐싱](caching.mdx):** Next.js는 데이터 요청, 서버 및 클라이언트 구성 요소의 렌더링 결과, 정적 자산 등을 캐시하여 서버, 데이터베이스 및 백엔드 서비스에 대한 네트워크 요청 수를 줄입니다. 적절한 경우 캐싱을 선택 해제할 수 있습니다.

이러한 기본값은 애플리케이션의 성능을 향상시키고 각 네트워크 요청에서 전송되는 데이터의 양과 비용을 줄이는 것을 목표로 합니다.

## 개발 중

애플리케이션을 구축하는 동안 최고의 성능과 사용자 경험을 보장하기 위해 다음 기능을 사용하는 것이 좋습니다.

### 라우팅 및 렌더링-  레이아웃을 사용하여 페이지 간에 UI를 공유하고 탐색 시 을 활성화합니다.

- **[Layouts 구성 요소](../api-reference/file-conventions/layout.mdx):** [클라이언트 측 탐색 및 프리패치](../getting-started/linking-and-navigating.mdx#client-side-transitions)에  구성 요소를 사용합니다.
- **[`<Link>` component](../api-reference/components/link.mdx):** 사용자 정의 오류 페이지를 생성하여 프로덕션에서 `<Link>` component for [포괄 오류](../getting-started/linking-and-navigating.mdx#how-navigation-works) 및 를 원활하게 처리합니다.
- **[클라이언트 및 서버 구성 요소](../getting-started/error-handling.mdx):** 서버 및 클라이언트 구성 요소에 권장되는 구성 패턴을 따르고 [catch-all errors 경계](../getting-started/error-handling.mdx)의 배치를 확인하여 클라이언트 측 JavaScript 번들을 불필요하게 늘리는 것을 방지하세요.[404 errors](../api-reference/file-conventions/not-found.mdx) in production by creating custom error pages.
- **[동적 API](../getting-started/server-and-client-components.mdx#examples):** [`"use client"` boundaries](../getting-started/server-and-client-components.mdx#examples#moving-client-components-down-the-tree) 및  소품과 같은 동적 API는 전체 경로를 \[동적]으로 선택합니다. 렌더링]\(caching.mdx#dynamic-rendering)(또는 에서 사용되는 경우 전체 애플리케이션). 동적 API 사용이 의도적인지 확인하고 적절한 경우  경계로 래핑합니다.
- **[Dynamic APIs](caching.mdx#dynamic-rendering):** Be aware that Dynamic APIs like [`cookies`](../api-reference/functions/cookies.mdx) and the [`searchParams`](../api-reference/file-conventions/page.mdx#searchparams-optional) prop will opt the entire route into [Dynamic Rendering](caching.mdx#dynamic-rendering) (or your whole application if used in the [Root Layout](../api-reference/file-conventions/layout.mdx#root-layout)). Ensure Dynamic API usage is intentional and wrap them in `<Suspense>` boundaries where appropriate.

> **알아두면 좋은 정보**: [부분 사전 렌더링(실험용)](https://nextjs.org/blog/next-14#partial-prerendering-preview)을 사용하면 전체 경로를 동적 렌더링으로 선택하지 않고도 경로의 일부를 동적으로 만들 수 있습니다.

### 데이터 가져오기 및 캐싱

- **[서버 구성 요소](../getting-started/fetching-data.mdx):** 서버 구성 요소를 사용하여 서버에서 데이터를 가져오는 이점을 활용합니다.
- **[경로 처리기](../api-reference/file-conventions/route.mdx):** 경로 처리기를 사용하여 클라이언트 구성 요소에서 백엔드 리소스에 액세스합니다. 그러나 추가 서버 요청을 피하기 위해 서버 구성 요소에서 경로 처리기를 호출하지 마십시오.
- **[스트리밍](../api-reference/file-conventions/loading.mdx):** 로딩 UI 및 React Suspense를 사용하여 서버에서 클라이언트로 UI를 점진적으로 전송하고 데이터를 가져오는 동안 전체 경로가 차단되는 것을 방지합니다.
- **[병렬 데이터 가져오기](../getting-started/fetching-data.mdx#parallel-data-fetching):** 필요한 경우 데이터를 병렬로 가져와 네트워크 폭포수를 줄입니다. 또한 적절한 경우 [데이터 사전 로드](../getting-started/fetching-data.mdx#preloading-data)를 고려하세요.
- **[데이터 캐싱](caching.mdx#data-cache):** 데이터 요청이 캐시되고 있는지 확인하고 필요한 경우 캐싱을 선택합니다. `fetch`을 사용하지 않는 요청이 [캐시](../api-reference/functions/unstable_cache.mdx)되는지 확인하세요.
- **[정적 이미지](../api-reference/file-conventions/public-folder.mdx):** `public` 디렉토리를 사용하여 애플리케이션의 정적 자산을 자동으로 캐시합니다. 이미지.

### UI 및 접근성-  서버 작업을 사용하여 양식 제출, 서버측 유효성 검사 및 오류를 처리합니다.

- **[전역 오류 UI](forms.mdx):** 을 추가하여 일관되고 액세스 가능한 대체 UI를 제공하고 앱 전체에서 발견되지 않은 오류에 대한 복구를 제공합니다.
- **[Global 404](../api-reference/file-conventions/error.mdx#global-error):** 앱 전체에서 비교할 수 없는 경로에 대해 액세스 가능한 404를 제공하려면 `app/global-error.tsx`을 추가하세요.
- **[Global 404](../api-reference/file-conventions/not-found.mdx#global-not-foundjs-experimental):** Add `app/global-not-found.tsx` to serve an accessible 404 for unmatched routes across your app.

* **[글꼴 모듈](../api-reference/components/font.mdx):** 다른 정적 자산과 함께 글꼴 파일을 자동으로 호스팅하고 외부 네트워크 요청을 제거하며 [레이아웃 변경](https://web.dev/articles/cls)을 줄이는 글꼴 모듈을 사용하여 글꼴을 최적화합니다.
* **[`<Image>` 구성 요소](../api-reference/components/image.mdx):** 이미지를 자동으로 최적화하고 레이아웃 변경을 방지하며 WebP와 같은 최신 형식으로 제공하는 이미지 구성 요소를 사용하여 이미지를 최적화합니다.
* **[`<Script>` 구성 요소](scripts.mdx):** 스크립트를 자동으로 연기하고 기본 스레드를 차단하는 것을 방지하는 스크립트 구성 요소를 사용하여 타사 스크립트를 최적화합니다.
* **[ESLint](../../architecture/accessibility.mdx#linting):** 내장된 `eslint-plugin-jsx-a11y` 플러그인을 사용하여 접근성 문제를 조기에 파악하세요.

### 보안

- **[테인팅](../api-reference/config/next-config-js/taint.mdx):** 데이터 객체 및/또는 특정 값을 오염시켜 민감한 데이터가 클라이언트에 노출되는 것을 방지합니다.
- **[서버 작업](../getting-started/updating-data.mdx):** 사용자가 서버 작업을 호출할 수 있는 권한이 있는지 확인하세요. 권장되는 [보안 관행](https://nextjs.org/blog/security-nextjs-server-components-actions)을 검토하세요.

* **[환경 변수](environment-variables.mdx):** `.env.*` 파일이 `.gitignore`에 추가되고 공용 변수에만 `NEXT_PUBLIC_` 접두사가 붙는지 확인하세요.
* **[콘텐츠 보안 정책](content-security-policy.mdx):** 크로스 사이트 스크립팅, 클릭재킹, 기타 코드 삽입 공격과 같은 다양한 보안 위협으로부터 애플리케이션을 보호하려면 콘텐츠 보안 정책을 추가하는 것이 좋습니다.

### 메타데이터 및 SEO

- **[메타데이터 API](../getting-started/metadata-and-og-images.mdx):** 페이지 제목, 설명 등을 추가하여 애플리케이션의 검색 엔진 최적화(SEO)를 개선하려면 메타데이터 API를 사용하세요.
- **[오픈 그래프(OG) 이미지](../api-reference/file-conventions/metadata/opengraph-image.mdx):** OG 이미지를 생성하여 소셜 공유용 애플리케이션을 준비합니다.
- **[사이트맵](../api-reference/functions/generate-sitemaps.mdx) 및 [로봇](../api-reference/file-conventions/metadata/robots.mdx):** 사이트맵과 로봇 파일을 생성하여 검색 엔진이 페이지를 크롤링하고 색인을 생성하도록 돕습니다.

### 유형 안전

- **TypeScript 및 [TS 플러그인](../api-reference/config/typescript.mdx):** 유형 안전성을 높이고 오류를 조기에 포착하려면 TypeScript 및 TypeScript 플러그인을 사용하세요.

## 제작에 들어가기 전

프로덕션으로 이동하기 전에 `next build`을 실행하여 애플리케이션을 로컬로 빌드하고 빌드 오류를 포착한 다음 `next start`을 실행하여 프로덕션과 유사한 환경에서 애플리케이션의 성능을 측정할 수 있습니다.

### 핵심 웹 바이탈-  시크릿 모드에서 Lighthouse를 실행하면 사용자가 사이트를 어떻게 경험하게 될지 더 잘 이해하고 개선이 필요한 부분을 식별할 수 있습니다. 이는 시뮬레이션된 테스트이며 현장 데이터(예: Core Web Vitals) 확인과 결합되어야 합니다.

- **[Lighthouse 후크](https://developers.google.com/web/tools/lighthouse):** 이 후크를 사용하여  데이터를 분석 도구로 보냅니다.

* **[`useReportWebVitals` hook](../api-reference/functions/use-report-web-vitals.mdx):** Use this hook to send [가져오기 비용](https://web.dev/articles/vitals) data to analytics tools.

### Analyzing bundles

Use the [`@next/bundle-analyzer` plugin](package-bundling.mdx#nextbundle-analyzer-for-webpack) to analyze the size of your JavaScript bundles and identify large modules and dependencies that might be impacting your application's performance.

- [Package Phobia](https://packagephobia.com/)
- [Bundle Phobia](https://bundlephobia.com/)
