관찰 가능성은 Next.js 앱의 동작과 성능을 이해하고 최적화하는 데 중요합니다.

애플리케이션이 더욱 복잡해짐에 따라 발생할 수 있는 문제를 식별하고 진단하는 것이 점점 더 어려워지고 있습니다. 개발자는 로깅 및 메트릭과 같은 관찰 도구를 활용하여 애플리케이션 동작에 대한 통찰력을 얻고 최적화 영역을 식별할 수 있습니다. 관찰 가능성을 통해 개발자는 문제가 심각한 문제로 발전하기 전에 사전에 해결하고 더 나은 사용자 경험을 제공할 수 있습니다. 따라서 성능을 향상하고 리소스를 최적화하며 사용자 경험을 향상하려면 Next.js 애플리케이션에서 관찰 기능을 사용하는 것이 좋습니다.

앱 계측에는 OpenTelemetry를 사용하는 것이 좋습니다.
이는 코드를 변경하지 않고도 관찰 가능성 공급자를 변경할 수 있도록 앱을 계측하는 플랫폼에 구애받지 않는 방법입니다.
OpenTelemetry 및 작동 방식에 대한 자세한 내용은 [공식 OpenTelemetry 문서](https://opentelemetry.io/docs/)를 읽어보세요.

이 문서에서는 *Span*, *Trace* 또는 *Exporter*와 같은 용어를 사용합니다. 이러한 용어는 모두 [OpenTelemetry Observability Primer](https://opentelemetry.io/docs/concepts/observability-primer/)에서 찾을 수 있습니다.

Next.js는 기본적으로 OpenTelemetry 계측을 지원합니다. 이는 우리가 이미 Next.js 자체를 계측했음을 의미합니다.

## 시작하기

OpenTelemetry는 확장 가능하지만 올바르게 설정하는 것은 상당히 장황할 수 있습니다.
이것이 바로 우리가 빠르게 시작하는 데 도움이 되는 `@vercel/otel` 패키지를 준비한 이유입니다.

### Using `@vercel/otel`

시작하려면 다음 패키지를 설치하세요.

```bash filename="Terminal"
npm install @vercel/otel @opentelemetry/sdk-logs @opentelemetry/api-logs @opentelemetry/instrumentation
```

그런 다음 프로젝트의 [`instrumentation.ts`](instrumentation.mdx)(또는 `.js`) 파일을 만듭니다.**root directory** of the project (or inside `src` folder if using one):

```ts filename="your-project/instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel({ serviceName: 'next-app' })
}
```

```js filename="your-project/instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel({ serviceName: 'next-app' })
}
```

추가 구성 옵션은 [`@vercel/otel` 문서](https://www.npmjs.com/package/@vercel/otel)를 참조하세요.

> **알면 좋은 점**:
>
> - The `instrumentation` 파일은 `app` 또는 `pages` 디렉터리가 아닌 프로젝트 루트에 있어야 합니다. `src` 폴더를 사용하는 경우 파일을 `src` 및 `pages`와 함께 `app` 안에 배치하세요.
> - If you use the [`pageExtensions` 구성 옵션](../api-reference/config/next-config-js/pageExtensions.mdx)을 사용하여 접미사를 추가하는 경우 일치하도록 `instrumentation` 파일 이름도 업데이트해야 합니다.
> - 사용할 수 있는 기본 [with-opentelemetry](https://github.com/vercel/next.js/tree/canary/examples/with-opentelemetry) 예제를 만들었습니다.

### 수동 OpenTelemetry 구성

The `@vercel/otel` 패키지는 다양한 구성 옵션을 제공하며 대부분의 일반적인 사용 사례에 사용됩니다. 그러나 요구 사항에 맞지 않는 경우 OpenTelemetry를 수동으로 구성할 수 있습니다.

먼저 OpenTelemetry 패키지를 설치해야 합니다.

```bash filename="Terminal"
npm install @opentelemetry/sdk-node @opentelemetry/resources @opentelemetry/semantic-conventions @opentelemetry/sdk-trace-node @opentelemetry/exporter-trace-otlp-http
```

이제 `NodeSDK`에서 `instrumentation.ts`을 초기화할 수 있습니다.
`@vercel/otel`과 달리 `NodeSDK`은 Edge 런타임과 호환되지 않으므로 `process.env.NEXT_RUNTIME === 'nodejs'`인 경우에만 가져오는지 확인해야 합니다. 노드를 사용할 때만 조건부로 가져오는 새 파일 `instrumentation.node.ts`을 생성하는 것이 좋습니다.

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation.node.ts')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation.node.js')
  }
}
```

```ts filename="instrumentation.node.ts" switcher
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'
import { resourceFromAttributes } from '@opentelemetry/resources'
import { NodeSDK } from '@opentelemetry/sdk-node'
import { SimpleSpanProcessor } from '@opentelemetry/sdk-trace-node'
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions'

const sdk = new NodeSDK({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: 'next-app',
  }),
  spanProcessor: new SimpleSpanProcessor(new OTLPTraceExporter()),
})
sdk.start()
```

```js filename="instrumentation.node.js" switcher
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'
import { resourceFromAttributes } from '@opentelemetry/resources'
import { NodeSDK } from '@opentelemetry/sdk-node'
import { SimpleSpanProcessor } from '@opentelemetry/sdk-trace-node'
import { ATTR_SERVICE_NAME } from '@opentelemetry/semantic-conventions'

const sdk = new NodeSDK({
  resource: resourceFromAttributes({
    [ATTR_SERVICE_NAME]: 'next-app',
  }),
  spanProcessor: new SimpleSpanProcessor(new OTLPTraceExporter()),
})
sdk.start()
```

이를 수행하는 것은 `@vercel/otel`을 사용하는 것과 동일하지만 `@vercel/otel`에 의해 노출되지 않는 일부 기능을 수정하고 확장하는 것이 가능합니다. Edge 런타임 지원이 필요한 경우 `@vercel/otel`을 사용해야 합니다.

## 계측 테스트

OpenTelemetry 추적을 로컬에서 테스트하려면 호환되는 백엔드가 있는 OpenTelemetry 수집기가 필요합니다.
[OpenTelemetry 개발 환경](https://github.com/vercel/opentelemetry-collector-dev-setup)을 사용하는 것이 좋습니다.

모든 것이 제대로 작동하면 `GET /requested/pathname`라는 레이블이 붙은 루트 서버 범위를 볼 수 있습니다.
해당 특정 추적의 다른 모든 범위는 해당 추적 아래에 중첩됩니다.

Next.js는 기본적으로 내보내는 것보다 더 많은 범위를 추적합니다.
더 많은 범위를 보려면 `NEXT_OTEL_VERBOSE=1`을 설정해야 합니다.

## 배포

### OpenTelemetry 수집기 사용

OpenTelemetry Collector를 사용하여 배포하는 경우 `@vercel/otel`을 사용할 수 있습니다.
Vercel 및 자체 호스팅 시 모두 작동합니다.

#### Vercel에 배포 중

Vercel에서 OpenTelemetry가 기본적으로 작동하는지 확인했습니다.

Follow [Vercel 문서](https://vercel.com/docs/concepts/observability/otel-overview/quickstart)에 따라 프로젝트를 관측 가능성 공급자에 연결하세요.

#### 자체 호스팅

다른 플랫폼에 배포하는 것도 간단합니다. Next.js 앱에서 원격 측정 데이터를 수신하고 처리하려면 자체 OpenTelemetry Collector를 가동해야 합니다.

이렇게 하려면 수집기를 설정하고 Next.js 앱에서 데이터를 수신하도록 구성하는 과정을 안내하는 [OpenTelemetry Collector 시작 가이드](https://opentelemetry.io/docs/collector/getting-started/)를 따르세요.

컬렉터를 실행하고 나면 해당 배포 가이드에 따라 선택한 플랫폼에 Next.js 앱을 배포할 수 있습니다.

### 사용자 정의 내보내기

OpenTelemetry Collector는 필요하지 않습니다. [`@vercel/otel`](#using-vercelotel) 또는 [수동 OpenTelemetry 구성](#manual-opentelemetry-configuration)을 통해 사용자 정의 OpenTelemetry 내보내기 도구를 사용할 수 있습니다.

## 커스텀 스팬

You can add a custom span with [OpenTelemetry API](https://opentelemetry.io/docs/instrumentation/js/instrumentation)를 사용하여 사용자 정의 범위를 추가할 수 있습니다.

```bash filename="Terminal"
npm install @opentelemetry/api
```

다음 예에서는 GitHub 별을 가져오고 사용자 지정 `fetchGithubStars` 범위를 추가하여 가져오기 요청 결과를 추적하는 함수를 보여줍니다.

```ts
import { trace } from '@opentelemetry/api'

export async function fetchGithubStars() {
  return await trace
    .getTracer('nextjs-example')
    .startActiveSpan('fetchGithubStars', async (span) => {
      try {
        return await getValue()
      } finally {
        span.end()
      }
    })
}
```

The `register` 함수는 코드가 새로운 환경에서 실행되기 전에 실행됩니다.
새 범위 생성을 시작할 수 있으며 내보낸 추적에 올바르게 추가되어야 합니다.

## Next.js의 기본 스팬

Next.js는 여러 범위를 자동으로 계측하여 애플리케이션 성능에 대한 유용한 통찰력을 제공합니다.

범위의 속성은 [OpenTelemetry 의미 체계](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/)를 따릅니다. 또한 `next` 네임스페이스 아래에 몇 가지 사용자 정의 속성을 추가합니다.

- `next.span_name` - 스팬 이름이 중복됩니다.
- `next.span_type` - 각 범위 유형에는 고유 식별자가 있습니다.
- `next.route` - 요청의 경로 패턴입니다(예: `/[param]/user`).
- `next.rsc`(true/false) - 요청이 프리페치와 같은 RSC 요청인지 여부입니다.
- `next.page`
  - 앱 라우터에서 사용하는 내부 값입니다.
  - 특수 파일(예: `page.ts`, `layout.ts`, `loading.ts` 등)에 대한 경로로 생각할 수 있습니다.
  - It can be used as a unique identifier only when paired with `next.route`는 `/layout` 및 `/(groupA)/layout.ts`을 모두 식별하는 데 사용할 수 있으므로 `/(groupB)/layout.ts`

### `[http.method] [next.route]`

- `next.span_type`: `BaseServer.handleRequest`

이 범위는 Next.js 애플리케이션으로 들어오는 각 요청의 루트 범위를 나타냅니다. 요청의 HTTP 메서드, 경로, 대상 및 상태 코드를 추적합니다.

속성:

- [공통 HTTP 속성](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#common-attributes)
  - `http.method`
  - `http.status_code`
- [서버 HTTP 속성](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#http-server-semantic-conventions)
  - `http.route`
  - `http.target`
- `next.span_name`
- `next.span_type`
- `next.route`

### `render route (app) [next.route]`

- `next.span_type`: `AppRender.getBodyResult`.

이 범위는 앱 라우터에서 경로를 렌더링하는 프로세스를 나타냅니다.

속성:

- `next.span_name`
- `next.span_type`
- `next.route`

### `fetch [http.method] [http.url]`

- `next.span_type`: `AppRender.fetch`

이 범위는 코드에서 실행된 가져오기 요청을 나타냅니다.

속성:

- [공통 HTTP 속성](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#common-attributes)
  - `http.method`
- [클라이언트 HTTP 속성](https://opentelemetry.io/docs/reference/specification/trace/semantic_conventions/http/#http-client)
  - `http.url`
  - `net.peer.name`
  - `net.peer.port`(지정된 경우에만)
- `next.span_name`
- `next.span_type`

이 범위는 사용자 환경에서 `NEXT_OTEL_FETCH_DISABLED=1`을 설정하여 끌 수 있습니다. 이는 사용자 정의 가져오기 계측 라이브러리를 사용하려는 경우에 유용합니다.

### `executing api route (app) [next.route]`

- `next.span_type`: `AppRouteRouteHandlers.runHandler`.

이 범위는 앱 라우터에서 API 경로 핸들러의 실행을 나타냅니다.

속성:

- `next.span_name`
- `next.span_type`
- `next.route`

### `getServerSideProps [next.route]`

- `next.span_type`: `Render.getServerSideProps`.

이 범위는 특정 경로에 대한 `getServerSideProps`의 실행을 나타냅니다.

속성:

- `next.span_name`
- `next.span_type`
- `next.route`

### `getStaticProps [next.route]`

- `next.span_type`: `Render.getStaticProps`.가 범위는 특정 경로에 대한 의 실행을 나타냅니다.

속성:`getStaticProps` for a specific route.

이 범위는 특정 경로에 대한 문서를 렌더링하는 프로세스를 나타냅니다.

- `next.span_name`
- `next.span_type`
- `next.route`

### `render route (pages) [next.route]`

- `next.span_type`: `Render.renderDocument`.

이 범위는 특정 페이지에 대한 메타데이터를 생성하는 프로세스를 나타냅니다(단일 경로에는 이러한 범위가 여러 개 있을 수 있음).

속성:

- `next.span_name`
- `next.span_type`
- `next.route`

### `generateMetadata [next.page]`

- `next.span_type`: `ResolveMetadata.generateMetadata`.

이 범위는 특정 페이지에 대한 페이지 구성 요소를 확인하는 프로세스를 나타냅니다.

속성:

- `next.span_name`
- `next.span_type`
- `next.page`

### `resolve page components`

- `next.span_type`: `NextNodeServer.findPageComponents`.

이 범위는 레이아웃이나 페이지에 대한 코드 모듈의 로드를 나타냅니다.

속성:

- `next.span_name`
- `next.span_type`
- `next.route`

### `resolve segment modules`

- `next.span_type`: `NextNodeServer.getLayoutOrPageModule`.

이 길이가 0인 범위는 응답에서 첫 번째 바이트가 전송된 시간을 나타냅니다.

Attributes:

- `next.span_name`
- `next.span_type`
- `next.segment`

### `start response`

- `next.span_type`: `NextNodeServer.startResponse`.

This zero-length span represents the time when the first byte has been sent in the response.
