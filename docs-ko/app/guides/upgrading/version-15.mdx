## 14에서 15로 업그레이드

Next.js 버전 15로 업데이트하려면 `upgrade` codemod를 사용할 수 있습니다.

```bash filename="Terminal"
npx @next/codemod@canary upgrade latest
```

수동으로 수행하려면 최신 Next 및 React 버전을 설치하고 있는지 확인하세요.

```bash filename="Terminal"
npm i next@latest react@latest react-dom@latest eslint-config-next@latest
```

> **알아두면 좋은 점:**
>
> - 피어 종속성 경고가 표시되면 `react` 및 `react-dom`을 제안된 버전으로 업데이트하거나 `--force` 또는 `--legacy-peer-deps` 플래그를 사용하여 경고를 무시해야 할 수 있습니다. Next.js 15 및 React 19가 모두 안정적이면 이는 필요하지 않습니다.

## React 19

- The minimum versions of `react` 및 `react-dom`의 최소 버전은 이제 19입니다.
- `useFormState`이 `useActionState`로 대체되었습니다. `useFormState` 후크는 React 19에서 계속 사용할 수 있지만 더 이상 사용되지 않으며 향후 릴리스에서 제거될 예정입니다. `useActionState`이 권장되며 `pending` 상태를 직접 읽는 것과 같은 추가 속성을 포함합니다. [자세히 알아보기](https://react.dev/reference/react/useActionState).
- `useFormStatus`에는 이제 `data`, `method` 및 `action`와 같은 추가 키가 포함됩니다. React 19를 사용하지 않는 경우 `pending` 키만 사용할 수 있습니다. [자세히 알아보기](https://react.dev/reference/react-dom/hooks/useFormStatus).
- Read more in the [React 19 업그레이드 가이드](https://react.dev/blog/2024/04/25/react-19-upgrade-guide)에서 자세한 내용을 읽어보세요.

> **알아두면 좋은 점:** TypeScript를 사용하는 경우 `@types/react` 및 `@types/react-dom`도 최신 버전으로 업그레이드하세요.

## 비동기 요청 API(급격한 변경)

런타임 정보에 의존하는 이전 동기식 동적 API는 이제 **비동기식**입니다.

- [`cookies`](../../api-reference/functions/cookies.mdx)
- [`headers`](../../api-reference/functions/headers.mdx)
- [`draftMode`](../../api-reference/functions/draft-mode.mdx)
- `params`, [`layout.js`](../../api-reference/file-conventions/layout.mdx), [`page.js`](../../api-reference/file-conventions/page.mdx), [`route.js`](../../api-reference/file-conventions/route.mdx), [`default.js`](../../api-reference/file-conventions/default.mdx) 및 [`opengraph-image`](../../api-reference/file-conventions/metadata/opengraph-image.mdx).[`twitter-image`](../../api-reference/file-conventions/metadata/opengraph-image.mdx), [`icon`](../../api-reference/file-conventions/metadata/app-icons.mdx), and [`apple-icon`](../../api-reference/file-conventions/metadata/app-icons.mdx).
- `searchParams` in [`page.js`](../../api-reference/file-conventions/page.mdx)

마이그레이션 부담을 덜기 위해 [codemod를 사용할 수 있습니다](codemods.mdx#150) 프로세스를 자동화하고 API에 일시적으로 동기식으로 액세스할 수 있습니다.

### `cookies`

#### 권장 비동기 사용

```tsx
import { cookies } from 'next/headers'

// Before
const cookieStore = cookies()
const token = cookieStore.get('token')

// After
const cookieStore = await cookies()
const token = cookieStore.get('token')
```

#### 임시 동기 사용

```tsx filename="app/page.tsx" switcher
import { cookies, type UnsafeUnwrappedCookies } from 'next/headers'

// Before
const cookieStore = cookies()
const token = cookieStore.get('token')

// After
const cookieStore = cookies() as unknown as UnsafeUnwrappedCookies
// will log a warning in dev
const token = cookieStore.get('token')
```

```jsx filename="app/page.js" switcher
import { cookies } from 'next/headers'

// Before
const cookieStore = cookies()
const token = cookieStore.get('token')

// After
const cookieStore = cookies()
// will log a warning in dev
```


### `params` 및 `searchParams`

#### 비동기 레이아웃

```tsx filename="app/layout.tsx" switcher

  const { slug } = params
}

export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Params

  const { slug } = params

  const { slug } = await params
}

  children,
  params,
}: {
  children: React.ReactNode
  params: Params
}) {
  const { slug } = await params
}
```

```jsx filename="app/layout.js" switcher
  const { slug } = await params

```

```tsx filename="app/page.tsx" switcher
  const query = searchParams.query

}) {
```

## `runtime` 구성(급격한 변경)

The `runtime` [세그먼트 구성](../../api-reference/file-conventions/route-segment-config.mdx#runtime)은 이전에 `experimental-edge` 외에 `edge` 값을 지원했습니다. 두 구성 모두 동일한 것을 참조하며 옵션을 단순화하기 위해 이제 `experimental-edge`을 사용하면 오류가 발생합니다. 이 문제를 해결하려면 `runtime` 구성을 `edge`로 업데이트하세요. 이 작업을 자동으로 수행하는 데 [codemod](codemods.mdx#app-dir-runtime-config-experimental-edge)를 사용할 수 있습니다.

## `fetch` 요청

[`fetch` 요청](../../api-reference/functions/fetch.mdx)은 더 이상 기본적으로 캐시되지 않습니다.

특정 `fetch` 요청을 캐싱하도록 선택하려면 `cache: 'force-cache'` 옵션을 전달할 수 있습니다.

```js filename="app/layout.js"
export default async function RootLayout() {
  const a = await fetch('https://...') // Not Cached
  const b = await fetch('https://...', { cache: 'force-cache' }) // Cached

  // ...
}
```

레이아웃이나 페이지의 모든 `fetch` 요청을 캐싱하도록 선택하려면 `export const fetchCache = 'default-cache'` [세그먼트 구성 옵션](../../api-reference/file-conventions/route-segment-config.mdx)을 사용할 수 있습니다. 개별 `fetch` 요청이 `cache` 옵션을 지정하는 경우 해당 옵션이 대신 사용됩니다.

```js filename="app/layout.js"
// Since this is the root layout, all fetch requests in the app
// that don't set their own cache option will be cached.
export const fetchCache = 'default-cache'

export default async function RootLayout() {
  const a = await fetch('https://...') // Cached
  const b = await fetch('https://...', { cache: 'no-store' }) // Not cached

  // ...
}
```

## 경로 처리기

`GET` 함수는 더 이상 기본적으로 캐시되지 않습니다. [경로 구성 옵션](../../api-reference/file-conventions/route.mdx)을 사용할 수 있습니다.`GET` methods into caching, you can use a [route config option](../../api-reference/file-conventions/route-segment-config.mdx) such as `export const dynamic = 'force-static'` in your Route Handler file.

```js filename="app/api/route.js"
export const dynamic = 'force-static'

export async function GET() {}
```

## 클라이언트측 라우터 캐시

When navigating between pages via `<Link>` 또는 `useRouter`을 통해 페이지 간을 탐색할 때 [페이지](../../api-reference/file-conventions/page.mdx) 세그먼트가 더 이상 클라이언트 측 라우터 캐시에서 재사용되지 않습니다. 그러나 브라우저의 뒤로 및 앞으로 탐색과 공유 레이아웃에서는 계속 재사용됩니다.

페이지 세그먼트를 캐싱하도록 선택하려면 [`staleTimes`](../../api-reference/config/next-config-js/staleTimes.mdx) 구성 옵션을 사용할 수 있습니다.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    staleTimes: {
      dynamic: 30,
      static: 180,
    },
  },
}

module.exports = nextConfig
```

[레이아웃](../../api-reference/file-conventions/layout.mdx) 및 [로드 상태](../../api-reference/file-conventions/loading.mdx)는 여전히 캐시되어 탐색 시 재사용됩니다.

## `next/font`

내장된 `@next/font` 패키지가 제거되었습니다. 가져오기 이름을 안전하고 자동으로 바꾸는 [`next/font`](../../api-reference/components/font.mdx).[codemod is available](codemods.mdx#built-in-next-font) to safely and automatically rename your imports.

```js filename="app/layout.js"
// Before
import { Inter } from '@next/font/google'

// After
import { Inter } from 'next/font/google'
```

## BundlePagesRouterDependency

`experimental.bundlePagesExternals`는 이제 안정되었으며 이름이 `bundlePagesRouterDependencies`로 변경되었습니다.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Before
  experimental: {
    bundlePagesExternals: true,
  },

  // After
  bundlePagesRouterDependencies: true,
}

module.exports = nextConfig
```

## 서버외부패키지

`experimental.serverComponentsExternalPackages`은 이제 안정되었으며 이름이 `serverExternalPackages`로 변경되었습니다.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  // Before
  experimental: {
    serverComponentsExternalPackages: ['package-name'],
  },

  // After
  serverExternalPackages: ['package-name'],
}

module.exports = nextConfig
```

## `NextRequest` Geolocation

Vercel를 사용하는 경우 대신 `geo` 및 `ip` 함수를 사용할 수 있습니다.`NextRequest` have been removed as these values are provided by your hosting provider. A [codemod](codemods.mdx#150) is available to automate this migration.

If you are using Vercel, you can alternatively use the `geolocation` and `ipAddress` functions from [`@vercel/functions`](https://vercel.com/docs/functions/vercel-functions-package) instead:

```ts filename="middleware.ts"
import { geolocation } from '@vercel/functions'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  const { city } = geolocation(request)

  // ...
}
```

```ts filename="middleware.ts"
import { ipAddress } from '@vercel/functions'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  const ip = ipAddress(request)

  // ...
}
```
