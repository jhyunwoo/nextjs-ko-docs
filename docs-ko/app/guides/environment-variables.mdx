Next.js에는 환경 변수 지원이 기본으로 내장되어 있어 다음을 수행할 수 있습니다:

- [`.env`를 사용해 환경 변수 로드하기](#loading-environment-variables)
- [`NEXT_PUBLIC_` 접두사를 붙여 브라우저용 환경 변수 번들링하기](#bundling-environment-variables-for-the-browser)

> **경고:** 기본 `create-next-app` 템플릿은 모든 `.env` 파일이 `.gitignore`에 추가되도록 설정합니다. 이러한 파일을 저장소에 커밋하고 싶은 경우는 거의 없습니다.

<a id="loading-environment-variables"></a>

## 환경 변수 로드

Next.js는 `.env*` 파일에서 `process.env`로 환경 변수를 로드하는 기능을 기본으로 지원합니다.

```txt filename=".env"
DB_HOST=localhost
DB_USER=myuser
DB_PASS=mypassword
```

> **참고:** Next.js는 `.env*` 파일 안의 여러 줄 변수도 지원합니다:
>
> ```bash
> # .env
>
> # you can write with line breaks
> PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
> ...
> Kh9NV...
> ...
> -----END DSA PRIVATE KEY-----"
>
> # or with `\n` inside double quotes
> PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nKh9NV...\n-----END DSA PRIVATE KEY-----\n"
> ```

> **참고:** `/src` 폴더를 사용하는 경우, Next.js는 .env 파일을 부모 폴더에서만 로드하며 `/src` 폴더에서는 로드하지 않습니다.
> 이렇게 하면 `process.env.DB_HOST`, `process.env.DB_USER`, `process.env.DB_PASS`가 Node.js 환경에 자동으로 로드되어 [경로 처리기](../api-reference/file-conventions/route.mdx)에서 사용할 수 있습니다.

예를 들면 다음과 같습니다:

```js filename="app/api/route.js"
export async function GET() {
  const db = await myDB.connect({
    host: process.env.DB_HOST,
    username: process.env.DB_USER,
    password: process.env.DB_PASS,
  })
  // ...
}
```

### `@next/env`로 환경 변수 로드하기

ORM이나 테스트 러너용 루트 설정 파일처럼 Next.js 런타임 밖에서 환경 변수를 로드해야 한다면 `@next/env` 패키지를 사용할 수 있습니다.

이 패키지는 Next.js가 `.env*` 파일에서 환경 변수를 로드할 때 내부적으로 사용합니다.

사용하려면 패키지를 설치한 다음 `loadEnvConfig` 함수를 사용해 환경 변수를 로드하세요:

```bash
npm install @next/env
```

```tsx filename="envConfig.ts" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

```jsx filename="envConfig.js" switcher
import { loadEnvConfig } from '@next/env'

const projectDir = process.cwd()
loadEnvConfig(projectDir)
```

그런 다음 필요한 위치에서 구성을 가져와 사용할 수 있습니다. 예를 들면 다음과 같습니다:

```tsx filename="orm.config.ts" switcher
import './envConfig.ts'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL!,
  },
})
```

```jsx filename="orm.config.js" switcher
import './envConfig.js'

export default defineConfig({
  dbCredentials: {
    connectionString: process.env.DATABASE_URL,
  },
})
```

### 다른 변수 참조하기

Next.js는 `$`를 사용해 다른 변수를 참조하는 변수(예: `$VARIABLE`)를 `.env*` 파일 안에서 자동으로 확장합니다. 이를 통해 다른 비밀 값을 참조할 수 있습니다. 예를 들면 다음과 같습니다:

```txt filename=".env"
TWITTER_USER=nextjs
TWITTER_URL=https://x.com/$TWITTER_USER
```

위 예시에서 `process.env.TWITTER_URL`은 `https://x.com/nextjs`로 설정됩니다.

> **알아두면 좋은 점:** 실제 값에 `$`가 들어간 변수를 사용해야 한다면 `\$`처럼 이스케이프해야 합니다.

## 브라우저용 환경 변수 번들링

`NEXT_PUBLIC_`가 붙지 않은 환경 변수는 Node.js 환경에서만 사용할 수 있으므로 브라우저에서는 접근할 수 없습니다(클라이언트는 서로 다른 _environment_ 에서 실행됩니다).

환경 변수 값을 브라우저에서 사용할 수 있게 하려면, Next.js는 클라이언트에 전달되는 js 번들 안에 빌드 시점의 값을 "인라인"할 수 있습니다. 이 과정에서 `process.env.[variable]`에 대한 모든 참조는 하드코딩된 값으로 대체됩니다. 이를 위해서는 변수 이름에 `NEXT_PUBLIC_` 접두사만 붙이면 됩니다. 예를 들면 다음과 같습니다:

```txt filename="Terminal"
NEXT_PUBLIC_ANALYTICS_ID=abcdefghijk
```

이렇게 하면 Next.js는 Node.js 환경에서 `process.env.NEXT_PUBLIC_ANALYTICS_ID`를 `next build`를 실행하는 환경의 값으로 모두 대체하므로, 코드 어디에서나 이를 사용할 수 있습니다. 이 값은 브라우저로 전송되는 모든 JavaScript 안에 인라인됩니다.

> **참고:** 앱이 빌드된 뒤에는 더 이상 이러한 환경 변수의 변경 사항에 반응하지 않습니다. 예를 들어 Heroku 파이프라인으로 한 환경에서 빌드한 slug를 다른 환경으로 승격하거나, 하나의 Docker 이미지를 빌드해 여러 환경에 배포하는 경우 모든 `NEXT_PUBLIC_` 변수는 빌드 시점에 평가된 값으로 고정됩니다. 따라서 이러한 값은 프로젝트를 빌드할 때 알맞게 설정되어 있어야 합니다. 런타임 환경 값에 접근해야 한다면, 클라이언트에 이를 제공하는 자체 API를 설정해야 합니다(필요할 때 요청하거나 초기화 중에 제공하는 방식 모두 가능합니다).

```js filename="pages/index.js"
import setupAnalyticsService from '../lib/my-analytics-service'

// 'NEXT_PUBLIC_ANALYTICS_ID' can be used here as it's prefixed by 'NEXT_PUBLIC_'.
// It will be transformed at build time to `setupAnalyticsService('abcdefghijk')`.
setupAnalyticsService(process.env.NEXT_PUBLIC_ANALYTICS_ID)

function HomePage() {
  return <h1>Hello World</h1>
}

export default HomePage
```

동적 조회는 다음과 같이 _인라인되지 않습니다_:

```js
// This will NOT be inlined, because it uses a variable
const varName = 'NEXT_PUBLIC_ANALYTICS_ID'
setupAnalyticsService(process.env[varName])

// This will NOT be inlined, because it uses a variable
const env = process.env
setupAnalyticsService(env.NEXT_PUBLIC_ANALYTICS_ID)
```

### 런타임 환경 변수

Next.js는 빌드 타임 환경 변수와 런타임 환경 변수를 모두 지원할 수 있습니다.

**기본적으로 환경 변수는 서버에서만 사용할 수 있습니다**. 환경 변수를 브라우저에 노출하려면 `NEXT_PUBLIC_` 접두사를 붙여야 합니다. 하지만 이러한 공개 환경 변수는 `next build` 중 JavaScript 번들 안에 인라인됩니다.

서버에서 동적 렌더링 중에는 환경 변수를 안전하게 읽을 수 있습니다:

```tsx filename="app/page.ts" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies, headers, and other Dynamic APIs
  // will also opt into dynamic rendering, meaning
  // this env variable is evaluated at runtime
  const value = process.env.MY_VALUE
  // ...
}
```

```jsx filename="app/page.js" switcher
import { connection } from 'next/server'

export default async function Component() {
  await connection()
  // cookies, headers, and other Dynamic APIs
  // will also opt into dynamic rendering, meaning
  // this env variable is evaluated at runtime
  const value = process.env.MY_VALUE
  // ...
}
```

이렇게 하면 서로 다른 값을 가진 여러 환경으로 승격할 수 있는 단일 Docker 이미지를 사용할 수 있습니다.

**알아두면 좋은 점:**

- 서버 시작 시 [`register` 함수](instrumentation.mdx)를 사용해 코드를 실행할 수 있습니다.

## 테스트 환경 변수

`development` 및 `production` 환경 외에도 세 번째 옵션인 `test`가 있습니다. 개발 또는 프로덕션 환경의 기본값을 설정하듯이, `.env.test` 파일을 `testing` 환경용으로 사용해 같은 작업을 수행할 수 있습니다(앞의 두 경우만큼 흔하지는 않지만 가능합니다). Next.js는 `.env.development`나 `.env.production`의 환경 변수를 `testing` 환경에서는 로드하지 않습니다.

이는 `jest`나 `cypress` 같은 도구로 테스트를 실행할 때, 테스트 전용 환경 변수를 설정해야 하는 경우 유용합니다. `NODE_ENV`가 `test`로 설정되어 있으면 테스트 기본값이 로드되지만, 보통은 테스트 도구가 이를 처리하므로 직접 설정할 필요는 없습니다.

기억해야 할 작은 차이점이 하나 있습니다. `test` 환경은 `development`, `production`과 달리 `.env.local`을 로드하지 않습니다. 테스트는 누구에게나 동일한 결과를 내야 하므로, 각 테스트 실행은 기본 설정을 덮어쓰는 용도의 `.env.local`을 무시하고 동일한 환경 변수 기본값을 사용합니다.

> **알아두면 좋은 점:** 기본 환경 변수와 마찬가지로 `.env.test` 파일은 저장소에 포함되어야 하지만, `.env.test.local`은 포함되면 안 됩니다. `.env*.local`은 `.gitignore`를 통해 무시되도록 설계되었기 때문입니다.

단위 테스트를 실행하는 동안에는 `loadEnvConfig` 함수를 `@next/env` 패키지에서 사용해 Next.js와 동일한 방식으로 환경 변수를 로드할 수 있습니다.

```js
// The below can be used in a Jest global setup file or similar for your testing set-up
import { loadEnvConfig } from '@next/env'

export default async () => {
  const projectDir = process.cwd()
  loadEnvConfig(projectDir)
}
```

## 환경 변수 로드 순서

환경 변수는 다음 위치를 아래 순서대로 확인하며, 변수를 찾는 즉시 탐색을 멈춥니다.

1. `process.env`
1. `.env.$(NODE_ENV).local`
1. `.env.local` (`NODE_ENV`가 `test`일 때는 확인하지 않음.)
1. `.env.$(NODE_ENV)`
1. `.env`

예를 들어 `NODE_ENV`가 `development`이고 변수를 `.env.development.local`과 `.env` 모두에 정의했다면, `.env.development.local`의 값이 사용됩니다.

> **알아두면 좋은 점:** `NODE_ENV`에 허용되는 값은 `production`, `development`, `test`입니다.

## 알아두면 좋은 점

- [`/src` 디렉터리](../api-reference/file-conventions/src-folder.mdx)를 사용하는 경우, `.env.*` 파일은 프로젝트 루트에 그대로 두어야 합니다.
- 환경 변수 `NODE_ENV`가 할당되지 않으면, Next.js는 `development`를 `next dev` 명령 실행 시 자동으로 할당하고 그 외 모든 명령에서는 `production`을 할당합니다.
