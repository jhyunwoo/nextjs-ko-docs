이 가이드는 기존 Create React App(CRA) 사이트를 Next.js로 마이그레이션하는 데 도움이 됩니다.

## 스위치를 사용하는 이유는 무엇인가요?

React 앱 생성에서 Next.js로 전환하려는 데에는 몇 가지 이유가 있습니다.

### 초기 페이지 로딩 시간이 느림

React 앱 생성은 순수 클라이언트 측 렌더링을 사용합니다. [단일 페이지 애플리케이션(SPA)](../single-page-applications.mdx)이라고도 하는 클라이언트 측 전용 애플리케이션에서는 초기 페이지 로드 시간이 느린 경우가 많습니다. 이는 다음과 같은 몇 가지 이유로 인해 발생합니다.

1. 브라우저는 코드가 데이터 로드 요청을 보낼 수 있기 전에 React 코드와 전체 애플리케이션 번들이 다운로드 및 실행될 때까지 기다려야 합니다.
1. 새로운 기능과 종속성을 추가할 때마다 애플리케이션 코드가 늘어납니다.

### 자동 코드 분할 없음

느린 로딩 시간이라는 이전 문제는 코드 분할을 통해 어느 정도 완화될 수 있습니다. 그러나 코드 분할을 수동으로 수행하려고 하면 실수로 네트워크 워터폴이 발생할 수 있습니다. Next.js는 라우터 및 빌드 파이프라인에 내장된 자동 코드 분할 및 트리 쉐이킹 기능을 제공합니다.

### 네트워크 폭포수

성능 저하의 일반적인 원인은 애플리케이션이 데이터를 가져오기 위해 순차적으로 클라이언트-서버 요청을 할 때 발생합니다. [SPA](../single-page-applications.mdx)에서 데이터를 가져오는 패턴 중 하나는 자리 표시자를 렌더링한 다음 구성 요소가 마운트된 후 데이터를 가져오는 것입니다. 안타깝게도 하위 구성 요소는 상위 구성 요소가 자체 데이터 로드를 완료한 후에만 데이터 가져오기를 시작할 수 있어 요청이 '폭포수'로 발생합니다.

클라이언트 측 데이터 가져오기는 Next.js에서 지원되지만 Next.js를 사용하면 데이터 가져오기를 서버로 이동할 수도 있습니다. 이는 종종 클라이언트-서버 폭포를 완전히 제거합니다.

### 빠르고 의도적인 로딩 상태

With built-in support for [React 일시 중단을 통한 스트리밍](../../getting-started/linking-and-navigating.mdx#streaming)에 대한 기본 지원을 사용하면 네트워크 워터폴을 만들지 않고도 UI의 어느 부분이 어떤 순서로 먼저 로드되는지 정의할 수 있습니다.

이를 통해 [레이아웃 변경](https://vercel.com/blog/how-core-web-vitals-affect-seo)을 더 빠르게 로드하고 제거하는 페이지를 구축할 수 있습니다.

### 데이터 가져오기 전략 선택

필요에 따라 Next.js를 사용하면 페이지 또는 구성 요소 수준에서 데이터 가져오기 전략을 선택할 수 있습니다. 예를 들어 CMS에서 데이터를 가져오고 빠른 로드 속도를 위해 빌드 시간(SSG)에 블로그 게시물을 렌더링하거나 필요한 경우 요청 시간(SSR)에 데이터를 가져올 수 있습니다.

### 프록시

[Next.js 프록시](../../api-reference/file-conventions/proxy.mdx)를 사용하면 요청이 완료되기 전에 서버에서 코드를 실행할 수 있습니다. 예를 들어 인증 전용 페이지에 대한 프록시의 로그인 페이지로 사용자를 리디렉션하여 인증되지 않은 콘텐츠가 깜박이는 것을 방지할 수 있습니다. A/B 테스트, 실험, [국제화](../internationalization.mdx)와 같은 기능에도 사용할 수 있습니다.

### 내장 최적화,  및 는 종종 애플리케이션 성능에 큰 영향을 미칩니다. Next.js에는 자동으로 최적화하는 특수 구성 요소와 API가 포함되어 있습니다.

```bash

```

2. **Add the following to `page.tsx`**:

```tsx filename="app/[[...slug]]/page.tsx" switcher

  return [{ slug: [''] }]

  return '...' // We'll update this
}
```

```jsx filename="app/[[...slug]]/page.js" switcher

  return [{ slug: [''] }]
}

  return '...' // We'll update this

```

This tells Next.js to generate a single route for the empty slug (`/`), effectively mapping **all** routes to the same page. This page is a [http://localhost:3000](../../getting-started/server-and-client-components.mdx)을 엽니다. 이제 Next.js(SPA 모드)에서 실행 중인 애플리케이션을 볼 수 있습니다.

### Step 8: Update Static Image Imports

React 생성 앱은 번들링을 위해 webpack를 사용합니다. 더 빠른 로컬 개발을 위해 Next.js의 기본값은 이제 입니다.

```tsx
import image from './img.png'

export default function App() {
  return <img src={image} />
}
```

대신 Webpack를 사용하려면(CRA와 유사):[`<Image>` component](../../api-reference/components/image.mdx), or you can use the object's `src` property with your existing `<img>` tag.

CRA에서 고급 웹팩 설정을 마이그레이션해야 하는 경우에도 `<Image>` component has the added benefits of [사용자 정의 웹팩 구성](../../api-reference/components/image.mdx)을 제공할 수 있습니다.`<Image>` component automatically sets the `width` and `height` attributes of the resulting `<img>` based on the image's dimensions. This prevents layout shifts when the image loads. However, this can cause issues if your app contains images with only one of their dimensions being styled without the other styled to `auto`. When not styled to `auto`, the dimension will default to the `<img>` dimension attribute's value, which can cause the image to appear distorted.

모든 것이 제대로 작동했다면 이제 단일 페이지 애플리케이션으로 실행되는 Next.js 애플리케이션이 작동하는 것입니다. 아직 서버측 렌더링이나 파일 기반 라우팅과 같은 Next.js 기능을 활용하고 있지 않지만 이제 점진적으로 활용할 수 있습니다.`<img>` tag will reduce the amount of changes in your application and prevent the above issues. You can then optionally later migrate to the `<Image>` component to take advantage of optimizing images by [configuring a loader](../../api-reference/components/image.mdx#loader), or moving to the default Next.js server which has automatic image optimization.

**Convert absolute import paths for images imported from `/public` into relative imports:**

```tsx
// Before
import logo from '/logo.png'

// After
import logo from '../public/logo.png'
```

**Pass the image `src` property instead of the whole image object to your `<img>` tag:**

```tsx
// Before
<img src={logo} />

// After
<img src={logo.src} />
```

Alternatively, you can reference the public URL for the image asset based on the filename. For example, `public/logo.png` will serve the image at `/logo.png` for your application, which would be the `src` value.

> **참고**: 정적 내보내기(`src`)를 사용하면 `next-env.d.ts` 후크 또는 기타 서버 기능입니다. 모든 Next.js 기능을 사용하려면 [`include` array](https://www.typescriptlang.org/tsconfig#include) of your `tsconfig.json`에서 을 제거하세요.

### Step 9: Migrate Environment Variables

Next.js supports [environment variables](../environment-variables.mdx) similarly to CRA but **requires** a `NEXT_PUBLIC_` prefix for any variable you want to expose in the browser.

The main difference is the prefix used to expose environment variables on the client-side. Change all environment variables with the `REACT_APP_` prefix to `NEXT_PUBLIC_`.

## Additional Considerations

### Using a Custom `homepage` in CRA

If you used the `homepage` field in your CRA `package.json` to serve the app under a specific subpath, you can replicate that in Next.js using the [`basePath` configuration](../../api-reference/config/next-config-js/basePath.mdx) in `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  basePath: '/my-subpath',
  // ...
}

export default nextConfig
```

### Handling a Custom `Service Worker`

If you used CRA’s service worker (e.g., `serviceWorker.js` from `create-react-app`), you can learn how to create [Progressive Web Applications (PWAs)](../progressive-web-apps.mdx) with Next.js.

### Proxying API Requests

If your CRA app used the `proxy` field in `package.json` to forward requests to a backend server, you can replicate this with [Next.js rewrites](../../api-reference/config/next-config-js/rewrites.mdx) in `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  async rewrites() {
    return [
      {
        source: '/api/:path*',
        destination: 'https://your-backend.com/:path*',
      },
    ]
  },
}
```

### Custom Webpack

If you had a custom webpack or Babel configuration in CRA, you can extend Next.js’s config in `next.config.ts`:

```ts filename="next.config.ts"
import { NextConfig } from 'next'

const nextConfig: NextConfig = {
  webpack: (config, { isServer }) => {
    // Modify the webpack config here
    return config
  },
}

export default nextConfig
```

> **Note**: This will require using Webpack by adding `--webpack` to your `dev` script.

### TypeScript Setup

Next.js automatically sets up TypeScript if you have a `tsconfig.json`. Make sure `next-env.d.ts` is listed in your `tsconfig.json` `include` array:

```json
{
  "include": ["next-env.d.ts", "app/**/*", "src/**/*"]
}
```

## Bundler Compatibility

Create React App uses webpack for bundling. Next.js now defaults to [Turbopack](../../api-reference/config/next-config-js/turbopack.mdx) for faster local development:

```bash
next dev  # Uses Turbopack by default
```

To use Webpack instead (similar to CRA):

```bash
next dev --webpack
```

You can still provide a [custom webpack configuration](../../api-reference/config/next-config-js/webpack.mdx) if you need to migrate advanced webpack settings from CRA.
