`useSearchParams`은 현재 URL의 **쿼리 문자열**을 읽을 수 있는 **클라이언트 구성 요소** 후크입니다.

`useSearchParams`는 **읽기 전용** 버전을 반환합니다.[`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams) interface.

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // URL -> `/dashboard?search=my-project`
  // `search` -> 'my-project'
  return <>Search: {search}</>
}
```

## 매개변수

```tsx
const searchParams = useSearchParams()
```

`useSearchParams`은 매개변수를 사용하지 않습니다.

## 반품

`useSearchParams`은 URL의 쿼리 문자열을 읽기 위한 유틸리티 메소드를 포함하는 **읽기 전용** 버전을 반환합니다.[`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams) interface, which includes utility methods for reading the URL's query string:

- [`URLSearchParams.get()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/get): 검색 매개변수와 연관된 첫 번째 값을 반환합니다. 예를 들면:

  | URL | `searchParams.get("a")` |
  | ------- | ------------------------------------------------------------------------------------- |
  | `/dashboard?a=1` | `'1'` |
  | `/dashboard?a=` | `''` |
  | `/dashboard?b=3` | `null` |
  | `/dashboard?a=1&a=2` | `'1'` *- [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll)를 사용하여 모든 값을 가져옵니다* |

- [`URLSearchParams.has()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/has): 주어진 매개변수가 존재하는지 나타내는 부울 값을 반환합니다. 예를 들면:

  | URL | `searchParams.has("a")` |
  | ---------------- | ---------- |
  | `/dashboard?a=1` | `true` |
  | `/dashboard?b=3` | `false` |

- Learn more about other **읽기 전용** 방법에 대해 자세히 알아보세요. [`URLSearchParams`](https://developer.mozilla.org/docs/Web/API/URLSearchParams), [`getAll()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/getAll), [`keys()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/keys) 및 [`values()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/values).> [`entries()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/entries), [`forEach()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/forEach), and [`toString()`](https://developer.mozilla.org/docs/Web/API/URLSearchParams/toString).:

> **Good to know**:
>
> - `useSearchParams`은 [클라이언트 구성 요소](../../getting-started/server-and-client-components.mdx) 후크이며 **지원되지 않습니다**.[Server Components](../../getting-started/server-and-client-components.mdx) to prevent stale values during [partial rendering](../../getting-started/linking-and-navigating.mdx#client-side-transitions).
> - 검색 매개변수를 기반으로 서버 구성 요소에서 데이터를 가져오려는 경우 해당 페이지의 [`searchParams` prop](../file-conventions/page.mdx#searchparams-optional)을 읽는 것이 더 나은 옵션인 경우가 많습니다. 그런 다음 해당 페이지 내의 모든 구성 요소(서버 또는 클라이언트)에 소품을 통해 이를 전달할 수 있습니다.
> - 애플리케이션에 `/pages` 디렉터리가 포함된 경우 `useSearchParams`은 `ReadonlyURLSearchParams | null`을 반환합니다. `null` 값은 `getServerSideProps`

## 행동

### 정적 렌더링

경로가 [정적으로 렌더링](../../guides/caching.mdx#static-rendering)된 경우 `useSearchParams`을 호출하면 클라이언트 구성 요소 트리가 가장 가까운 [`Suspense` 경계](../file-conventions/loading.mdx#examples)까지 클라이언트 측에서 렌더링됩니다.

이를 통해 `useSearchParams`를 사용하는 동적 부분이 클라이언트 측에서 렌더링되는 동안 경로의 일부가 정적으로 렌더링될 수 있습니다.

We recommend wrapping the Client Component that uses `useSearchParams` 경계에서 `<Suspense/>`을 사용하는 클라이언트 구성 요소를 래핑하는 것이 좋습니다. 이를 통해 상위의 클라이언트 구성 요소를 정적으로 렌더링하고 초기 HTML의 일부로 전송할 수 있습니다. [예](use-search-params.mdx#static-rendering).

예를 들면:

```tsx filename="app/dashboard/search-bar.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // This will not be logged on the server when using static rendering
  console.log(search)

  return <>Search: {search}</>
}
```

```jsx filename="app/dashboard/search-bar.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function SearchBar() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  // This will not be logged on the server when using static rendering
  console.log(search)

  return <>Search: {search}</>
}
```

```tsx filename="app/dashboard/page.tsx" switcher
import { Suspense } from 'react'
import SearchBar from './search-bar'

// This component passed as a fallback to the Suspense boundary
// will be rendered in place of the search bar in the initial HTML.
// When the value is available during React hydration the fallback
// will be replaced with the `<SearchBar>` component.
function SearchBarFallback() {
  return <>placeholder</>
}

export default function Page() {
  return (
    <>
      <nav>
        <Suspense fallback={<SearchBarFallback />}>
          <SearchBar />
        </Suspense>
      </nav>
      <h1>Dashboard</h1>
    </>
  )
}
```

> **알면 좋은 점**:
>
> - 개발 중에는 경로가 주문형으로 렌더링되므로 `useSearchParams`이 일시 중지되지 않으며 `Suspense` 없이도 작동하는 것처럼 보일 수 있습니다.
> - 프로덕션 빌드 중에 클라이언트 구성 요소에서 [정적 페이지](../../guides/caching.mdx#static-rendering)는 `useSearchParams` 경계로 래핑되어야 합니다. 그렇지 않으면 `Suspense` boundary, otherwise the build fails with the [useSearchParams가 있는 일시 중지 경계 누락](https://nextjs.org/docs/messages/missing-suspense-with-csr-bailout) 오류로 인해 빌드가 실패합니다.
> - 경로를 동적으로 렌더링하려는 경우 먼저 서버 구성 요소에서 [`connection`](connection.mdx) 함수를 사용하여 들어오는 요청을 기다리는 것이 좋습니다. 그러면 사전 렌더링에서 아래의 모든 항목이 제외됩니다. [동적 렌더링 가이드](../../guides/caching.mdx#dynamic-rendering)에서 경로를 동적으로 만드는 방법을 알아보세요.
> - 이미 서버 구성 요소 페이지에 있는 경우 [`searchParams` 소품](../file-conventions/page.mdx#searchparams-optional)을 사용하고 값을 클라이언트 구성 요소에 전달하는 것을 고려하세요.
> - 페이지 [`searchParams` 소품](../file-conventions/page.mdx#searchparams-optional)을 클라이언트 구성 요소에 직접 전달하고 React의 `use()`로 래핑을 풀 수도 있습니다. 일시 중지되지만 클라이언트 구성 요소는 `Suspense` 경계로 래핑되어야 합니다.

### 동적 렌더링

경로가 [동적으로 렌더링](../../guides/caching.mdx#dynamic-rendering)되면 클라이언트 구성 요소의 초기 서버 렌더링 중에 서버에서 `useSearchParams`을 사용할 수 있습니다.예를 들면:

For example:(서버 구성 요소)의 검색 매개변수에 액세스하려면  소품을 사용하세요.

  // and on the client on subsequent navigations.

}

> **Good to know**:
>
> - Previously, setting `export const dynamic = 'force-dynamic'` on the page was used to force dynamic rendering. Prefer using [`connection()`](connection.mdx) instead, as it semantically ties dynamic rendering to the incoming request.

### Server Components

#### Pages

| 버전 | 변경사항 |[Pages](../file-conventions/page.mdx) (Server Components), use the [`searchParams`](../file-conventions/page.mdx#searchparams-optional) prop.

#### Layouts

| --------- | ---------------- |
| [Layouts](../file-conventions/layout.mdx) (Server Components) **do not** receive the `searchParams` | [not re-rendered during navigation](../../getting-started/linking-and-navigating.mdx#client-side-transitions) which could lead to stale `searchParams`이 도입되었습니다. |[detailed explanation](../file-conventions/layout.mdx#query-params).

Instead, use the Page [`searchParams`](../file-conventions/page.mdx) prop or the [`useSearchParams`](use-search-params.mdx) hook in a Client Component, which is re-rendered on the client with the latest `searchParams`.

## Examples

### Updating `searchParams`

You can use [`useRouter`](use-router.mdx) or [`Link`](../components/link.mdx) to set new `searchParams`. After a navigation is performed, the current [`page.js`](../file-conventions/page.mdx) will receive an updated [`searchParams` prop](../file-conventions/page.mdx#searchparams-optional).

```tsx filename="app/example-client-component.tsx" switcher
'use client'

export default function ExampleClientComponent() {
  const router = useRouter()
  const pathname = usePathname()
  const searchParams = useSearchParams()

  // Get a new searchParams string by merging the current
  // searchParams with a provided key/value pair
  const createQueryString = useCallback(
    (name: string, value: string) => {
      const params = new URLSearchParams(searchParams.toString())
      params.set(name, value)

      return params.toString()
    },
    [searchParams]
  )

  return (
    <>
      <p>Sort By</p>

      {/* using useRouter */}
      <button
        onClick={() => {
          // <pathname>?sort=asc
          router.push(pathname + '?' + createQueryString('sort', 'asc'))
        }}
      >
        ASC
      </button>

      {/* using <Link> */}
      <Link
        href={
          // <pathname>?sort=desc
          pathname + '?' + createQueryString('sort', 'desc')
        }
      >
        DESC
      </Link>
    </>
  )
}
```
