The `redirect` 기능을 사용하면 사용자를 다른 URL로 리디렉션할 수 있습니다. `redirect`은 [서버 및 클라이언트 구성 요소](../../getting-started/server-and-client-components.mdx), [경로 처리기](../file-conventions/route.mdx) 및 [서버 기능](../../getting-started/updating-data.mdx)에서 렌더링하는 동안 사용할 수 있습니다.

When used in a [스트리밍 컨텍스트](../../getting-started/linking-and-navigating.mdx#streaming)에서 사용될 때 메타 태그를 삽입하여 클라이언트 측에서 리디렉션을 내보냅니다. 서버 작업에 사용되면 호출자에게 303 HTTP 리디렉션 응답을 제공합니다. 그렇지 않으면 호출자에게 307 HTTP 리디렉션 응답을 제공합니다.

리소스가 없으면 [`notFound` 함수](not-found.mdx)를 대신 사용할 수 있습니다.

## 참조

### 매개변수

The `redirect` 함수는 두 가지 인수를 허용합니다.

```js
redirect(path, type)
```

| 매개변수 | 유형 | 설명 |`path`    | `string`                                                      | The URL to redirect to. Can be a relative or absolute path. |`type`    | `'replace'` (default) or `'push'` (default in Server Actions) | The type of redirect to perform.                            |

| `redirect`    | `push` (default) or [Server Actions](../../getting-started/updating-data.mdx) and `replace` (default in Server Actions) | The type of redirect to perform.                            |`type` parameter.

| --------- | ------------------------------------------------ | ---------------------------------------------- |`RedirectType` object contains the available options for the `type` parameter.

```ts
import { redirect, RedirectType } from 'next/navigation'

redirect('/redirect-to', RedirectType.replace)
// or
redirect('/redirect-to', RedirectType.push)
```

The `type` 매개변수는 서버 구성요소에서 사용될 때 아무런 효과가 없습니다.

### 반품

`redirect`은 값을 반환하지 않습니다.

## 행동

- 서버 작업 및 경로 처리기에서 리디렉션은 **외부**에서 호출되어야 합니다.`try` block when using `try/catch` statements.
- 307(임시) 대신 308(영구) HTTP 리디렉션을 반환하려는 경우 [`permanentRedirect` 함수](permanentRedirect.mdx)를 대신 사용할 수 있습니다.
- `redirect`은 오류를 발생시키므로 **외부**에서 호출해야 합니다.`try` block when using `try/catch` statements.
- `redirect`은 렌더링 프로세스 중에 클라이언트 구성 요소에서 호출할 수 있지만 이벤트 핸들러에서는 호출할 수 없습니다. 대신 [`useRouter` 후크](use-router.mdx)를 사용할 수 있습니다.
- `redirect`은 절대 URL도 허용하며 외부 링크로 리디렉션하는 데 사용할 수 있습니다.
- 렌더링 프로세스 전에 리디렉션하려면 [`next.config.js`](../../guides/redirecting.mdx#redirects-in-nextconfigjs) 또는 [프록시](../../guides/redirecting.mdx#nextresponseredirect-in-proxy)를 사용하세요.

## 예

### 서버 구성요소 함수를 호출하면  오류가 발생하고 오류가 발생한 경로 세그먼트의 렌더링이 종료됩니다.

Invoking the `redirect()`은 클라이언트 구성 요소에서 직접 사용할 수 있습니다.`NEXT_REDIRECT` error and terminates rendering of the route segment in which it was thrown.

```tsx filename="app/team/[id]/page.tsx" switcher
import { redirect } from 'next/navigation'

async function fetchTeam(id: string) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const team = await fetchTeam(id)

  if (!team) {
    redirect('/login')
  }

  // ...
}
```

```jsx filename="app/team/[id]/page.js" switcher
import { redirect } from 'next/navigation'

async function fetchTeam(id) {
  const res = await fetch('https://...')
  if (!res.ok) return undefined
  return res.json()
}

export default async function Profile({ params }) {
  const { id } = await params
  const team = await fetchTeam(id)

  if (!team) {
    redirect('/login')
  }

  // ...
}
```

> **알아두면 좋은 정보**: 서버 측 렌더링(SSR) 중 초기 페이지 로드 시 클라이언트 구성 요소에서 `redirect`을 사용하면 서버 측 리디렉션이 수행됩니다.`return redirect()` as it uses the TypeScript [`never`](https://www.typescriptlang.org/docs/handbook/2/functions.html#never) type.

### Client Component에서 307와 308를 사용하는 이유는 무엇인가요?

`redirect`을 사용할 때 사용되는 상태 코드는 임시 리디렉션의 경우 이고 영구 리디렉션의 경우 입니다. 전통적으로 은 임시 리디렉션에 사용되었고 은 영구 리디렉션에 사용되었지만 많은 브라우저는 원본 요청 방법에 관계없이 를 사용할 때 리디렉션 요청 방법을 에서  요청으로 변경했습니다.

```tsx filename="components/client-redirect.tsx" switcher
'use client'

import { redirect, usePathname } from 'next/navigation'

export function ClientRedirect() {
  const pathname = usePathname()

  if (pathname.startsWith('/admin') && !pathname.includes('/login')) {
    redirect('/admin/login')
  }

  return <div>Login Page</div>
}
```

```jsx filename="components/client-redirect.jsx" switcher
'use client'

import { redirect, usePathname } from 'next/navigation'

export function ClientRedirect() {
  const pathname = usePathname()

  if (pathname.startsWith('/admin') && !pathname.includes('/login')) {
    redirect('/admin/login')
  }

  return <div>Login Page</div>
}
```

> **Good to know**: When using `redirect` in a Client Component on initial page load during Server-Side Rendering (SSR), it will perform a server-side redirect.

`redirect`에서 [`useRouter`](use-router.mdx) hook.로의 리디렉션에 대한 다음 예를 보면, 새 사용자를 생성하기 위해 에  요청을 하고  임시 리디렉션을 준수하는 경우 요청 방법은 을  요청으로 변경합니다. 새로운 사용자를 생성하려면  요청이 아니라 에  요청을 해야 하기 때문에 이것은 말이 되지 않습니다.

```tsx filename="app/client-redirect.tsx" switcher
'use client'

import { navigate } from './actions'

export function ClientRedirect() {
  return (
    <form action={navigate}>
      <input type="text" name="id" />
      <button>Submit</button>
    </form>
  )
}
```

```jsx filename="app/client-redirect.jsx" switcher

import { navigate } from './actions'

export function ClientRedirect() {
  return (

    </form>

```

import { redirect } from 'next/navigation'

export async function navigate(data: FormData) {

}
```

```

## 버전 기록

### Why does `redirect` use 307 and 308?

| 버전 | 변경사항 |`redirect()` you may notice that the status codes used are `307` for a temporary redirect, and `308` for a permanent redirect. While traditionally a `302` was used for a temporary redirect, and a `301` for a permanent redirect, many browsers changed the request method of the redirect, from a `POST` to `GET` request when using a `302`, regardless of the origins request method.

| --------- | --------- |`/users` to `/people`, if you make a `POST` request to `/users` to create a new user, and are conforming to a `302` temporary redirect, the request method will be changed from a `POST` to a `GET` request. This doesn't make sense, as to create a new user, you should be making a `POST` request to `/people`, and not a `GET` request.

| `307` | `POST`이 도입되었습니다. | request to  to create a new user, and are conforming to a  temporary redirect, the request method will be changed from a  to a  request. This doesn't make sense, as to create a new user, you should be making a  request to , and not a  request.

- `302` - Temporary redirect, will change the request method from `POST` to `GET`
- `307` - Temporary redirect, will preserve the request method as `POST`

The `redirect()` method uses a `307` by default, instead of a `302` temporary redirect, meaning your requests will *always* be preserved as `POST` requests.

[Learn more](https://developer.mozilla.org/docs/Web/HTTP/Redirections) about HTTP Redirects.
