The `layout` 파일은 Next.js 애플리케이션에서 레이아웃을 정의하는 데 사용됩니다.

```tsx filename="app/dashboard/layout.tsx" switcher
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
```

```jsx filename="app/dashboard/layout.js" switcher
export default function DashboardLayout({ children }) {
  return <section>{children}</section>
}
```

A **루트 레이아웃**은 루트 `app` 디렉터리의 최상위 레이아웃입니다. `<html>` 및 `<body>` 태그와 기타 전역적으로 공유되는 UI를 정의하는 데 사용됩니다.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

## 참조

### 소품

#### `children` (필수)

레이아웃 구성요소는 `children` 소품을 허용하고 사용해야 합니다. 렌더링하는 동안 `children`는 레이아웃이 래핑되는 경로 세그먼트로 채워집니다. 이는 주로 하위 [레이아웃](page.mdx)(존재하는 경우) 또는 [페이지](page.mdx)의 구성 요소가 되지만 해당하는 경우 [로드 중](loading.mdx) 또는 [오류](../../getting-started/error-handling.mdx)와 같은 다른 특수 파일일 수도 있습니다.

#### `params`(선택 사항)

루트 세그먼트부터 해당 레이아웃까지 [동적 경로 매개변수](dynamic-routes.mdx) 객체를 포함하는 객체로 확인되는 프라미스입니다.

```tsx filename="app/dashboard/[team]/layout.tsx" switcher
export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params
}
```

```jsx filename="app/dashboard/[team]/layout.js" switcher
export default async function Layout({ children, params }) {
  const { team } = await params
}
```

| 예시 경로 | URL | `params` |`app/dashboard/[team]/layout.js`  | `/dashboard/1` | `Promise<{ team: '1' }>`           |`app/shop/[tag]/[item]/layout.js` | `/shop/1/2`    | `Promise<{ tag: '1', item: '2' }>` |`app/blog/[...slug]/layout.js`    | `/blog/1/2`    | `Promise<{ slug: ['1', '2'] }>`    |

- Since the `params` 소품은 약속이기 때문입니다. 값에 액세스하려면 `async/await` 또는 React의 [`use`](https://react.dev/reference/react/use) 함수를 사용해야 합니다.
  - 버전 14 이하에서는 `params`가 동기식 prop가었습니다. 이전 버전과의 호환성을 돕기 위해 Next.js 15에서 동기적으로 계속 액세스할 수 있지만 이 동작은 향후 더 이상 사용되지 않습니다.

### 레이아웃 소품 도우미

You can type layouts with `LayoutProps`을 사용하여 레이아웃을 입력하면 강력한 유형의 `params`과 디렉터리 구조에서 유추되는 명명된 슬롯을 얻을 수 있습니다. `LayoutProps`는 전역적으로 사용 가능한 도우미입니다.

```tsx filename="app/dashboard/layout.tsx"
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* If you have app/dashboard/@analytics, it appears as a typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
```

> **알면 좋은 점**:
>
> - 유형은 `next dev`, `next build` 또는 `next typegen` 중에 생성됩니다.
> - 유형 생성 후 `LayoutProps` 도우미를 전역적으로 사용할 수 있습니다. 수입할 필요는 없습니다.

### 루트 레이아웃

The `app` 디렉터리에는 **반드시** 루트 **루트 레이아웃**이 포함되어야 합니다. 일반적으로 루트 레이아웃은 `app`입니다.`app/layout.js`.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

- 루트 레이아웃은 **반드시** `<html>` 및 `<body>` 태그를 정의해야 합니다.
  - You should **안 됩니다**. 대신 `<head>` 요소 스트리밍 및 중복 제거와 같은 고급 요구 사항을 자동으로 처리하는 `<title>` and `<meta>` to root layouts. Instead, you should use the [메타데이터 API](../../getting-started/metadata-and-og-images.mdx)을 사용해야 합니다.`<head>` elements.
- You can create **여러 루트 레이아웃**을 생성할 수 있습니다. 위에 `layout.js`이 없는 레이아웃은 루트 레이아웃입니다. 두 가지 일반적인 접근 방식:
  - Using [경로 그룹](route-groups.mdx) 사용`app/(shop)/layout.js` and `app/(marketing)/layout.js`
  - Omitting `app/layout.js`를 생략하면 `app/dashboard/layout.js` 및 `app/blog/layout.js`과 같은 하위 디렉터리의 레이아웃이 각각 해당 디렉터리의 루트 레이아웃이 됩니다.
  - Navigating **여러 루트 레이아웃에 걸쳐** 탐색하면 **전체 페이지 로드**가 발생합니다(클라이언트 측 탐색과 반대).
- 예를 들어 **동적 세그먼트** 아래에 있을 수 있습니다.[internationalization](../../guides/internationalization.mdx) with `app/[lang]/layout.js`.

## 주의사항

### 요청 객체

불필요한 서버 요청을 피하기 위해 탐색 중에 레이아웃이 클라이언트에 캐시됩니다.

[레이아웃](layout.mdx)이 다시 렌더링되지 않습니다. 페이지 간을 탐색할 때 불필요한 계산을 피하기 위해 캐시하고 재사용할 수 있습니다. 레이아웃이 원시 요청에 액세스하지 못하도록 제한함으로써 Next.js는 레이아웃 내에서 성능에 부정적인 영향을 미칠 수 있는 느리거나 비용이 많이 드는 사용자 코드의 실행을 방지할 수 있습니다.

요청 개체에 액세스하려면 [`headers`](../functions/headers.mdx) 및 함수에서 [`cookies`](../functions/cookies.mdx) 및 [Server Components](../../getting-started/server-and-client-components.mdx) API를 사용할 수 있습니다.

```tsx filename="app/shop/layout.tsx" switcher
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
```

```jsx filename="app/shop/layout.js" switcher
import { cookies } from 'next/headers'

export default async function Layout({ children }) {
  const cookieStore = await cookies()
  const theme = cookieStore.get('theme')
  return '...'
}
```

### 쿼리 매개변수

레이아웃은 탐색 시 다시 렌더링되지 않으므로 그렇지 않으면 오래될 수 있는 검색 매개변수에 액세스할 수 없습니다.

업데이트된 쿼리 매개변수에 액세스하려면 페이지 [`searchParams`](page.mdx#searchparams-optional) 소품을 사용하거나 [`useSearchParams`](../functions/use-search-params.mdx) 후크를 사용하여 클라이언트 구성 요소 내에서 읽을 수 있습니다. 클라이언트 구성 요소는 탐색 시 다시 렌더링되므로 최신 쿼리 매개변수에 액세스할 수 있습니다.

```tsx filename="app/ui/search.tsx" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}
```

```jsx filename="app/ui/search.js" switcher
'use client'

import { useSearchParams } from 'next/navigation'

export default function Search() {
  const searchParams = useSearchParams()

  const search = searchParams.get('search')

  return '...'
}
```

```tsx filename="app/shop/layout.tsx" switcher
import Search from '@/app/ui/search'

export default function Layout({ children }) {
  return (
    <>
      <Search />
      {children}
    </>
  )
}
```

```jsx filename="app/shop/layout.js" switcher

  return (
    <>
      <Search />
```

### 경로명

레이아웃은 탐색 시 다시 렌더링되지 않으므로 그렇지 않으면 오래될 수 있는 경로 이름에 액세스하지 않습니다.

현재 경로 이름에 액세스하려면 [`usePathname`](../functions/use-pathname.mdx) 후크를 사용하여 클라이언트 구성 요소 내에서 읽을 수 있습니다. 탐색 중에 클라이언트 구성 요소가 다시 렌더링되므로 최신 경로 이름에 액세스할 수 있습니다.

```tsx filename="app/ui/breadcrumbs.tsx" switcher
'use client'

import { usePathname } from 'next/navigation'

// Simplified breadcrumbs logic
export default function Breadcrumbs() {
  const pathname = usePathname()
  const segments = pathname.split('/')

  return (
    <nav>
      {segments.map((segment, index) => (
        <span key={index}>
          {' > '}
          {segment}
        </span>
      ))}
    </nav>
  )
}
```

### 활성 탐색 링크

Layouts do not have access to the route segments below itself. To access all route segments, you can use [`useSelectedLayoutSegment`](../functions/use-selected-layout-segment.mdx) 후크를 사용하여 탐색 링크가 활성화되어 있는지 확인할 수 있습니다.[`useSelectedLayoutSegments`](../functions/use-selected-layout-segments.mdx) in a Client Component.

```tsx filename="app/ui/nav-link.tsx" switcher
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

export default function NavLink({
  slug,
  children,
}: {
  slug: string
  children: React.ReactNode
}) {
  const segment = useSelectedLayoutSegment()
  const isActive = slug === segment

  return (
    <Link
      href={`/blog/${slug}`}
      // Change style depending on whether the link is active
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
  )
}
```

```jsx filename="app/ui/nav-link.js" switcher
'use client'

import Link from 'next/link'
import { useSelectedLayoutSegment } from 'next/navigation'

export default function NavLinks({ slug, children }) {

    <Link
      href={`/blog/${slug}`}
      style={{ fontWeight: isActive ? 'bold' : 'normal' }}
    >
      {children}
    </Link>
```
```jsx filename="app/blog/layout.js" switcher
  )
}
```

## Examples

### Metadata을 기반으로 콘텐츠 표시

You can modify the `<head>` 소품을 기반으로 특정 콘텐츠를 표시하거나 가져올 수 있습니다.`title` and `meta` using the [`metadata` object](../functions/generate-metadata.mdx#the-metadata-object) or [`generateMetadata` function](../functions/generate-metadata.mdx#generatemetadata-function).

```tsx filename="app/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'Next.js',
}

export default function Layout({ children }: { children: React.ReactNode }) {
  return '...'
}
```

```jsx filename="app/layout.js" switcher
export const metadata = {
  title: 'Next.js',
}

export default function Layout({ children }) {
  return '...'
}
```

> **Good to know**: You should **not** manually add `<head>` tags such as `<title>` and `<meta>` to root layouts. Instead, use the [Metadata APIs](../functions/generate-metadata.mdx) which automatically handles advanced requirements such as streaming and de-duplicating `<head>` elements.

```tsx filename="app/ui/nav-links.tsx" switcher
'use client'
```
