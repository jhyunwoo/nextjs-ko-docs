A **템플릿** 파일은 레이아웃이나 페이지를 래핑한다는 점에서 [레이아웃](../../getting-started/layouts-and-pages.mdx#creating-a-layout)과 유사합니다. 여러 경로에 걸쳐 유지되고 상태를 유지하는 레이아웃과 달리 템플릿에는 고유한 키가 제공됩니다. 즉, 하위 클라이언트 구성 요소가 탐색 시 상태를 재설정합니다.

다음과 같은 경우에 유용합니다.

- 탐색 시 `useEffect`을 다시 동기화합니다.
- 탐색 시 하위 클라이언트 구성 요소의 상태를 재설정합니다. 예를 들어 입력 필드입니다.
- 기본 프레임워크 동작을 변경합니다. 예를 들어 레이아웃 내부의 Suspense 경계는 첫 번째 로드 시에만 대체를 표시하는 반면 템플릿은 모든 탐색에 이를 표시합니다.

## 컨벤션

템플릿은 `template.js` 파일에서 기본 React 구성 요소를 내보내 정의할 수 있습니다. 구성요소는 `children` 소품을 허용해야 합니다.

<Image alt="template.js 특수 파일" srcLight="/docs/light/template-special-file.png" srcDark="/docs/dark/template-special-file.png" width="1600" height="444" />

```tsx filename="app/template.tsx" switcher
export default function Template({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>
}
```

```jsx filename="app/template.js" switcher
export default function Template({ children }) {
  return <div>{children}</div>
}
```

중첩 측면에서 `template.js`은 레이아웃과 해당 하위 항목 사이에 렌더링됩니다. 다음은 단순화된 출력입니다.

```jsx filename="Output"
<Layout>
  {/* Note that the template is given a unique key. */}
  <Template key={routeParam}>{children}</Template>
</Layout>
```

## 소품

### `children` (필수)

템플릿은 `children` 소품을 허용합니다.

```jsx filename="Output"
<Layout>
  {/* Note that the template is automatically given a unique key. */}
  <Template key={routeParam}>{children}</Template>
</Layout>
```

## 행동

- **서버 구성 요소**: 기본적으로 템플릿은 서버 구성 요소입니다.
- **탐색 포함**: 템플릿은 자체 세그먼트 수준에 대한 고유 키를 받습니다. 해당 세그먼트(동적 매개변수 포함)가 변경되면 다시 마운트됩니다. 더 깊은 세그먼트 내의 탐색은 더 높은 수준의 템플릿을 다시 마운트하지 않습니다. 검색 매개변수는 다시 마운트를 트리거하지 않습니다.
- **상태 재설정**: 템플릿 내부의 모든 클라이언트 구성 요소는 탐색 시 상태를 재설정합니다.
- **효과 재실행**: `useEffect`과 같은 효과는 구성 요소가 다시 마운트될 때 다시 동기화됩니다.
- **DOM 재설정**: 템플릿 내부의 DOM 요소가 완전히 다시 생성됩니다.

### 탐색 및 다시 마운트 중 템플릿

이 섹션에서는 탐색 중에 템플릿이 작동하는 방식을 보여줍니다. 각 경로 변경 시 어떤 템플릿이 다시 탑재되는지와 그 이유를 단계별로 보여줍니다.

이 프로젝트 트리를 사용하여:

```
app
├── about
│   ├── page.tsx
├── blog
│   ├── [slug]
│   │   └── page.tsx
│   ├── page.tsx
│   └── template.tsx
├── layout.tsx
├── page.tsx
└── template.tsx
```

Starting at `/`부터 시작하는 React 트리는 대략 다음과 같습니다.

> 참고: 예제에 표시된 `key` 값은 예시일 뿐이며 애플리케이션의 값은 다를 수 있습니다.

```jsx filename="Output"
<RootLayout>
  {/* app/template.tsx */}
  <Template key="/">
    <Page />
  </Template>
</RootLayout>
```

Navigating to `/about`(첫 번째 세그먼트 변경)로 이동하면 루트 템플릿 키가 변경되고 다시 마운트됩니다.

```jsx filename="Output"
<RootLayout>
  {/* app/template.tsx */}
  <Template key="/about">
    <AboutPage />
  </Template>
</RootLayout>
```

Navigating to `/blog`(첫 번째 세그먼트 변경)으로 이동하면 루트 템플릿 키가 변경되고 다시 마운트되고 블로그 수준 템플릿이 마운트됩니다.

```jsx filename="Output"
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    <Template key="/blog">
      <BlogIndexPage />
    </Template>
  </Template>
</RootLayout>
```

동일한 첫 번째 세그먼트 내에서 `/blog/first-post`(하위 세그먼트 변경)로 이동하면 루트 템플릿 키는 변경되지 않지만 블로그 수준 템플릿 키는 변경되어 다시 마운트됩니다.

```jsx filename="Output"
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    {/* remounts because the child segment at this level changed */}
    <Template key="/blog/first-post">
      <BlogPostPage slug="first-post" />
    </Template>
  </Template>
</RootLayout>
```

Navigating to `/blog/second-post`(동일한 첫 번째 세그먼트, 다른 하위 세그먼트)로 이동하면 루트 템플릿 키는 변경되지 않지만 블로그 수준 템플릿 키는 변경되고 다시 마운트됩니다.

```jsx filename="Output"
<RootLayout>
  {/* app/template.tsx (root) */}
  <Template key="/blog">
    {/* app/blog/template.tsx */}
    {/* remounts again due to changed child segment */}
    <Template key="/blog/second-post">
      <BlogPostPage slug="second-post" />
    </Template>
  </Template>
</RootLayout>
```
