The `use cache` 지시어를 사용하면 경로, React 구성 요소 또는 기능을 캐시 가능으로 표시할 수 있습니다. 파일의 모든 내보내기를 캐시해야 함을 나타내기 위해 파일 상단에서 사용하거나, 반환 값을 캐시하기 위해 함수나 구성 요소의 상단에서 인라인으로 사용할 수 있습니다.

> **알아두면 좋은 점:**
>
> - 쿠키나 헤더를 사용하려면 캐시된 범위 외부에서 읽고 값을 인수로 전달합니다. 이것이 선호되는 패턴입니다.
> - 메모리 내 캐시가 런타임 데이터에 충분하지 않은 경우 [`'use cache: remote'`](use-cache-remote.mdx)을 사용하면 플랫폼에서 전용 캐시 핸들러를 제공할 수 있습니다. 하지만 캐시를 확인하려면 네트워크 왕복이 필요하고 일반적으로 플랫폼 수수료가 발생합니다.
> - 규정 준수 요구 사항에 대해 또는 런타임 데이터를 `use cache` 범위에 대한 인수로 전달하도록 리팩터링할 수 없는 경우 [`'use cache: private'`](use-cache-private.mdx)를 참조하세요.

## 사용법

`use cache`은 캐시 구성 요소 기능입니다. 이를 활성화하려면 [`cacheComponents`](../config/next-config-js/cacheComponents.mdx) 옵션을 추가하세요.`next.config.ts` file:

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  cacheComponents: true,
}

module.exports = nextConfig
```

그런 다음 파일, 구성 요소 또는 함수 수준에서 `use cache`을 추가합니다.

```tsx
// File level
'use cache'

export default async function Page() {
  // ...
}

// Component level
export async function MyComponent() {
  'use cache'
  return <></>
}

// Function level
export async function getData() {
  'use cache'
  const data = await fetch('/api/data')
  return data
}
```

> **알아두면 좋은 점**: 파일 수준에서 사용하는 경우 모든 함수 내보내기는 비동기 함수여야 합니다.

## How `use cache` 작동 방식

### 캐시 키

캐시 항목의 키는 다음을 포함하는 입력의 직렬화된 버전을 사용하여 생성됩니다.

1. **빌드 ID** - 빌드별로 고유하며 이를 변경하면 모든 캐시 항목이 무효화됩니다.
1. **함수 ID** - 코드베이스의 함수 위치 및 서명에 대한 보안 해시
1. **직렬화 가능한 인수** - Props(구성 요소용) 또는 함수 인수
1. **HMR 새로 고침 해시**(개발 전용) - 핫 모듈 교체 시 캐시를 무효화합니다.

캐시된 함수가 외부 범위의 변수를 참조하면 해당 변수는 자동으로 캡처되어 인수로 바인딩되어 캐시 키의 일부가 됩니다.

```tsx filename="lib/data.ts"
async function Component({ userId }: { userId: string }) {
  const getData = async (filter: string) => {
    'use cache'
    // Cache key includes both userId (from closure) and filter (argument)
    return fetch(`/api/users/${userId}/data?filter=${filter}`)
  }

  return getData('active')
}
```

위의 코드 조각에서 `userId`은 외부 범위에서 캡처되고 `filter`는 인수로 전달되므로 둘 다 `getData` 함수의 캐시 키의 일부가 됩니다. 이는 서로 다른 사용자 및 필터 조합이 별도의 캐시 항목을 갖게 됨을 의미합니다.

## 직렬화

캐시된 함수에 대한 인수와 해당 반환 값은 직렬화 가능해야 합니다.

전체 참조를 보려면 다음을 참조하세요.

- [직렬화 가능한 인수](https://react.dev/reference/rsc/use-server#serializable-parameters-and-return-values) - **React 서버 구성 요소** 직렬화를 사용합니다.
- [직렬화 가능한 반환 유형](https://react.dev/reference/rsc/use-client#serializable-types) - **React 클라이언트 구성 요소** 직렬화 사용

> **알아두면 좋은 점:** 인수와 반환 값은 서로 다른 직렬화 시스템을 사용합니다. 서버 구성 요소 직렬화(인수용)는 클라이언트 구성 요소 직렬화(반환 값용)보다 더 제한적입니다. 이는 JSX 요소를 반환할 수 있지만 통과 패턴을 사용하지 않는 한 인수로 허용할 수 없음을 의미합니다.

### 지원되는 유형

**인수:**

- 일반 객체: `string`, `number`, `boolean`, `null`, `undefined`
- 배열: `{ key: value }`
- 날짜, 지도, 세트, TypedArrays, ArrayBuffers`[1, 2, 3]`
- React 요소(통과 전용)
- React elements (as pass-through only)

**반환 값:**

- 인수와 동일하며 JSX 요소도 추가됨

### 지원되지 않는 유형

- 클래스 인스턴스
- 기능(통과 제외)
- 기호, WeakMap, WeakSet
- URL 인스턴스

```tsx filename="app/components/user-card.tsx"
// Valid - primitives and plain objects
async function UserCard({
  id,
  config,
}: {
  id: string
  config: { theme: string }
}) {
  'use cache'
  return <div>{id}</div>
}

// Invalid - class instance
async function UserProfile({ user }: { user: UserClass }) {
  'use cache'
  // Error: Cannot serialize class instance
  return <div>{user.name}</div>
}
```

### 통과(직렬화할 수 없는 인수)

You can accept non-serializable values **자체 검사를 하지 않는 한** 직렬화할 수 없는 값을 허용할 수 있습니다. 이를 통해 `children` 및 서버 작업을 사용하여 구성 패턴을 활성화할 수 있습니다.

```tsx filename="app/components/cached-wrapper.tsx"
async function CachedWrapper({ children }: { children: ReactNode }) {
  'use cache'
  // Don't read or modify children - just pass it through
  return (
    <div className="wrapper">
      <header>Cached Header</header>
      {children}
    </div>
  )
}

// Usage: children can be dynamic
export default function Page() {
  return (
    <CachedWrapper>
      <DynamicComponent /> {/* Not cached, passed through */}
    </CachedWrapper>
  )
}
```

캐시된 구성 요소를 통해 서버 작업을 전달할 수도 있습니다.

```tsx filename="app/components/cached-form.tsx"
async function CachedForm({ action }: { action: () => Promise<void> }) {
  'use cache'
  // Don't call action here - just pass it through
  return <form action={action}>{/* ... */}</form>
}
```

## 제약

캐시된 함수는 격리된 환경에서 실행됩니다. 다음 제약 조건은 캐시 동작을 예측 가능하고 안전하게 유지하도록 보장합니다.

### 런타임 API

캐시된 함수 및 구성 요소는 **없습니다**. 대신, 캐시된 범위 외부에서 이러한 값을 읽고 인수로 전달하십시오.`cookies()`, `headers()`, or `searchParams`. Instead, read these values outside the cached scope and pass them as arguments.

### 런타임 캐싱 고려사항

While `use cache`는 주로 정적 셸에 동적 데이터를 포함하도록 설계되었지만 메모리 내 LRU(Least Recent Used) 저장소를 사용하여 런타임에 데이터를 캐시할 수도 있습니다.

런타임 캐시 동작은 호스팅 환경에 따라 다릅니다.

| 환경 | 런타임 캐싱 동작 |**Serverless**  | Cache entries typically don't persist across requests (each request can be a different instance). Build-time caching works normally.                              |**Self-hosted** | Cache entries persist across requests. Control cache size with [`cacheMaxMemorySize`](../config/next-config-js/incrementalCacheHandlerPath.mdx). |

| **[`use cache: remote`](use-cache-remote.mdx)** | Cache entries persist across requests. Control cache size with . |

| --------------- | -------------------------------------------------------------------------------------------------------------------------- |`use cache` scope, you might need [`use cache: private`](use-cache-private.mdx).

### React.

[`React.cache`](https://react.dev/reference/react/cache) operates in an isolated scope inside `use cache` boundaries. Values stored via `React.cache` outside a `use cache` function are not visible inside it.

This means you cannot use `React.cache` 경계 내부의 격리된 범위에서 작동합니다. `use cache` 함수 외부에서 을 통해 저장된 값은 내부에 표시되지 않습니다.가는 을 사용하여 데이터를  범위로 전달할 수 없음을 의미합니다.

```tsx
import { cache } from 'react'

const store = cache(() => ({ current: null as string | null }))

function Parent() {
  const shared = store()
  shared.current = 'value from parent'
  return <Child />
}

async function Child() {
  'use cache'
  const shared = store()
  // shared.current is null, not 'value from parent'
  // use cache has its own isolated React.cache scope
  return <div>{shared.current}</div>
}
```

이러한 격리는 캐시된 함수가 예측 가능하고 독립적인 동작을 갖도록 보장합니다. 데이터를 `use cache` 범위로 전달하려면 대신 함수 인수를 사용하세요.

## `use cache` at runtime

On the **서버**에서 캐시 항목은 메모리에 저장되며 `revalidate` 구성의 `expire` 및 `cacheLife` 시간을 따릅니다. [`cacheHandlers`](../config/next-config-js/cacheHandlers.mdx)을 구성하여 캐시 스토리지를 사용자 정의할 수 있습니다.`next.config.js` file.

On the **클라이언트**에서 서버 캐시의 콘텐츠는 `stale` 시간에 정의된 기간 동안 브라우저의 메모리에 저장됩니다. 클라이언트 라우터는 구성에 관계없이 **최소 30초의 비활성 시간**을 적용합니다.

The `x-nextjs-stale-time` 응답 헤더는 서버에서 클라이언트로 캐시 수명을 전달하여 조정된 동작을 보장합니다.

## 재검증

기본적으로 `use cache`는 다음 설정으로 `default` 프로필을 사용합니다.

- **오래된**: 5분(클라이언트 측)
- **재검증**: 15분(서버 측)
- **만료**: 시간에 따라 만료되지 않음

```tsx filename="lib/data.ts"
async function getData() {
  'use cache'
  // Implicitly uses default profile
  return fetch('/api/data')
}
```

### 캐시 수명 맞춤설정

캐시 기간을 맞춤설정하려면 [`cacheLife`](../functions/cacheLife.mdx) 함수를 사용하세요.

```tsx filename="lib/data.ts"
import { cacheLife } from 'next/cache'

async function getData() {
  'use cache'
  cacheLife('hours') // Use built-in 'hours' profile
  return fetch('/api/data')
}
```

### 주문형 재검증

주문형 캐시 무효화에는 [`cacheTag`](../functions/cacheTag.mdx), [`updateTag`](../functions/updateTag.mdx) 또는 [`revalidateTag`](../functions/revalidateTag.mdx)을 사용하세요.

```tsx filename="lib/data.ts"
import { cacheTag } from 'next/cache'

async function getProducts() {
  'use cache'
  cacheTag('products')
  return fetch('/api/products')
}
```

```tsx filename="app/actions.ts"
'use server'

import { updateTag } from 'next/cache'

export async function updateProduct() {
  await db.products.update(...)
  updateTag('products') // Invalidates all 'products' caches
}
```

Both `cacheLife` 및 `cacheTag`은 모두 클라이언트 및 서버 캐싱 계층에 통합됩니다. 즉, 캐싱 의미 체계를 한 곳에서 구성하고 모든 곳에 적용할 수 있습니다.

## 예

### Caching an entire route with `use cache`

전체 경로를 사전 렌더링하려면 `use cache` 및 **둘 다**의 상단에 `layout`을 추가하세요. 이러한 각 세그먼트는 애플리케이션에서 별도의 진입점으로 처리되며 독립적으로 캐시됩니다.`page` files. Each of these segments are treated as separate entry points in your application, and will be cached independently.

```tsx filename="app/layout.tsx" switcher
'use cache'

export default async function Layout({ children }: { children: ReactNode }) {
  return <div>{children}</div>
}
```

```jsx filename="app/layout.js" switcher
'use cache'

export default async function Layout({ children }) {
  return <div>{children}</div>
}
```

Any components imported and nested in `page` 파일에 가져오고 중첩된 모든 구성 요소는 `page`과 연결된 캐시 출력의 일부입니다.

```tsx filename="app/page.tsx" switcher
'use cache'

async function Users() {
  const users = await fetch('/api/users')
  // loop through users
}

export default async function Page() {
  return (
    <main>
      <Users />
    </main>
  )
}
```

```jsx filename="app/page.js" switcher
'use cache'

async function Users() {
  const users = await fetch('/api/users')
  // loop through users
}

export default async function Page() {
  return (
    <main>
      <Users />
    </main>
  )
}
```

> **알면 좋은 점**:
>
> - If `use cache`이 `layout` 또는 `page`에만 추가된 경우 해당 경로 세그먼트와 여기에 가져온 모든 구성 요소만 캐시됩니다.

### Caching a component's output with `use cache`

구성 요소 수준에서 `use cache`을 사용하여 해당 구성 요소 내에서 수행된 모든 가져오기 또는 계산을 캐시할 수 있습니다. 캐시 항목은 직렬화된 소품이 각 인스턴스에서 동일한 값을 생성하는 한 재사용됩니다.

```tsx filename="app/components/bookings.tsx" highlight={2} switcher
export async function Bookings({ type = 'haircut' }: BookingsProps) {
  'use cache'
  async function getBookingsData() {
    const data = await fetch(`/api/bookings?type=${encodeURIComponent(type)}`)
    return data
  }
  return //...
}

interface BookingsProps {
  type: string
}
```

```jsx filename="app/components/bookings.js" highlight={2} switcher
export async function Bookings({ type = 'haircut' }) {
  'use cache'
  async function getBookingsData() {
    const data = await fetch(`/api/bookings?type=${encodeURIComponent(type)}`)
    return data
  }
  return //...
}
```

### Caching function output with `use cache`

React에서 `use cache` 또는 슬롯을 사용한 구성은 유연한 구성 요소를 구축하기 위한 잘 알려진 패턴입니다. 을 사용하면 이 방식으로 UI를 계속 구성할 수 있습니다. 반환된 JSX에  또는 기타 구성 슬롯으로 포함된 모든 항목은 캐시 항목에 영향을 주지 않고 캐시된 구성 요소를 통해 전달됩니다.

```tsx filename="app/actions.ts" highlight={2} switcher
export async function getData() {
  'use cache'

  const data = await fetch('/api/data')
  return data
}
```

```jsx filename="app/actions.js" highlight={2} switcher
export async function getData() {
  'use cache'

  const data = await fetch('/api/data')
  return data
}
```

### 캐시 동작 디버깅

자세한 캐시 로깅을 위해 `children`을 설정합니다.`use cache`, you can continue to compose your UI in this way. Anything included as `children`, or other compositional slots, in the returned JSX will be passed through the cached component without affecting its cache entry.

개발 중에는 캐시된 함수의 콘솔 로그에  접두사가 붙습니다.

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  const uncachedData = await getData()
  return (
    // Pass compositional slots as props, e.g. header and children
    <CacheComponent header={<h1>Home</h1>}>
      {/* DynamicComponent is provided as the children slot */}
      <DynamicComponent data={uncachedData} />
    </CacheComponent>
  )
}

async function CacheComponent({
  header, // header: a compositional slot, injected as a prop
  children, // children: another slot for nested composition
}: {
  header: ReactNode
  children: ReactNode
}) {
  'use cache'
  const cachedData = await fetch('/api/cached-data')
  return (
    <div>
      {header}
      <PrerenderedComponent data={cachedData} />
      {children}
    </div>
  )
}
```

```jsx filename="app/page.js" switcher
export default async function Page() {
  const uncachedData = await getData()
  return (
    // Pass compositional slots as props, e.g. header and children
    <CacheComponent header={<h1>Home</h1>}>
      {/* DynamicComponent is provided as the children slot */}
      <DynamicComponent data={uncachedData} />
    </CacheComponent>
  )
}

async function CacheComponent({
  header, // header: a compositional slot, injected as a prop
  children, // children: another slot for nested composition
}) {
  'use cache'
  const cachedData = await fetch('/api/cached-data')
  return (
    <div>
      {header}
      <PrerenderedComponent data={cachedData} />
      {children}
    </div>
  )
}
```

Next.js에 내장된  중복 제거 기능을 사용하거나 캐시된 컨텍스트와 캐시되지 않은 컨텍스트에 대해 별도의 맵을 사용하세요.

```tsx filename="app/page.tsx" switcher
import ClientComponent from './ClientComponent'

export default async function Page() {
  const performUpdate = async () => {
    'use server'
    // Perform some server-side update
    await db.update(...)
  }

  return <CachedComponent performUpdate={performUpdate} />
}

async function CachedComponent({
  performUpdate,
}: {
  performUpdate: () => Promise<void>
}) {
  'use cache'
  // Do not call performUpdate here
  return <ClientComponent action={performUpdate} />
}
```

```jsx filename="app/page.js" switcher
import ClientComponent from './ClientComponent'

export default async function Page() {
  const performUpdate = async () => {
    'use server'
    // Perform some server-side update
    await db.update(...)
  }

  return <CachedComponent performUpdate={performUpdate} />
}

async function CachedComponent({ performUpdate }) {
  'use cache'
  // Do not call performUpdate here
  return <ClientComponent action={performUpdate} />
}
```

### Build Hangs (Cache Timeout)

| `use cache` boundary. The cached function waits for data that can't resolve during the build, causing a timeout after 50 seconds. | 아니요 |

|  | 플랫폼별 |

> Error: Filling a cache during prerender timed out, likely because request-specific arguments such as params, searchParams, cookies() or dynamic data were used inside "use cache".

| 버전 | 변경사항 |

> **Good to know:** Directly calling `cookies()` or `headers()` inside `use cache` fails immediately with a [different error](https://nextjs.org/docs/messages/next-request-in-use-cache), not a timeout.

**Passing runtime data Promises as props:**

```tsx filename="app/page.tsx"
import { cookies } from 'next/headers'
import { Suspense } from 'react'

export default function Page() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Dynamic />
    </Suspense>
  )
}

async function Dynamic() {
  const cookieStore = cookies()
  return <Cached promise={cookieStore} /> // Build hangs
}

async function Cached({ promise }: { promise: Promise<unknown> }) {
  'use cache'
  const data = await promise // Waits for runtime data during build
  return <p>..</p>
}
```

| `cookies` | `Dynamic`은 실험적 기능으로 도입되었습니다.     |`Cached` component.

**Shared deduplication storage:**

```tsx filename="app/page.tsx"
// Problem: Map stores dynamic Promises, accessed by cached code
import { Suspense } from 'react'

const cache = new Map<string, Promise<string>>()

export default function Page() {
  return (
    <>
      <Suspense fallback={<div>Loading...</div>}>
        <Dynamic id="data" />
      </Suspense>
      <Cached id="data" />
    </>
  )
}

async function Dynamic({ id }: { id: string }) {
  // Stores dynamic Promise in shared Map
  cache.set(
    id,
    fetch(`https://api.example.com/${id}`).then((r) => r.text())
  )
  return <p>Dynamic</p>
}

async function Cached({ id }: { id: string }) {
  'use cache'
  return <p>{await cache.get(id)}</p> // Build hangs - retrieves dynamic Promise
}
```

Use Next.js's built-in `fetch()` deduplication or use separate Maps for cached and uncached contexts.
