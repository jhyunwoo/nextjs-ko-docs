The `'use cache: private'` 지시문을 사용하면 함수가 캐시된 범위 내에서 `cookies()`, `headers()` 및 `searchParams`과 같은 런타임 요청 API에 액세스할 수 있습니다. 그러나 결과는 **서버에 저장되지 않습니다**. 브라우저의 메모리에만 캐시되며 페이지를 다시 로드해도 지속되지 않습니다.

다음과 같은 경우 `'use cache: private'`에 도달하세요.

- 이미 런타임 데이터에 액세스하고 있는 함수를 캐시하려고 하며 [런타임 액세스를 외부로 이동하고 값을 인수로 전달](../../getting-started/cache-components.mdx#with-runtime-data)하도록 리팩토링하는 것은 실용적이지 않습니다.
- 규정 준수 요구 사항으로 인해 일시적이라도 특정 데이터가 서버에 저장되지 않습니다.

이 지시어는 런타임 데이터에 액세스하기 때문에 함수는 모든 서버 렌더링에서 실행되며 [정적 셸](../../getting-started/cache-components.mdx#how-rendering-works-with-cache-components) 생성 중에 실행에서 제외됩니다.

It is **불가능**합니다.`'use cache: private'`.

다양한 캐시 지시어를 비교하려면 [How `use cache: remote`이 `use cache` 및 `use cache: private`](use-cache-remote.mdx#how-use-cache-remote-differs-from-use-cache-and-use-cache-private)을 참조하세요.

> **알아두면 좋은 정보**: 이 지시문은 아직 안정적이지 않은 런타임 프리페칭에 의존하기 때문에 `experimental`로 표시됩니다. 런타임 프리페칭은 라우터가 [정적 셸](../../getting-started/cache-components.mdx#how-rendering-works-with-cache-components)을 지나 개인 캐시뿐만 아니라 **모든** 캐시된 범위로 프리페치를 할 수 있도록 하는 향후 기능입니다.

## 사용법

To use `'use cache: private'`을 사용하려면 [`cacheComponents`](../config/next-config-js/cacheComponents.mdx) 플래그를 활성화하세요.`next.config.ts` file:

```tsx filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

```jsx filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  cacheComponents: true,
}

export default nextConfig
```

그런 다음 `'use cache: private'` 구성과 함께 `cacheLife`을 함수에 추가하세요.

> **알아두면 좋은 정보**: 이 지시어는 경로 핸들러에서 사용할 수 없습니다.

### 기본 예

이 예에서는 `'use cache: private'` 범위 내에서 쿠키에 액세스할 수 있음을 보여줍니다.

```tsx filename="app/product/[id]/page.tsx" switcher
import { Suspense } from 'react'
import { cookies } from 'next/headers'
import { cacheLife, cacheTag } from 'next/cache'

export async function generateStaticParams() {
  return [{ id: '1' }]
}

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params

  return (
    <div>
      <ProductDetails id={id} />
      <Suspense fallback={<div>Loading recommendations...</div>}>
        <Recommendations productId={id} />
      </Suspense>
    </div>
  )
}

async function Recommendations({ productId }: { productId: string }) {
  const recommendations = await getRecommendations(productId)

  return (
    <div>
      {recommendations.map((rec) => (
        <ProductCard key={rec.id} product={rec} />
      ))}
    </div>
  )
}

async function getRecommendations(productId: string) {
  'use cache: private'
  cacheTag(`recommendations-${productId}`)
  cacheLife({ stale: 60 })

  // Access cookies within private cache functions
  const sessionId = (await cookies()).get('session-id')?.value || 'guest'

  return getPersonalizedRecommendations(productId, sessionId)
}
```


> **알아두면 좋은 정보**: 런타임 미리 가져오기가 작동하려면 `stale` 시간이 최소 30초 이상이어야 합니다. 자세한 내용은 [`cacheLife` 클라이언트 라우터 캐시 동작](../functions/cacheLife.mdx#client-router-cache-behavior)을 참조하세요.

## 개인 캐시에서 허용되는 요청 API

다음 요청별 API는 `'use cache: private'` 함수 내에서 사용할 수 있습니다.

| API | `use cache`에서 허용됨 | `'use cache: private'`에서 허용됨 |`cookies()`    | No                     | Yes                               |`headers()`    | No                     | Yes                               |
| `searchParams` | No                     | Yes                               |
| `connection()` | No                     | No                                |

> **참고:** [`connection()`](https://nextjs.org/docs/app/api-reference/functions/connection) API는 안전하게 캐시할 수 없는 연결별 정보를 제공하므로 `use cache` 및 `'use cache: private'` 모두에서 금지됩니다.
