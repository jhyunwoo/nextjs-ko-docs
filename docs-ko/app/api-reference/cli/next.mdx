Next.js CLI를 사용하면 애플리케이션을 개발, 빌드, 시작하는 등의 작업을 수행할 수 있습니다.

기본 사용법:

```bash filename="Terminal"
npx next [command] [options]
```

## 참조

다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
| ------ | --------------------- |
| `-h` 또는 `--help` | 사용 가능한 모든 옵션을 표시합니다 |
| `-v` 또는 `--version` | Next.js 버전 번호 출력 |

### 명령

다음 명령을 사용할 수 있습니다.

| 명령 | 설명 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| [`dev`](#next-dev-options) | 핫 모듈 다시 로드, 오류 보고 등을 통해 개발 모드에서 Next.js를 시작합니다.                      |
| [`build`](#next-build-options) | 애플리케이션의 최적화된 프로덕션 빌드를 만듭니다. 각 경로에 대한 정보를 표시합니다.           |
| [`start`](#next-start-options) | 프로덕션 모드에서 Next.js를 시작합니다. 애플리케이션은 먼저 `next build`를 사용하여 컴파일되어야 합니다.                |
| [`info`](#next-info-options) | Next.js 버그를 보고하는 데 사용할 수 있는 현재 시스템에 대한 관련 세부 정보를 인쇄합니다.                    |
| [`telemetry`](#next-telemetry-options) | Next.js'의 완전 익명 원격 측정 수집을 활성화하거나 비활성화할 수 있습니다.                           |
| [`typegen`](#next-typegen-options) | 전체 빌드를 실행하지 않고 경로, 페이지, 레이아웃 및 경로 핸들러에 대한 TypeScript 정의를 생성합니다. |
| [`upgrade`](#next-upgrade-options) | Next.js 애플리케이션을 최신 버전으로 업그레이드합니다.                                                      |
| [`experimental-analyze`](#next-experimental-analyze-options) | Turbopack를 사용하여 번들 출력을 분석합니다. 빌드 아티팩트를 생성하지 않습니다.                                     |

> **알아두면 좋은 정보**: 명령 없이 `next`을 실행하는 것은 `next dev`의 별칭입니다.

### `next dev` 옵션

`next dev`은 HMR(핫 모듈 다시 로드), 오류 보고 등을 통해 개발 모드에서 애플리케이션을 시작합니다. `next dev`을 실행할 때 다음 옵션을 사용할 수 있습니다.| 옵션 | 설명 |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.                                                                                                                          |
| `[directory]` | 애플리케이션을 빌드할 디렉터리입니다. 제공되지 않으면 현재 디렉터리가 사용됩니다.                                                           |
| `--turbopack` | [Turbopack](../turbopack.mdx)을 강제 활성화합니다(기본적으로 활성화되어 있음). `--turbo`로도 사용 가능합니다.                                       |
| `--webpack` | 개발에는 기본 [Turbopack](../turbopack.mdx) 번들러 대신 Webpack를 사용하세요.                                           |
| `-p` 또는 `--port <port>` | 애플리케이션을 시작할 포트 번호를 지정합니다. 기본값: 3000, 환경: PORT |
| `-H`또는 `--hostname <hostname>` | 애플리케이션을 시작할 호스트 이름을 지정합니다. 네트워크의 다른 장치에서 애플리케이션을 사용할 수 있도록 하는 데 유용합니다. 기본값: 0.0.0.0 |
| `--experimental-https` | HTTPS로 서버를 시작하고 자체 서명된 인증서를 생성합니다.                                                                                |
| `--experimental-https-key <path>` | HTTPS 키 파일의 경로입니다.                                                                                                                            |
| `--experimental-https-cert <path>` | HTTPS 인증서 파일의 경로입니다.                                                                                                                    |
| `--experimental-https-ca <path>` | HTTPS 인증 기관 파일의 경로입니다.                                                                                                          |
| `--experimental-upload-trace <traceUrl>` | 디버깅 추적의 하위 집합을 원격 HTTP URL에 보고합니다.                                                                                        |

### `next build` 옵션

`next build`은 애플리케이션의 최적화된 프로덕션 빌드를 생성합니다. 출력에는 각 경로에 대한 정보가 표시됩니다. 예를 들면:

```bash filename="Terminal"
Route (app)
┌ ○ /_not-found
└ ƒ /products/[id]

○  (Static)   prerendered as static content
ƒ  (Dynamic)  server-rendered on demand
```

`next build` 명령에는 다음 옵션을 사용할 수 있습니다.| 옵션 | 설명 |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.                                                                                                                                                        |
| `[directory]` | 애플리케이션을 빌드할 디렉터리입니다. 제공되지 않으면 현재 디렉터리가 사용됩니다.                                                                                |
| `--turbopack` | [Turbopack](../turbopack.mdx)을 강제 활성화합니다(기본적으로 활성화되어 있음). `--turbo`로도 사용 가능합니다.                                                                     |
| `--webpack` | Webpack를 사용하여 빌드합니다.                                                                                                                                                               |
| `-d` 또는 `--debug` | 보다 자세한 빌드 출력을 활성화합니다. 이 플래그를 활성화하면 재작성, 리디렉션 및 헤더와 같은 추가 빌드 출력이 표시됩니다.                                           |
|                                    |
| `--profile` | 프로덕션 [React에 대한 프로파일링](https://react.dev/reference/react/Profiler)을 활성화합니다.                                                                                              |
| `--no-lint` | 린팅을 비활성화합니다. *참고: Next 16에서는 `next build`에서 Linting가 제거됩니다. `eslint` 이외의 Linter와 함께 Next 15.5 이상을 사용하는 경우 빌드 중 Linting가 발생하지 않습니다.* |
| `--no-mangling` | [맹글링](https://en.wikipedia.org/wiki/Name_mangling)을 비활성화합니다. 이는 성능에 영향을 미칠 수 있으므로 디버깅 목적으로만 사용해야 합니다.                                      |
| `--experimental-app-only` | 앱 라우터 경로만 빌드합니다.                                                                                                                                                     |
| `--experimental-build-mode [mode]` | 실험적인 빌드 모드를 사용합니다. (선택: "컴파일", "생성", 기본값: "기본값") |
| `--debug-prerender` | 개발 중 사전 렌더링 오류를 디버그합니다.                                                                                                                                             |
| `--debug-build-paths=<patterns>` | 디버깅을 위해 특정 경로만 빌드하세요.                                                                                                                                          |### `next start` 옵션

`next start`은 프로덕션 모드에서 애플리케이션을 시작합니다. 애플리케이션은 먼저 [`next build`](#next-build-options)으로 컴파일되어야 합니다.

`next start` 명령에는 다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `-h` 또는 `--help` | 사용 가능한 모든 옵션을 표시합니다.                                                                                     |
| `[directory]` | 애플리케이션을 시작할 디렉터리입니다. 디렉토리가 제공되지 않으면 현재 디렉토리가 사용됩니다. |
| `-p` 또는 `--port <port>` | 애플리케이션을 시작할 포트 번호를 지정합니다. (기본값: 3000, 환경: PORT) |
| `-H` 또는 `--hostname <hostname>` | 애플리케이션을 시작할 호스트 이름을 지정합니다(기본값: 0.0.0.0).                                        |
| `--keepAliveTimeout <keepAliveTimeout>` | 비활성 연결을 닫기 전에 대기할 최대 시간(밀리초)을 지정하십시오.                     |

### `next info` 옵션

`next info`는 [GitHub 문제](https://github.com/vercel/next.js/issues)를 열 때 Next.js 버그를 보고하는 데 사용할 수 있는 현재 시스템에 대한 관련 세부 정보를 인쇄합니다. 이 정보에는 운영 체제 플랫폼/아치/버전, 바이너리(Node.js, npm, Yarn, pnpm), 패키지 버전(`next`, `react`, `react-dom`) 등이 포함됩니다.

출력은 다음과 같아야 합니다.

```bash filename="Terminal"
Operating System:
  Platform: darwin
  Arch: arm64
  Version: Darwin Kernel Version 23.6.0
  Available memory (MB): 65536
  Available CPU cores: 10
Binaries:
  Node: 20.12.0
  npm: 10.5.0
  Yarn: 1.22.19
  pnpm: 9.6.0
Relevant Packages:
  next: 15.0.0-canary.115 // Latest available version is detected (15.0.0-canary.115).
  eslint-config-next: 14.2.5
  react: 19.0.0-rc
  react-dom: 19.0.0
  typescript: 5.5.4
Next.js Config:
  output: N/A
```

`next info` 명령에는 다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
| ---------------- | --------------------------------- |
| `-h` 또는 `--help` | 사용 가능한 모든 옵션 표시 |
| `--verbose` | 디버깅을 위한 추가 정보를 수집합니다. |

### `next telemetry` 옵션

Next.js는 일반적인 사용에 대한 **완전히 익명** 원격 측정 데이터를 수집합니다. 이 익명 프로그램에 대한 참여는 선택 사항이며, 정보를 공유하지 않으려면 참여를 취소할 수 있습니다.

`next telemetry` 명령에는 다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
| ------------ | -------------------------- |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.             |
| `--enable` | Next.js' 원격 측정 수집을 활성화합니다.  |
| `--disable` | Next.js' 원격 측정 수집을 비활성화합니다. |

[원격 측정](https://nextjs.org/telemetry)에 대해 자세히 알아보세요.### `next typegen` 옵션

`next typegen`은 전체 빌드를 수행하지 않고 애플리케이션 경로에 대한 TypeScript 정의를 생성합니다. 이는 IDE 자동 완성 및 경로 사용의 CI 유형 확인에 유용합니다.

이전에는 경로 유형이 `next dev` 또는 `next build` 중에만 생성되었습니다. 즉, `tsc --noEmit`을 직접 실행해도 경로 유형이 검증되지 않았습니다. 이제 유형을 독립적으로 생성하고 외부에서 유효성을 검사할 수 있습니다.

```bash filename="Terminal"
# Generate route types first, then validate with TypeScript
next typegen && tsc --noEmit

# Or in CI workflows for type checking without building
next typegen && npm run type-check
```

`next typegen` 명령에는 다음 옵션을 사용할 수 있습니다.

| 옵션 | 설명 |
| ------------- | ------------------------------------------------------------------ |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.                                                                  |
| `[directory]` | 유형을 생성할 디렉터리입니다. 제공되지 않으면 현재 디렉터리가 사용됩니다. |

출력 파일은 `<distDir>/types`에 기록됩니다(일반적으로: `.next/dev/types` 또는 `.next/types`, [`isolatedDevBuild`](../config/next-config-js/isolatedDevBuild.mdx) 참조).

```bash filename="Terminal"
next typegen
# or for a specific app
next typegen ./apps/web
```

또한 `next typegen`는 `next-env.d.ts` 파일을 생성합니다. `next-env.d.ts` 파일에 `.gitignore`을 추가하는 것이 좋습니다.

`next-env.d.ts` 파일은 `tsconfig.json` 파일에 포함되어 프로젝트에서 Next.js 유형을 사용할 수 있습니다.

유형 검사 전에 `next-env.d.ts`이 있는지 확인하려면 `next typegen`을 실행하세요. `next dev` 및 `next build` 명령도 `next-env.d.ts` 파일을 생성하지만 예를 들어 CI/CD 환경에서 단지 유형 확인을 위해 이러한 명령을 실행하는 것은 바람직하지 않은 경우가 많습니다.

> **알아두면 좋은 정보**: `next typegen`는 프로덕션 빌드 단계를 사용하여 Next.js 구성(`next.config.js`, `next.config.mjs` 또는 `next.config.ts`)을 로드합니다. 구성이 올바르게 로드될 수 있도록 필요한 환경 변수와 종속성을 사용할 수 있는지 확인하세요.

### `next upgrade` 옵션

`next upgrade`은 Next.js 애플리케이션을 최신 버전으로 업그레이드합니다.

`next upgrade` 명령에는 다음 옵션을 사용할 수 있습니다.| 옵션 | 설명 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.                                                                                                                        |
| `[directory]` | 업그레이드할 Next.js 애플리케이션이 있는 디렉터리입니다. 제공되지 않으면 현재 디렉터리가 사용됩니다.                                          |
| `--revision <revision>` | 업그레이드할 Next.js 버전 또는 태그를 지정합니다(예: `latest`, `canary`, `15.0.0`). 기본값은 현재 설치된 릴리스 채널입니다. |
| `--verbose` | 업그레이드 프로세스 중에 자세한 출력을 표시합니다.                                                                                                    |

### `next experimental-analyze` 옵션

`next experimental-analyze`은 [Turbopack](../turbopack.mdx)을 사용하여 애플리케이션의 번들 출력을 분석합니다. 이 명령은 JavaScript, CSS 및 기타 자산을 포함하여 번들의 크기와 구성을 이해하는 데 도움이 됩니다. 이 명령은 애플리케이션 빌드를 생성하지 않습니다.

```bash filename="Terminal"
npx next experimental-analyze
```

기본적으로 이 명령은 분석이 완료된 후 로컬 서버를 시작하므로 브라우저에서 번들 구성을 탐색할 수 있습니다. 분석기를 사용하면 다음을 수행할 수 있습니다.

- 경로별로 번들을 필터링하고 클라이언트와 서버 보기 간 전환
- 모듈이 포함된 이유를 보여주는 전체 가져오기 체인 보기
- 서버-클라이언트 구성 요소 경계 및 동적 가져오기를 통한 추적 가져오기

최적화 전략은 [패키지 번들링](../../guides/package-bundling.mdx#optimizing-large-bundles)을 참조하세요.

서버를 시작하지 않고 분석 출력을 디스크에 쓰려면 `--output` 플래그를 사용하십시오. 출력은 `.next/diagnostics/analyze`에 기록되며 다른 곳으로 복사하거나 다른 사람과 공유할 수 있는 정적 파일을 포함합니다.

```bash filename="Terminal"
# Write output to .next/diagnostics/analyze
npx next experimental-analyze --output

# Copy the output for comparison with a future analysis
cp -r .next/diagnostics/analyze ./analyze-before-refactor
```

`next experimental-analyze` 명령에는 다음 옵션을 사용할 수 있습니다.| 옵션 | 설명 |
| --------------- | ------------------------------------------------------------------------------------------------------------------- |
| `-h, --help` | 사용 가능한 모든 옵션을 표시합니다.                                                                                                                   |
| `[directory]` | 애플리케이션을 분석할 디렉터리입니다. 제공되지 않으면 현재 디렉터리가 사용됩니다.                                         |
| `--no-mangling` | [맹글링](https://en.wikipedia.org/wiki/Name_mangling)을 비활성화합니다. 이는 성능에 영향을 미칠 수 있으므로 디버깅 목적으로만 사용해야 합니다. |
| `--profile` | 프로덕션 [React에 대한 프로파일링](https://react.dev/reference/react/Profiler)을 활성화합니다. 이는 성능에 영향을 미칠 수 있습니다.                            |
| `-o, --output` | 서버를 시작하지 않고 분석 파일을 디스크에 씁니다. 출력은 `.next/diagnostics/analyze`에 기록됩니다.                                   |
| `--port <port>` | 분석기를 제공할 포트 번호를 지정합니다. (기본값: 4000, 환경: PORT) |

## 예

### 사전 렌더링 오류 디버깅

`next build` 중에 사전 렌더링 오류가 발생하는 경우 `--debug-prerender` 플래그를 전달하여 더 자세한 출력을 얻을 수 있습니다.

```bash filename="Terminal"
next build --debug-prerender
```

이를 통해 디버깅을 더 쉽게 만드는 여러 가지 실험적 옵션이 가능해졌습니다.

- 서버 코드 축소를 비활성화합니다.
  - `experimental.serverMinification = false`
  - `experimental.turbopackMinify = false`
- 서버 번들에 대한 소스 맵을 생성합니다.
  - `experimental.serverSourceMaps = true`
- 사전 렌더링에 사용되는 하위 프로세스에서 소스 맵 소비를 활성화합니다.
  - `enablePrerenderSourceMaps = true`
- 첫 번째 사전 렌더링 오류 후에도 계속 빌드되므로 모든 문제를 한 번에 볼 수 있습니다.
  - `experimental.prerenderEarlyExit = false`

이는 빌드 출력에서 더 읽기 쉬운 스택 추적 및 코드 프레임을 표시하는 데 도움이 됩니다.

> **경고**: `--debug-prerender`은 개발 중인 디버깅에만 사용됩니다. 성능에 영향을 미칠 수 있으므로 `--debug-prerender`로 생성된 빌드를 프로덕션에 배포하지 마세요.

### 특정 경로 구축

`--debug-build-paths` 옵션을 사용하면 앱 및 페이지 라우터에서 특정 경로만 구축할 수 있습니다. 이는 대규모 애플리케이션으로 작업할 때 더 빠른 디버깅에 유용합니다. `--debug-build-paths` 옵션은 쉼표로 구분된 파일 경로를 허용하고 glob 패턴을 지원합니다.

```bash filename="Terminal"
# Build a specific route
next build --debug-build-paths="app/page.tsx"

# Build more than one route
next build --debug-build-paths="app/page.tsx,pages/index.tsx"

# Use glob patterns
next build --debug-build-paths="app/**/page.tsx"
next build --debug-build-paths="pages/*.tsx"
```

### 기본 포트 변경하기

기본적으로 Next.js는 개발 중에 `http://localhost:3000`과 함께 `next start`을 사용합니다. 기본 포트는 다음과 같이 `-p` 옵션을 사용하여 변경할 수 있습니다.

```bash filename="Terminal"
next dev -p 4000
```

또는 `PORT` 환경 변수를 사용합니다.

```bash filename="Terminal"
PORT=4000 next dev
```

> **알아두면 좋은 정보**: `PORT`은 다른 코드가 초기화되기 전에 HTTP 서버 부팅이 발생하므로 `.env`에서 설정할 수 없습니다.### 개발 중 HTTPS 사용

웹후크 또는 인증과 같은 특정 사용 사례의 경우 [HTTPS](https://developer.mozilla.org/en-US/docs/Glossary/HTTPS)를 사용하여 `localhost`에 보안 환경을 확보할 수 있습니다. Next.js는 `next dev` 플래그를 사용하여 `--experimental-https`로 자체 서명된 인증서를 생성할 수 있습니다.

```bash filename="Terminal"
next dev --experimental-https
```

생성된 인증서를 사용하면 Next.js 개발 서버가 `https://localhost:3000`에 존재하게 됩니다. 포트가 `3000`, `-p` 또는 `--port`로 지정되지 않으면 기본 포트 `PORT`가 사용됩니다.

`--experimental-https-key` 및 `--experimental-https-cert`을 사용하여 사용자 지정 인증서와 키를 제공할 수도 있습니다. 선택적으로 `--experimental-https-ca`을 사용하여 사용자 정의 CA 인증서를 제공할 수도 있습니다.

```bash filename="Terminal"
next dev --experimental-https --experimental-https-key ./certificates/localhost-key.pem --experimental-https-cert ./certificates/localhost.pem
```

`next dev --experimental-https`은 개발 전용이며 [`mkcert`](https://github.com/FiloSottile/mkcert)을 사용하여 로컬에서 신뢰할 수 있는 인증서를 생성합니다. 프로덕션에서는 신뢰할 수 있는 기관에서 적절하게 발급된 인증서를 사용하세요.

### 다운스트림 프록시에 대한 시간 초과 구성

다운스트림 프록시(예: AWS ELB/ALB와 같은 로드 밸런서) 뒤에 Next.js를 배포할 때 다운스트림 프록시의 시간 초과보다 *큰* [연결 유지 시간 초과](https://nodejs.org/api/http.html#http_server_keepalivetimeout)로 Next의 기본 HTTP 서버를 구성하는 것이 중요합니다. 그렇지 않고 지정된 TCP 연결에 대해 연결 유지 시간 초과에 도달하면 Node.js는 다운스트림 프록시에 알리지 않고 해당 연결을 즉시 종료합니다. 이로 인해 Node.js가 이미 종료된 연결을 재사용하려고 할 때마다 프록시 오류가 발생합니다.

프로덕션 Next.js 서버의 시간 초과 값을 구성하려면 다음과 같이 `--keepAliveTimeout`(밀리초 단위)을 `next start`에 전달합니다.

```bash filename="Terminal"
next start --keepAliveTimeout 70000
```

### Node.js 인수 전달

모든 [노드 인수](https://nodejs.org/api/cli.html#cli_node_options_options)를 `next` 명령에 전달할 수 있습니다. 예를 들면:

```bash filename="Terminal"
NODE_OPTIONS='--throw-deprecation' next
NODE_OPTIONS='-r esm' next
NODE_OPTIONS='--inspect' next
```
