Next.js는 기본 내보내기를 사용하여 프로젝트 디렉터리의 루트에 있는 `next.config.js` 파일(예: `package.json`)을 통해 구성할 수 있습니다.

```js filename="next.config.js"
// @ts-check

/** @type {import('next').NextConfig} */
const nextConfig = {
  /* config options here */
}

module.exports = nextConfig
```

## ECMAScript 모듈

`next.config.js`은 JSON 파일이 아닌 일반 Node.js 모듈입니다. Next.js 서버 및 빌드 단계에서 사용되며 브라우저 빌드에는 포함되지 않습니다.

If you need [ECMAScript 모듈](https://nodejs.org/api/esm.html)이 필요한 경우 `next.config.mjs`을 사용할 수 있습니다.

```js filename="next.config.mjs"
// @ts-check

/**
 * @type {import('next').NextConfig}
 */
const nextConfig = {
  /* config options here */
}

export default nextConfig
```

> **알아두면 좋은 정보**: `next.config` 또는 `.cjs` 확장이 포함된 `.cts`은 현재 지원되지 **않습니다**.

## 기능으로 구성

다음과 같은 기능을 사용할 수도 있습니다.

```js filename="next.config.mjs"
// @ts-check

export default (phase, { defaultConfig }) => {
  /**
   * @type {import('next').NextConfig}
   */
  const nextConfig = {
    /* config options here */
  }
  return nextConfig
}
```

### 비동기 구성

Next.js 12.1.0부터 비동기 기능을 사용할 수 있습니다.

```js filename="next.config.js"
// @ts-check

module.exports = async (phase, { defaultConfig }) => {
  /**
   * @type {import('next').NextConfig}
   */
  const nextConfig = {
    /* config options here */
  }
  return nextConfig
}
```

### 단계

`phase`은 구성이 로드되는 현재 컨텍스트입니다. [사용 가능한 단계](https://github.com/vercel/next.js/blob/5e6b008b561caf2710ab7be63320a3d549474a5b/packages/next/shared/lib/constants.ts#L19-L23)를 확인할 수 있습니다. `next/constants`에서 단계를 가져올 수 있습니다.

```js filename="next.config.js"
// @ts-check

const { PHASE_DEVELOPMENT_SERVER } = require('next/constants')

module.exports = (phase, { defaultConfig }) => {
  if (phase === PHASE_DEVELOPMENT_SERVER) {
    return {
      /* development only config options here */
    }
  }

  return {
    /* config options for all phases except development here */
  }
}
```

## TypeScript

프로젝트에서 TypeScript를 사용하는 경우 `next.config.ts`을 사용하여 구성에서 TypeScript를 사용할 수 있습니다.

```ts filename="next.config.ts"
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  /* config options here */
}

export default nextConfig
```

주석 처리된 줄은 `next.config.js`에서 허용하는 구성을 넣을 수 있는 장소입니다.[defined in this file](https://github.com/vercel/next.js/blob/canary/packages/next/src/server/config-shared.ts).

그러나 어떤 구성도 필요하지 않으며 각 구성의 기능을 이해할 필요도 없습니다. 대신 이 섹션에서 활성화하거나 수정해야 하는 기능을 검색하면 수행할 작업이 표시됩니다.

> 대상 Node.js 버전에서 사용할 수 없는 새로운 JavaScript 기능을 사용하지 마십시오. `next.config.js`은 Webpack 또는 Babel에 의해 구문 분석되지 않습니다.

이 페이지에는 사용 가능한 모든 구성 옵션이 설명되어 있습니다.

## 단위 테스트(실험적)

Next.js 15.1부터 `next/experimental/testing/server` 패키지에는 `next.config.js` 파일의 단위 테스트를 돕는 유틸리티가 포함되어 있습니다.

The `unstable_getResponseFromNextConfig` 함수는 다음에서 [`headers`](headers.mdx), [`redirects`](redirects.mdx) 및 [`rewrites`](rewrites.mdx) 함수를 실행합니다. `next.config.js`를 제공된 요청 정보와 함께 사용하고 라우팅 결과와 함께 `NextResponse`을 반환합니다.

> The response from `unstable_getResponseFromNextConfig`의 응답은 `next.config.js` 필드만 고려하고 프록시 또는 파일 시스템 경로는 고려하지 않으므로 프로덕션 결과는 단위 테스트와 다를 수 있습니다.

```js
import {
  getRedirectUrl,
  unstable_getResponseFromNextConfig,
} from 'next/experimental/testing/server'

const response = await unstable_getResponseFromNextConfig({
  url: 'https://nextjs.org/test',
  nextConfig: {
    async redirects() {
      return [{ source: '/test', destination: '/test2', permanent: false }]
    },
  },
})
expect(response.status).toEqual(307)
expect(getRedirectUrl(response)).toEqual('https://nextjs.org/test2')
```
