## 사용법

The `taint` 옵션을 사용하면 개체 및 값 오염을 위한 실험적인 React API를 지원할 수 있습니다. 이 기능은 중요한 데이터가 실수로 클라이언트에 전달되는 것을 방지하는 데 도움이 됩니다. 활성화되면 다음을 사용할 수 있습니다.

- [`experimental_taintObjectReference`](https://react.dev/reference/react/experimental_taintObjectReference) 오염 개체 참조.
- [`experimental_taintUniqueValue`](https://react.dev/reference/react/experimental_taintUniqueValue)를 사용하여 고유한 값을 오염시킵니다.

> **알아두면 좋은 정보**: 이 플래그를 활성화하면 `experimental` 디렉터리에 대한 React `app` 채널도 활성화됩니다.

```ts filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    taint: true,
  },
}

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    taint: true,
  },
}

module.exports = nextConfig
```

> **경고:** 민감한 데이터가 클라이언트에 노출되는 것을 방지하는 유일한 메커니즘으로 API 오염에 의존하지 마십시오. [보안 권장 사항](https://nextjs.org/blog/security-nextjs-server-components-actions)을 참조하세요.

오염 API를 사용하면 서버-클라이언트 경계를 통과할 수 없는 데이터를 선언적이고 명시적으로 표시하여 방어할 수 있습니다. 개체나 값이 서버-클라이언트 경계를 통과하면 React에서 오류가 발생합니다.

이는 다음과 같은 경우에 유용합니다.

- 데이터를 읽는 방법은 사용자가 통제할 수 없습니다.
- 자신이 정의하지 않은 민감한 데이터 형태로 작업해야 합니다.
- 서버 구성 요소 렌더링 중에 민감한 데이터에 액세스합니다.

민감한 데이터가 필요하지 않은 컨텍스트에 반환되지 않도록 데이터와 API를 모델링하는 것이 좋습니다.

## 주의사항

- 오염은 참조를 통해서만 객체를 추적할 수 있습니다. 객체를 복사하면 오염되지 않은 버전이 생성되어 API에서 제공하는 모든 보장을 잃게 됩니다. 복사본을 오염시켜야 합니다.
- 오염은 오염된 값에서 파생된 데이터를 추적할 수 없습니다. 또한 파생된 값을 오염시켜야 합니다.
- 수명 참조가 범위 내에 있는 동안 값은 오염됩니다. 자세한 내용은 [`experimental_taintUniqueValue` 매개변수 참조](https://react.dev/reference/react/experimental_taintUniqueValue#parameters)를 참조하세요.

## 예

### 객체 참조 오염

이 경우 `getUserDetails` 함수는 특정 사용자에 대한 데이터를 반환합니다. 사용자 개체 참조를 오염시켜 서버-클라이언트 경계를 넘을 수 없도록 합니다. 예를 들어 `UserCard`이 클라이언트 구성 요소라고 가정합니다.

```ts switcher
import { experimental_taintObjectReference } from 'react'

function getUserDetails(id: string): UserDetails {
  const user = await db.queryUserById(id)

  experimental_taintObjectReference(
    'Do not use the entire user info object. Instead, select only the fields you need.',
    user
  )

  return user
}
```

```js switcher
import { experimental_taintObjectReference } from 'react'

function getUserDetails(id) {
  const user = await db.queryUserById(id)

  experimental_taintObjectReference(
    'Do not use the entire user info object. Instead, select only the fields you need.',
    user
  )

  return user
}
```

오염된 `userDetails` 개체의 개별 필드에 계속 액세스할 수 있습니다.

```tsx filename="app/contact/page.tsx switcher
export async function ContactPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const userDetails = await getUserDetails(id)

  return (
    <UserCard
      firstName={userDetails.firstName}
      lastName={userDetails.lastName}
    />
  )
}
```

```jsx filename="app/contact/page.js switcher
export async function ContactPage({ params }) {
  const { id } = await params
  const userDetails = await getUserDetails(id)

  return (
    <UserCard
      firstName={userDetails.firstName}
      lastName={userDetails.lastName}
    />
  )
}
```

이제 전체 개체를 클라이언트 구성 요소에 전달하면 오류가 발생합니다.

```tsx switcher
export async function ContactPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const userDetails = await getUserDetails(id)

  // Throws an error
  return <UserCard user={userDetails} />
}
```

```jsx switcher
export async function ContactPage({ params }) {
  const { id } = await params
  const userDetails = await getUserDetails(id)

  // Throws an error
  return <UserCard user={userDetails} />
}
```

### 고유한 값 오염

이 경우 `config.getConfigDetails`에 대한 호출을 기다려 서버 구성에 액세스할 수 있습니다. 그러나 시스템 구성에는 클라이언트에 노출되기를 원하지 않는 `SERVICE_API_KEY`이 포함되어 있습니다.

We can taint the `config.SERVICE_API_KEY` 값을 오염시킬 수 있습니다.

```ts switcher
import { experimental_taintUniqueValue } from 'react'

function getSystemConfig(): SystemConfig {
  const config = await config.getConfigDetails()

  experimental_taintUniqueValue(
    'Do not pass configuration tokens to the client',
    config,
    config.SERVICE_API_KEY
  )

  return config
}
```

```js switcher
import { experimental_taintUniqueValue } from 'react'

function getSystemConfig() {
  const config = await config.getConfigDetails()

  experimental_taintUniqueValue(
    'Do not pass configuration tokens to the client',
    config,
    config.SERVICE_API_KEY
  )

  return config
}
```

We can still access other properties of the `systemConfig` 개체의 다른 속성에는 계속 액세스할 수 있습니다.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()

  return <ClientDashboard version={systemConfig.SERVICE_API_VERSION} />
}
```

그러나 `SERVICE_API_KEY`을 `ClientDashboard`에 전달하면 오류가 발생합니다.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()
  // Someone makes a mistake in a PR
  const version = systemConfig.SERVICE_API_KEY

  return <ClientDashboard version={version} />
}
```

하지만 `systemConfig.SERVICE_API_KEY`은 새 변수에 다시 할당됩니다. 클라이언트 구성 요소에 전달하면 여전히 오류가 발생합니다.

반면, 오염된 고유 값에서 파생된 값은 클라이언트에 노출됩니다.

```tsx
export async function Dashboard() {
  const systemConfig = await getSystemConfig()
  // Someone makes a mistake in a PR
  const version = `version::${systemConfig.SERVICE_API_KEY}`

  return <ClientDashboard version={version} />
}
```

더 나은 접근 방식은 `SERVICE_API_KEY`에서 반환된 데이터에서 `getSystemConfig`을 제거하는 것입니다.
