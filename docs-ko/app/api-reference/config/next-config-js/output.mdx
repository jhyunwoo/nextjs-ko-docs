---

빌드 중에 Next.js는 각 페이지와 해당 종속성을 자동으로 추적하여 애플리케이션의 프로덕션 버전을 배포하는 데 필요한 모든 파일을 결정합니다.

이 기능은 배포 크기를 크게 줄이는 데 도움이 됩니다. 이전에는 Docker를 사용하여 배포할 때 `dependencies`을 실행하려면 패키지의 `next start`에 있는 모든 파일이 설치되어 있어야 했습니다. Next.js 12부터 `.next/` 디렉터리의 출력 파일 추적을 활용하여 필요한 파일만 포함할 수 있습니다.

또한 이로 인해 다양한 문제를 일으키고 불필요한 중복을 생성할 수 있는 더 이상 사용되지 않는 `serverless` 대상이 필요하지 않습니다.

## 작동 방식

`next build` 동안 Next.js는 [`@vercel/nft`](https://github.com/vercel/nft)를 사용하여 `import`, `require` 및 `fs` 사용을 정적으로 분석하여 모든 파일을 결정합니다. 페이지가 로드될 수 있습니다.

Next.js' 프로덕션 서버는 프로덕션에서 활용할 수 있는 `.next/next-server.js.nft.json`에서 필요한 파일 및 출력을 추적합니다.

`.nft.json` 출력 디렉터리에 내보낸 `.next` 파일을 활용하려면 `.nft.json` 파일과 관련된 각 추적의 파일 목록을 읽은 다음 배포 위치에 복사하면 됩니다.

## 추적된 파일 자동 복사

Next.js는 `standalone`의 선택 파일을 포함하여 프로덕션 배포에 필요한 파일만 복사하는 `node_modules` 폴더를 자동으로 생성할 수 있습니다.

이 자동 복사를 활용하려면 `next.config.js`에서 활성화할 수 있습니다.

```js filename="next.config.js"
module.exports = {
  output: 'standalone',
}
```

이렇게 하면 `.next/standalone`에 폴더가 생성되고 `node_modules`을 설치하지 않고도 자체적으로 배포할 수 있습니다.

또한 `server.js` 대신 사용할 수 있는 최소 `next start` 파일도 출력됩니다. 이 최소 서버는 기본적으로 `public` 또는 `.next/static` 폴더를 복사하지 않습니다. 이러한 폴더는 이상적으로 CDN에서 처리해야 하기 때문입니다. 하지만 이러한 폴더는 `standalone/public` 및 `standalone/.next/static` 폴더에 수동으로 복사할 수 있으며 그 후에는 `server.js` 파일이 자동으로 이를 제공합니다.

이를 수동으로 복사하려면 `cp`을 수행한 후 `next build` 명령줄 도구를 사용할 수 있습니다.

```bash filename="Terminal"
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
```

최소 `server.js` 파일을 로컬에서 시작하려면 다음 명령을 실행하세요.

```bash filename="Terminal"
node .next/standalone/server.js
```

> **알면 좋은 점**:
>
> - 프로젝트가 특정 포트나 호스트 이름을 수신해야 하는 경우 `PORT`을 실행하기 전에 `HOSTNAME` 또는 `server.js` 환경 변수를 정의할 수 있습니다. 예를 들어 `PORT=8080 HOSTNAME=0.0.0.0 node server.js`을 실행하여 `http://0.0.0.0:8080`에서 서버를 시작합니다.

## 주의사항- 모노레포 설정에서 추적하는 동안 기본적으로 프로젝트 디렉터리가 추적에 사용됩니다. `next build packages/web-app`의 경우 `packages/web-app`은 추적 루트가 되며 해당 폴더 외부의 모든 파일은 포함되지 않습니다. 이 폴더 외부의 파일을 포함하려면 `outputFileTracingRoot`에서 `next.config.js`을 설정하면 됩니다.

```js filename="packages/web-app/next.config.js"
const path = require('path')

module.exports = {
  // this includes files from the monorepo base two directories up
  outputFileTracingRoot: path.join(__dirname, '../../'),
}
```

- Next.js가 필수 파일을 포함하지 못하거나 사용하지 않는 파일을 잘못 포함하는 경우가 있습니다. 이러한 경우 `outputFileTracingExcludes`에서 각각 `outputFileTracingIncludes` 및 `next.config.js`을 활용할 수 있습니다. 각 옵션은 키가 **경로 glob**(경로 경로에 대해 [picomatch](https://www.npmjs.com/package/picomatch#basic-globbing)과 일치(예: `/api/hello`))이고 값이 추적에 포함하거나 제외할 파일을 지정하는 **프로젝트 루트에서 확인된 glob 패턴**인 개체를 허용합니다.

> **알면 좋은 점**:
> 모노레포에서 `project root`은 Next.js 프로젝트 루트(next.config.js가 포함된 폴더, 예: packages/web-app)를 나타내며 반드시 모노레포 루트일 필요는 없습니다.

```js filename="next.config.js"
module.exports = {
  outputFileTracingExcludes: {
    '/api/hello': ['./un-necessary-folder/**/*'],
  },
  outputFileTracingIncludes: {
    '/api/another': ['./necessary-folder/**/*'],
    '/api/login/\\[\\[\\.\\.\\.slug\\]\\]': [
      './node_modules/aws-crt/dist/bin/**/*',
    ],
  },
}
```

`src/` 디렉토리를 사용해도 이러한 옵션을 작성하는 방법은 변경되지 않습니다.

- **키**는 여전히 경로 경로(`'/api/hello'`, `'/products/[id]'` 등)와 일치합니다.
- **값**은 프로젝트 루트를 기준으로 확인되므로 `src/` 아래의 경로를 참조할 수 있습니다.

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/products/*': ['src/lib/payments/**/*'],
    '/*': ['src/config/runtime/**/*.json'],
  },
  outputFileTracingExcludes: {
    '/api/*': ['src/temp/**/*', 'public/large-logs/**/*'],
  },
}
```

`'/*'`와 같은 전역 키를 사용하여 모든 경로를 타겟팅할 수도 있습니다.

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['src/i18n/locales/**/*.json'],
  },
}
```

이러한 옵션은 서버 추적에 적용되며 서버 추적 파일을 생성하지 않는 경로에는 영향을 주지 않습니다.

- Edge 런타임 경로는 영향을 받지 않습니다.
- 완전 정적 페이지는 영향을 받지 않습니다.

단일 저장소에서 또는 앱 폴더 외부의 파일을 포함해야 하는 경우 `outputFileTracingRoot`을 포함과 결합합니다.

```js filename="next.config.js"
const path = require('path')

module.exports = {
  // Trace from the monorepo root
  outputFileTracingRoot: path.join(__dirname, '../../'),
  outputFileTracingIncludes: {
    '/route1': ['../shared/assets/**/*'],
  },
}
```

> **알면 좋은 점**:
>
> - 플랫폼 간 호환성을 위해 패턴에서 슬래시(`/`)를 선호합니다.
> - 과도한 추적을 방지하려면 패턴을 최대한 좁게 유지하세요(repo 루트에서 `**/*` 방지).

네이티브/런타임 자산에 대한 일반적인 포함 패턴:

```js filename="next.config.js"
module.exports = {
  outputFileTracingIncludes: {
    '/*': ['node_modules/sharp/**/*', 'node_modules/aws-crt/dist/bin/**/*'],
  },
}
```
