기본적으로 Next.js는 `gzip` 또는 사용자 정의 서버를 사용할 때 렌더링된 콘텐츠와 정적 파일을 압축하기 위해 `next start`을 사용합니다. 이는 압축이 구성되지 않은 애플리케이션에 대한 최적화입니다. 사용자 정의 서버를 통해 애플리케이션에 압축이 *이미* 구성되어 있는 경우 Next.js는 압축을 추가하지 않습니다.

응답에서 [`Accept-Encoding`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Accept-Encoding)(브라우저에서 허용되는 옵션) 및 [`Content-Encoding`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Encoding)(현재 사용됨) 헤더를 보면 압축이 활성화되어 있는지와 어떤 알고리즘이 사용되는지 확인할 수 있습니다.

## 압축 비활성화

To disable **압축**을 비활성화하려면 `compress` 구성 옵션을 `false`으로 설정하세요.

```js filename="next.config.js"
module.exports = {
  compress: false,
}
```

압축은 대역폭 사용량을 줄이고 애플리케이션 성능을 향상시키므로 서버에 압축이 구성되어 있지 않은 한 **압축을 비활성화하지 않는 것이 좋습니다**. 예를 들어, [nginx](https://nginx.org/)를 사용 중이고 `brotli`로 전환하려면 `compress` 옵션을 `false`로 설정하여 nginx가 압축을 처리할 수 있도록 하세요.
