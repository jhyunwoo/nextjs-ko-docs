Next.js는 빌드 프로세스에 연결할 사용자 정의 어댑터를 생성할 수 있는 실험적인 API를 제공합니다. 이는 Next.js 구성을 수정하거나 빌드 출력을 처리해야 하는 배포 플랫폼 또는 사용자 정의 빌드 통합에 유용합니다.

## 구성

어댑터를 사용하려면 `experimental.adapterPath`에서 어댑터 모듈의 경로를 지정하십시오.

```js filename="next.config.js"
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    adapterPath: require.resolve('./my-adapter.js'),
  },
}

module.exports = nextConfig
```

## 어댑터 만들기

어댑터는 `NextAdapter` 인터페이스를 구현하는 객체를 내보내는 모듈입니다.

```typescript
export interface NextAdapter {
  name: string
  modifyConfig?: (
    config: NextConfigComplete,
    ctx: {
      phase: PHASE_TYPE
    }
  ) => Promise<NextConfigComplete> | NextConfigComplete
  onBuildComplete?: (ctx: {
    routes: {
      headers: Array<ManifestHeaderRoute>
      redirects: Array<ManifestRedirectRoute>
      rewrites: {
        beforeFiles: Array<ManifestRewriteRoute>
        afterFiles: Array<ManifestRewriteRoute>
        fallback: Array<ManifestRewriteRoute>
      }
      dynamicRoutes: ReadonlyArray<ManifestRoute>
    }
    outputs: AdapterOutputs
    projectDir: string
    repoRoot: string
    distDir: string
    config: NextConfigComplete
    nextVersion: string
  }) => Promise<void> | void
}
```

### 기본 어댑터 구조

다음은 최소 어댑터 예입니다.

```js filename="my-adapter.js"
/** @type {import('next').NextAdapter} */
const adapter = {
  name: 'my-custom-adapter',

  async modifyConfig(config, { phase }) {
    // Modify the Next.js config based on the build phase
    if (phase === 'phase-production-build') {
      return {
        ...config,
        // Add your modifications
      }
    }
    return config
  },

  async onBuildComplete({
    routes,
    outputs,
    projectDir,
    repoRoot,
    distDir,
    config,
    nextVersion,
  }) {
    // Process the build output
    console.log('Build completed with', outputs.pages.length, 'pages')

    // Access different output types
    for (const page of outputs.pages) {
      console.log('Page:', page.pathname, 'at', page.filePath)
    }

    for (const apiRoute of outputs.pagesApi) {
      console.log('API Route:', apiRoute.pathname, 'at', apiRoute.filePath)
    }

    for (const appPage of outputs.appPages) {
      console.log('App Page:', appPage.pathname, 'at', appPage.filePath)
    }

    for (const prerender of outputs.prerenders) {
      console.log('Prerendered:', prerender.pathname)
    }
  },
}

module.exports = adapter
```

## API 참조

### `modifyConfig(config, context)`

구성 수정을 허용하기 위해 next.config를 로드하는 CLI 명령에 대해 호출됩니다.

**매개변수:**

- `config`: 전체 Next.js 구성 개체
- `context.phase`: 현재 빌드 단계([단계](index.mdx#phase) 참조)

**반환:** 수정된 구성 개체(비동기일 수 있음)

### `onBuildComplete(context)`

경로 및 출력에 대한 자세한 정보와 함께 빌드 프로세스가 완료된 후 호출됩니다.

**매개변수:**

- `routes`: 헤더, 리디렉션, 재작성 및 동적 경로에 대한 경로 매니페스트를 포함하는 개체
  - `routes.headers`: `source`, `sourceRegex`, `headers`, `has`, `missing` 및 선택적 `priority` 필드가 있는 헤더 경로 객체 배열
  - `routes.redirects`: `source`, `sourceRegex`, `destination`, `statusCode`, `has`, `missing` 및 선택 사항을 포함하는 리디렉션 경로 개체 배열 `priority` 필드
  - `routes.rewrites`: `beforeFiles`, `afterFiles` 및 `fallback` 배열이 있는 개체(각각 `source`, `sourceRegex`가 포함된 재작성 경로 개체 포함) `destination`, `has` 및 `missing` 필드
  - `routes.dynamicRoutes`: `source`, `sourceRegex`, `destination`, `has` 및 `missing` 필드가 있는 동적 경로 개체 배열
- `outputs`: 유형별로 정리된 모든 빌드 출력에 대한 자세한 정보
- `projectDir`: Next.js 프로젝트 디렉터리의 절대 경로
- `repoRoot`: 감지된 저장소 루트의 절대 경로
- `distDir`: 빌드 출력 디렉터리의 절대 경로
- `config`: 최종 Next.js 구성(`modifyConfig` 적용)
- `nextVersion`: 사용 중인 Next.js 버전
- `buildId`: 현재 빌드의 고유 식별자

## 출력 유형

The `outputs` 객체에는 다양한 출력 유형의 배열이 포함되어 있습니다.

### 페이지(`outputs.pages`) 디렉터리의 React 페이지:

API `pages/`에서 출발하는 경로:

```typescript
{
  type: 'PAGES'
  id: string           // Route identifier
  filePath: string     // Path to the built file
  pathname: string     // URL pathname
  sourcePage: string   // Original source file path in pages/ directory
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>  // Traced dependencies (key: relative path from repo root, value: absolute path)
  wasmAssets?: Record<string, string>  // Bundled wasm files (key: name, value: absolute path)
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>  // Environment variables (edge runtime only)
  }
}
```

### 앱 페이지(`outputs.pagesApi`)

API routes from `pages/api/`가 포함된  디렉터리의 React 페이지:

```typescript
{
  type: 'PAGES_API'
  id: string
  filePath: string
  pathname: string
  sourcePage: string   // Original relative source file path
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### 앱 경로(`outputs.appPages`)

API 및 `app/`를 사용하여 `page.{js,ts,jsx,tsx}`에서 메타데이터 경로:

```typescript
{
  type: 'APP_PAGE'
  id: string
  filePath: string
  pathname: string     // Includes .rsc suffix for RSC routes
  sourcePage: string   // Original relative source file path
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### 사전 렌더링(`outputs.appRoutes`)

ISR 지원 경로 및 정적 사전 렌더링:`app/` with `route.{js,ts,jsx,tsx}`:

```typescript
{
  type: 'APP_ROUTE'
  id: string
  filePath: string
  pathname: string
  sourcePage: string
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
  }
}
```

### 정적 파일(`outputs.prerenders`)

정적 자산 및 자동으로 정적으로 최적화된 페이지:

```typescript
{
  type: 'PRERENDER'
  id: string
  pathname: string
  parentOutputId: string  // ID of the source page/route
  groupId: number        // Revalidation group identifier (prerenders with same groupId revalidate together)
  pprChain?: {
    headers: Record<string, string>  // PPR chain headers (e.g., 'x-nextjs-resume': '1')
  }
  parentFallbackMode?: 'blocking' | false | null  // Fallback mode from getStaticPaths
  fallback?: {
    filePath: string
    initialStatus?: number
    initialHeaders?: Record<string, string | string[]>
    initialExpiration?: number
    initialRevalidate?: number
    postponedState?: string  // PPR postponed state
  }
  config: {
    allowQuery?: string[]     // Allowed query parameters
    allowHeader?: string[]    // Allowed headers for ISR
    bypassFor?: RouteHas[]    // Cache bypass conditions
    renderingMode?: RenderingMode
    bypassToken?: string
  }
}
```

### 미들웨어(`outputs.staticFiles`)

미들웨어 기능(있는 경우):

```typescript
{
  type: 'STATIC_FILE'
  id: string
  filePath: string
  pathname: string
}
```

### 헤더`outputs.middleware`)

각 헤더 경로에는 다음이 포함됩니다.

```typescript
{
  type: 'MIDDLEWARE'
  id: string
  filePath: string
  pathname: string      // Always '/_middleware'
  sourcePage: string    // Always 'middleware'
  runtime: 'nodejs' | 'edge'
  assets: Record<string, string>
  wasmAssets?: Record<string, string>
  config: {
    maxDuration?: number
    preferredRegion?: string | string[]
    env?: Record<string, string>
    matchers?: Array<{
      source: string
      sourceRegex: string
      has: RouteHas[] | undefined
      missing: RouteHas[] | undefined
    }>
  }
}
```

## Routes Information

각 리디렉션 경로에는 다음이 포함됩니다.`routes` object in `onBuildComplete` provides complete routing information with processed patterns ready for deployment:

### 재작성

재작성은 세 단계로 분류됩니다.

- `source`: 파일 시스템 이전에 확인됨(페이지 및 공용 파일 포함)`/about`)
- `sourceRegex`: 페이지/공용 파일 이후, 동적 경로 이전에 확인됨
- `headers`: 다른 모든 경로 이후에 확인됨
- `has`: Optional conditions that must be met
- `missing`: Optional conditions that must not be met
- `priority`: Optional flag for internal routes

### 동적 경로

동적 경로 세그먼트(예: , )에서 생성됩니다. 각각에는 다음이 포함됩니다.

- `source`: 경로 패턴
- `sourceRegex`: 명명된 캡처 그룹을 사용하여 컴파일된 정규식
- `destination`: 매개변수 대체가 있는 내부 대상
- `statusCode`: 선택적 긍정적 조건
- `has`: 선택적 부정 조건
- `missing`: Optional negative conditions
- `priority`: Optional flag for internal routes

### Rewrites

어댑터의 일반적인 사용 사례는 다음과 같습니다.- : 특정 호스팅 플랫폼에 대한 빌드 출력을 자동으로 구성합니다.

- `beforeFiles`: Checked before filesystem (including pages and public files): 빌드 출력 변환 또는 최적화
- `afterFiles`: Checked after pages/public files but before dynamic routes: 빌드 지표 및 경로 정보 수집
- `fallback`: Checked after all other routes: 플랫폼별 형식의 패키지 출력

Each rewrite includes `source`, `sourceRegex`, `destination`, `has`, and `missing`.

### Dynamic Routes

Generated from dynamic route segments (e.g., `[slug]`, `[...path]`). Each includes:

- `source`: Route pattern
- `sourceRegex`: Compiled regex with named capture groups
- `destination`: Internal destination with parameter substitution
- `has`: Optional positive conditions
- `missing`: Optional negative conditions

## Use Cases

Common use cases for adapters include:

- **Deployment Platform Integration**: Automatically configure build outputs for specific hosting platforms
- **Asset Processing**: Transform or optimize build outputs
- **Monitoring Integration**: Collect build metrics and route information
- **Custom Bundling**: Package outputs in platform-specific formats
- **Build Validation**: Ensure outputs meet specific requirements
- **Route Generation**: Use processed route information to generate platform-specific routing configs
