CSS 청킹은 CSS 파일을 청크로 분할하고 재정렬하여 웹 애플리케이션의 성능을 향상시키는 데 사용되는 전략입니다. 이를 통해 모든 애플리케이션의 CSS를 한 번에 로드하는 대신 특정 경로에 필요한 CSS만 로드할 수 있습니다.

You can control how CSS files are chunked using the `experimental.cssChunking` 파일의 `next.config.js` 옵션을 사용하여 CSS 파일을 청크하는 방법을 제어할 수 있습니다.

```tsx filename="next.config.ts" switcher
import type { NextConfig } from 'next'

const nextConfig = {
  experimental: {
    cssChunking: true, // default
  },
} satisfies NextConfig

export default nextConfig
```

```js filename="next.config.js" switcher
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    cssChunking: true, // default
  },
}

module.exports = nextConfig
```

## 옵션

- **`true`(기본값)**: Next.js는 가능할 때마다 CSS 파일을 병합하려고 시도하여 가져오기 순서에서 파일 간의 명시적 및 암시적 종속성을 결정하여 청크 수와 요청 수를 줄입니다.
- **`false`**: Next.js는 CSS 파일을 병합하거나 재정렬하려고 시도하지 않습니다.
- **`'strict'`**: Next.js는 CSS 파일을 파일로 가져온 올바른 순서로 로드하므로 더 많은 청크와 요청이 발생할 수 있습니다.

예상치 못한 CSS 동작이 발생하는 경우 `'strict'` 사용을 고려할 수 있습니다. 예를 들어, 다른 `a.css` 순서(`b.css` 앞의 `import` 또는 `a` 앞의 `b`)를 사용하여 다른 파일에서 `b` 및 `a`을 가져오는 경우, `true`는 어떤 순서로든 파일을 병합하고 파일 사이에 종속성이 없다고 가정합니다. 그러나 `b.css`이 `a.css`에 종속되는 경우 `'strict'`을 사용하여 파일이 병합되는 것을 방지하고 대신 가져온 순서대로 파일을 로드할 수 있습니다. 이로 인해 더 많은 청크와 요청이 발생할 수 있습니다.

대부분의 애플리케이션에서는 요청 수가 줄어들고 성능이 향상되므로 `true`을 사용하는 것이 좋습니다.
