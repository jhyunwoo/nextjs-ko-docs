title: 빠른 새로고침
description: 빠른 새로 고침은 React 구성 요소에 대한 편집 내용에 대한 즉각적인 피드백을 제공하는 핫 모듈 다시 로드 경험입니다.
---

빠른 새로 고침은 Next.js에 통합된 React 기능으로, 변경 사항을 파일에 저장할 때 임시 클라이언트 측 상태를 유지하면서 브라우저 페이지를 실시간으로 다시 로드할 수 있습니다. **9.4 이상**의 모든 Next.js 애플리케이션에서는 기본적으로 활성화되어 있습니다. 빠른 새로 고침을 활성화하면 대부분의 편집 내용이 1초 이내에 표시됩니다.

## 작동 방식

- **React 구성 요소만 내보내는** 파일을 편집하면 빠른 새로 고침이
  해당 파일에 대해서만 코드를 업데이트하고 구성 요소를 다시 렌더링하십시오. 편집할 수 있습니다
  스타일, 렌더링 로직, 이벤트 핸들러 또는
  효과.
- React 구성 요소가 *아닌* 내보내기가 포함된 파일을 편집하는 경우 빠른 새로 고침
  해당 파일과 이를 가져오는 다른 파일을 모두 다시 실행합니다. 그렇다면 둘 다
  `Button.js` 및 `Modal.js` 가져오기 `theme.js`, 편집 `theme.js`이 업데이트됩니다.
  두 구성 요소 모두.
- 마지막으로, 외부 파일에서 가져온 **파일을 편집**하는 경우
  React 트리\*\*, 빠른 새로 고침 **전체 다시 로드를 수행하는 것으로 돌아갑니다**. 당신
  React 구성요소를 렌더링하지만 값도 내보내는 파일이 있을 수 있습니다.
  **비 React 구성요소**에 의해 가져온 것입니다. 예를 들어, 아마도 당신의
  구성 요소는 또한 상수를 내보내고 React가 아닌 유틸리티 파일에서 이를 가져옵니다. 에서
  이 경우 상수를 별도의 파일로 마이그레이션하고 가져오는 것을 고려하십시오.
  두 파일 모두에. 이렇게 하면 빠른 새로 고침이 다시 활성화됩니다. 다른 경우도 가능
  대개 비슷한 방법으로 해결됩니다.

## 오류 복원력

### 구문 오류

개발 중 구문 오류가 발생하면 이를 수정하고 파일을 저장할 수 있습니다.
다시. 오류는 자동으로 사라지므로 다시 로드할 필요가 없습니다.
앱. **구성요소 상태는 손실되지 않습니다**.

### 런타임 오류

구성 요소 내부에서 런타임 오류가 발생하는 실수를 한 경우,
상황에 맞는 오버레이가 표시됩니다. 오류를 수정하면 자동으로
앱을 다시 로드하지 않고 오버레이를 닫습니다.

렌더링 중에 오류가 발생하지 않은 경우 구성 요소 상태가 유지됩니다. 만약에
렌더링 중에 오류가 발생했습니다. React는 다음을 사용하여 애플리케이션을 다시 마운트합니다.
업데이트된 코드.

[오류 경계](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)가 있는 경우
앱에서(프로덕션의 우아한 실패에 대한 좋은 아이디어임)
렌더링 오류가 발생한 후 다음 편집 시 렌더링을 다시 시도합니다. 이는 다음을 의미합니다.
오류 경계로 인해 항상 루트 앱으로 재설정되지 않을 수 있습니다.
상태. 그러나 오류 경계가 *너무* 세분화되어서는 안 된다는 점을 명심하세요.
프로덕션 환경에서 React에 의해 사용되며 항상 설계되어야 합니다.
의도적으로.

## 제한사항

빠른 새로 고침은 현재 구성 요소의 로컬 React 상태를 유지하려고 시도합니다.
편집은 안전할 경우에만 가능합니다. 다음과 같은 몇 가지 이유를 볼 수 있습니다.
파일을 편집할 때마다 로컬 상태가 재설정됩니다.- 클래스 구성요소의 경우 로컬 상태가 유지되지 않습니다(함수 구성요소만 해당).
및 후크는 상태를 유지합니다).

- 편집 중인 파일에 React 외에 *기타* 내보내기가 있을 수 있습니다.
  구성 요소.
- 때로는 파일이 상위 구성 요소 호출 결과를 내보내는 경우가 있습니다.
  `HOC(WrappedComponent)`와 같습니다. 반환된 구성 요소가
  클래스의 상태가 재설정됩니다.
- `export default () => <div />;`와 같은 익명 화살표 기능으로 인해 빠른 새로 고침이 로컬 구성 요소 상태를 유지하지 않게 됩니다. 대규모 코드베이스의 경우 [`name-default-component` codemod](https://nextjs.org/docs/pages/guides/upgrading/codemods#name-default-component)를 사용할 수 있습니다.

더 많은 코드베이스가 함수 구성 요소와 Hooks로 이동함에 따라 다음을 기대할 수 있습니다.
더 많은 경우에 상태가 보존됩니다.

## 팁

- 빠른 새로 고침은 다음을 통해 함수 구성 요소(및 후크)의 React 로컬 상태를 유지합니다.
  기본값.
- 때로는 상태를 *강제* 재설정하고 구성요소를 다시 설정하고 싶을 수도 있습니다.
  다시 마운트하십시오. 예를 들어 애니메이션을 조정하는 경우 유용할 수 있습니다.
  이는 마운트에서만 발생합니다. 이렇게 하려면 `// @refresh reset`을 추가하면 됩니다.
  편집 중인 파일의 어느 곳에서나 가능합니다. 이 지시문은 파일에 대해 로컬이며
  빠른 새로 고침을 수행할 때마다 해당 파일에 정의된 구성 요소를 다시 마운트하도록 지시합니다.
  편집하다.
- 편집하는 동안 구성 요소에 `console.log` 또는 `debugger;`을 넣을 수 있습니다.
  개발.
- 가져오기는 대소문자를 구분한다는 점을 기억하세요. 빠른 새로 고침과 전체 새로 고침 모두 실패할 수 있습니다.
  가져오기가 실제 파일 이름과 일치하지 않는 경우.
  예를 들어 `'./header'`과 `'./Header'`입니다.

## 빠른 새로 고침 및 후크

가능한 경우 빠른 새로 고침은 구성 요소의 상태를 보존하려고 시도합니다.
편집 사이. 특히 `useState` 및 `useRef`은 이전 값을 유지합니다.
인수나 Hook의 순서를 변경하지 않는 한 값
전화.

`useEffect`, `useMemo` 및 `useCallback`과 같은 종속성이 있는 후크는
*항상* 빠른 새로 고침 중에 업데이트됩니다. 해당 종속성 목록은 무시됩니다.
빠른 새로 고침이 진행되는 동안.

예를 들어, `useMemo(() => x * 2, [x])`을 편집하면
`useMemo(() => x * 10, [x])`, `x`(종속성)에도 불구하고 다시 실행됩니다.
변경되지 않았습니다. React가 그렇게 하지 않으면 편집 내용이
화면!

때로는 이로 인해 예상치 못한 결과가 발생할 수 있습니다. 예를 들어, `useEffect`
빈 종속성 배열이 있는 경우 빠른 새로 고침 중에 한 번 다시 실행됩니다.

그러나 가끔씩 `useEffect`을 다시 실행해도 탄력적으로 코드를 작성하는 것은 좋은 습관입니다.
빠른 새로 고침 없이. 나중에 새로운 종속성을 도입하기가 더 쉬워집니다.
이는 [React 엄격 모드](https://nextjs.org/docs/pages/api-reference/config/next-config-js/reactStrictMode)에 의해 시행됩니다.
활성화하는 것이 좋습니다.
